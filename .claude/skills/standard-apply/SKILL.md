# standard-apply

標準を project に適用する側の入口である。
手順の正本は標準の README にあり、この skill は入口と報告の形だけを定める。標準の内容をここに転写しない。

## 前提

- 標準リポジトリの場所(パス)を受け取る。
- project の ADR に準拠 commit の記録があれば、その commit の内容を基準にする。

## やり方

1. `<標準>/README.md` を読む。適用の3則(本文を読んでから適用・範囲は全域が既定・意図の上書き禁止)に常に従う。
2. 依頼をモード(新規構築・監査・移行・実装とレビュー)に写像し、README の利用節の該当手順を順に実行する。
3. 記述の矛盾を見つけたら、README の矛盾の解決に従って作業を続け、file と該当箇所を添えて報告する。黙って読み替えない。
4. 標準が沈黙する目的は、一般則で補完しない。README の標準の単一性に従い、project の ADR へ単一採用を記録する。
5. 逸脱・標準外の採用は、README の単一性が定める必須記載(採用理由・撤回条件・単一採用・置き換える標準規律の file 参照・前提の技術的制約の実証)で project の ADR に残す。

## 報告の形

- 適用・実装の報告には、照合した規律の file を添える。
- 監査の報告は、severity・file と該当箇所・対応する標準の規律で列挙する(README の監査手順 6)。

## 禁則

- 記憶・要約・見出しの略語で判定しない。該当ファイルの本文を読む。
- 標準本文を編集しない。標準側の不備への気づきは報告に留める(修正は standard-update の仕事)。

## 関連

- `standard-update` / `standard-audit` — 標準そのものの保守。適用中の気づきの送り先。
