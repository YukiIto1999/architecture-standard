# standard-apply

標準を project に適用する側の入口である。
手順の正本は標準の README にあり、この skill は入口と報告の形だけを定める。標準の内容をここに転写しない。

## 前提

- この skill の在るリポジトリが標準である。適用の対象 project と範囲は、依頼から取る。
- project の ADR に準拠 commit の記録があれば、その commit の内容を基準にする。

## やり方

1. 標準の `README.md` を読む。適用の4則(本文を読んでから適用・範囲は全域が既定・意図の上書き禁止・報告に本文引用の証跡)に常に従う。
2. 依頼をモードへ写像し、該当する手順の本文を読む。新規構築= `process/bootstrap.md`、監査= `process/audit.md`、移行= `process/migration.md`、設計= `process/design.md`、実装= `process/implementation.md`、構造改善= `process/refactoring.md`、レビュー= `process/review.md`。
3. 読んだ順序と確認点をチェックリストとして応答へ転写し、進行に合わせて消し込む。終了時は全項目を、実施済みか、理由を添えた見送りかのどちらかにする。黙って飛ばさない。
4. 規律を適用する各段で、先に該当ファイルの判定に使う本文(README の判定の枠が層ごとに定める照合先)を引用し、それから作業する。引用できないなら、まだ読んでいない。
5. 実装・構造改善の完了前に、レビューのモードを、変更の経緯を持たない白紙コンテキストの subagent で実行し、その指摘を報告に含める。自己照合で代替しない。
6. 記述の矛盾を見つけたら、README の矛盾の解決に従って作業を続け、file と該当箇所を添えて報告する。黙って読み替えない。
7. 標準が沈黙する目的は、一般則で補完しない。README の標準の単一性に従い、project の ADR へ単一採用を記録する。
8. 逸脱・標準外の採用は、README の単一性が定める必須記載(採用理由・撤回条件・単一採用・置き換える標準規律の file 参照・前提の技術的制約の実証)で project の ADR に残す。

## 報告の形

- 報告の前に、各主張を本セッションの tool 結果と照合する。証跡を指せる作業だけを報告し、未検証はそう明記する。
- 適用・実装の報告には、照合した規律の本文引用と file を添える。引用は README の判定の枠が層ごとに定める照合先から取る。
- 監査の報告は、severity・file と該当箇所・対応する標準の規律で列挙する(process/audit の順序 7)。
- 検証が実行できないときは、合格を主張せず、実行できない理由と次善の確認を報告する。

## 禁則

- 記憶・要約・見出しの略語で判定しない。該当ファイルの本文を読む。
- 標準本文を編集しない。標準側の不備への気づきは報告に留める(修正は standard-update の仕事)。

## 関連

- `standard-update` / `standard-audit` — 標準そのものの保守。適用中の気づきの送り先。
