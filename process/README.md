# process

process は、ソフトウェア開発ライフサイクルにおけるどの順で作るかという作業順序と、どこで確かめるかという確認点を定めます。

性質や品質の規範そのものは [principles](../principles/) と [concerns](../concerns/) に従い、順序の入力や確認点の照合先として [structure](../structure/) と [tools](../tools/) を指します。process 自体は作業順序と確認点のみを所有し、アーキテクチャの性質規範を再定義しません。

## 開発ライフサイクルの全体フロー

開発の各フェーズにおいて、以下の作業単位が連携して適用されます。
```text
 【立ち上げ・把握】
   - [ bootstrap ]   新規プロジェクトの立ち上げ
   - [ recovery ]    既存システムの責務と意味の回収
        │
        ▼
 【設計・実装】
   - [ design ]      要件から境界・責務・契約への展開
        │
        ▼
   - [ implementation ] テスト駆動による垂直スライスの実装
        ▲
        │
        ▼
   - [ refactoring ] 振る舞いを保った内部構造の段階的改善
        │
        ▼
 【レビュー・検証】
   - [ review ]      変更差分の独立した品質・規律照合
   - [ audit ]       システム全域の標準合致度・健全性の包括的評価
   - [ verification ] 自動テスト・機械検査・受入検証の実行
        │
        ▼
 【展開・運用・訓練】
   - [ migration ]   稼働中システムにおける段階的データ・機能移行
   - [ release ]     アーティファクトの生成・署名・安全な配備
   - [ drill ]       本番想定の障害復旧・ロールバック・インシデント演習
```

## 書式

各単位は、導入の参照文、順序、確認点、範囲外で書く。
順序は番号付きの手順で書き、各手順は一つの作業を指す。
確認点は、どの規律の完了条件と禁止事項をいつ照合するかと、照合の判定に使う基準を書く。
必須5節の書式は使わない。
性質の規範は各層の正本にある。

## 判定の枠

プロセスへの適合は、以下の2点をもって客観的に判定します。

1. 順序の遵守: 定められた作業ステップが省略や順序の逆転なく実行されたこと。
2. 確認点の照合: 各ステップの節目において、指定された規律の完了条件および禁止事項との照合が実際に行われ、証跡が残されていること。

検証の合否判定は、root の [README](../README.md) が定める適用の4則に従います。

## 範囲外の事項

本標準を実務に適用するにあたり、以下の事項は process の管轄外とします。

- プロジェクト運営: スコープ、開発費用、スケジュール、体制、デリバリーの周期は、プロジェクト自身が決定する。
- AI 指示の技法: 手順は実行主体が人間であっても AI エージェントであっても同じであり、特定の対話技法やプロンプトエンジニアリングには依存しない。
