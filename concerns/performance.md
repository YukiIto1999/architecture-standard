# performance

## 概要
performance は、計測の後の最適化を全系で統べる規律である。
principles の [construction](../principles/construction.md) が定める単純な形の既定と投機の排除を、性能の扱いとして具象化する。
計測を定めてから比べ、改善は計測が根拠を示した後にだけ行い、推測で単純な形を崩さない。

## 計測を定めてから比べる

### 要求
性能は、尺度・負荷・環境を定めた計測で測る。
遅延の尺度は分布の百分位とし、平均だけで判断しない。
計測は、代表する負荷と、比較の間で同等な環境で行う。
改善の判断は、同じ条件の前後の比較で行う。
尺度と閾値の値は、project が定めて記録する。

### 根拠
平均は分布の裾を隠し、少数の遅い要求が利用者の体験を決める事実を読み落とす。
複数の部品に依存する処理では、一つの部品の裾の遅延が全体の中央値を左右する。
分布を測って初めて、遅い裾と全体の悪化を区別できる。
負荷と環境が揃わない計測は、差の原因を最適化と条件の違いに切り分けられない。

### 完了条件
性能の判定が、百分位の尺度で行われている。
計測の負荷と環境が、比較の間で同等である。
改善の主張が、同じ条件の前後の比較に基づいている。
尺度と閾値の値が、project の記録にある。

### 禁止事項
平均だけを根拠に、性能を判定すること。
負荷や環境の違う計測を、並べて比較すること。

### 行動
測る対象ごとに、尺度・百分位・代表負荷を定める。
計測の条件を前後で揃え、差を最適化の効果として確かめる。

## 計測の後にだけ最適化する

### 要求
性能の最適化は、計測が改善の根拠を示した後にだけ行う。
推測を根拠に、最適化を入れない。

### 根拠
最適化は、単純な形を崩し、読み手が追跡する段数を増やす。
計測のない最適化は、対価を説明できない複雑さとして残る。
計測が特定した箇所に絞れば、複雑さの増加を実測の改善と引き換えにできる。

### 完了条件
入れた最適化のそれぞれが、計測した根拠と対応している。
最適化の後の計測が、改善を示している。

### 禁止事項
計測の根拠なく、最適化を入れること。

### 行動
性能の問題は、まず計測で箇所を特定する。
特定した箇所を直し、計測で改善を確かめる。
改善を確かめられない最適化は、取り除く。

## 性能目的の並列化を計測の後の一手段にする

### 要求
性能目的で処理を並列化する判断は、計測の後の最適化の一手段としてだけ行う。
採る project は、その判断を ADR に記録する。

### 根拠
複数を束ねて捌く構造の並行と、同時に動かして速くする実行の並列は、別の関心である。
並列化は競合と資源の複雑さを連れてくるので、計測の根拠なしに入れると複雑さだけが残る。
判断を ADR に記録すれば、並列化の根拠と範囲を後から辿れる。

### 完了条件
性能目的の並列化が、計測した根拠と対応している。
並列化の判断が、project の ADR に記録されている。

### 禁止事項
計測の根拠なく、性能目的の並列化を入れること。

### 行動
並列化の前に、計測で改善の見込みを確かめる。
採った判断を ADR に記録する。
並列の実行の寿命・取り消し・並行度は [concurrency](./concurrency.md) に従う。
