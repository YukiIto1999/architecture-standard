## 非同期と並行を業務の核から隔離する

### 要求
純粋核と効果の殻の分離は [separation](../../principles/separation/effects-at-boundaries.md) の「副作用を境界に集める」に従い、非同期と並行の制御は核に持ち込まず境界で扱う。

### 根拠
非同期や並行の制御が業務判断に混ざると、判断のテストに並行の足場が要る。
業務の核を同期の純粋関数に保てば、判断を単体で再現しテストできる。
非同期は並行と別の関心であり、ブロッキングは境界へ追い出す。

### 完了条件
業務の計算・判断が、非同期と並行の制御を持たない同期の関数として書かれている。
非同期と並行の制御が、境界に置かれている。
ブロッキングする処理が、境界へ隔離されている。

### 禁止事項
業務の核に、非同期や並行の制御を持ち込むこと。
業務の判断の途中で、ブロッキングする処理を呼ぶこと。

### 行動
業務の判断を同期の純粋関数へ切り出し、並行と非同期は呼び出し側の境界に置く。
ブロッキングする処理を、専用の境界へ追い出す。

### 例

業務の判断へ非同期処理を入れると、判断と外部効果を分離できない。

```
async function decide(x) { const r = await fetch(...); return r.ok ? a : b; }
```

非同期処理を境界へ置き、判断を同期の純粋関数にすれば、外部効果の足場なしで判断を検証できる。

```
function decide(x, fetched) { return fetched.ok ? a : b; }
```
