## 実行文脈の由来と寿命を保って伝える

### 要求
実行に随伴して境界を越える metadata は、trace、相関の識別子、deadline、cancel など、効果の実行に必要なものに限る。
この metadata は、境界で一度だけ構築した不変の carrier として伝える。
処理は、carrier から必要な値を取り出した projection か個別の引数で受け取ってよい。
projection は由来と寿命を保ち、deadline は境界で生成した同じ絶対期限、cancel は親の取消が届く同じ系統、相関の識別子は同じ値を引き継ぐ。
要求の寿命を越えて続く処理は、新しい実行の境界で carrier を構築し、終わった要求の期限と取消を持ち越さない。
carrier は不変に保ち、値の追加は新しい carrier を生む。
認証主体、資格情報の許可範囲、業務の入力は carrier に載せず、全ての層へ同梱して流さない。
純粋な domain の関数に、carrier、期限、取消の引数を要求しない。
技術的な処理の期限と取消は、業務上の期限と取消とは別の概念として扱う。
言語や基盤が持つ期限と取消の標準の形を、一つの context の型へ置き換えることを要求しない。
境界を越えて伝播する文脈に、秘密や個人情報を載せない。

### 根拠
trace、相関の識別子、deadline、cancel は、効果の実行にだけ必要な metadata であり、実行ごとに境界で決まる。
不変の carrier を境界で一度だけ構築すれば、境界を越える metadata が一貫して伝わり、並行する処理が同じ carrier を共有しても壊れない。
必要な値だけを取り出して渡せば、処理は自分が使わない metadata を受け取らず、署名が必要な依存だけを表す。
projection が由来と寿命を保てば、hop が増えても期限の起点は動かず、親の取消が子へ届き、相関の識別子が分散した処理を一つの流れとして追わせる。
終わった要求の期限と取消を寿命の違う処理へ持ち越すと、その処理が無関係な取消で止まり、または期限切れの値で動き続ける。
認証主体、資格情報の許可範囲、業務の入力は、変わる理由と見せてよい範囲が実行の metadata と異なる。
一つの袋にまとめて全ての層へ流すと、処理が使わない認証と業務の情報へ依存し、境界の外へ漏れる面も広がる。
純粋な domain の関数は、同じ入力から同じ結果を返すことが価値であり、実行の metadata を要求すると効果の実行の都合が核へ入る。
処理を打ち切る期限と取消は技術的な実行の制御であり、業務上の期限や取消は業務の事実として記録されるので、同一視すると処理の中断が業務の取消として記録される。
言語や基盤の標準の期限と取消の形は、その実行機構の協調に合わせて作られているので、一つの型へ置き換えると、その機構の性質と非取消の後始末の扱いを失う。
伝播する文脈は境界を越えて外まで流れるので、秘密や個人情報を載せると漏れる。

### 完了条件
trace、相関の識別子、deadline、cancel が、境界で構築した不変の carrier から伝わっている。
処理が、carrier の必要な値か個別の引数だけを受け取り、projection が由来の deadline、親へ連なる cancel、同じ相関の識別子を保っている。
要求の寿命を越えて続く処理が、新しい境界で carrier を構築している。
carrier が不変で、値の追加が新しい carrier を生んでいる。
carrier に、認証主体、資格情報の許可範囲、業務の入力が載っておらず、全ての層へ同梱して渡されていない。
純粋な domain の関数が、carrier、期限、取消の引数を持たない。
技術的な処理の期限と取消が、業務上の期限と取消の記録と別に表されている。
言語や基盤の標準の期限と取消の形が、一つの context の型へ置き換えられていない。
境界を越えて伝播する文脈に、秘密や個人情報が載っていない。

### 禁止事項
認証主体、資格情報の許可範囲、業務の入力を、実行の metadata と一つにまとめて全ての層へ流すこと。
projection の deadline を新しい期限へ作り直し、cancel を親と切り離すこと。
相関の識別子を、境界で途切れさせること。
carrier を、破壊的に書き換えること。
純粋な domain の関数へ、carrier、期限、取消の引数を要求すること。
技術的な処理の期限または取消を、業務上の期限または取消として扱うこと。
境界を越えて伝播する文脈に、秘密や個人情報を載せること。

### 行動
実行の metadata を境界で一度だけ不変の carrier に構築し、境界を越えて伝播させる。
処理には、carrier から必要な値だけを projection か個別の引数で渡し、由来の期限、親へ連なる取消、同じ相関の識別子を保つ。
相関の識別子を下流と外部呼び出しへ引き継ぐ。
認証主体、資格情報の許可範囲、業務の入力は carrier へ載せず、それぞれの契約で必要な処理へだけ渡す。
純粋な domain の関数からは、実行の metadata の引数を除く。

### 例

認証主体と業務の入力を実行の metadata に同梱すると、全ての層が認証と業務の情報を受け取り、純粋な計算まで文脈に依存する。

```
decide(context{ trace, deadline, cancel, subject, customerId }, order)
```

carrier は境界で一度だけ構築し、効果を実行する処理へは必要な値だけを渡す。
純粋な domain の関数は文脈を受け取らない。

```
carrier = buildCarrier(trace, deadline, cancel)
reserveStock(carrier.deadline, carrier.cancel, order)
decide(order, customerId)
```
