## 拒否は業務の前で止める

### 要求
拒否された要求を業務の処理の前で止める定めは [evaluate-at-entry](./evaluate-at-entry.md) の「入口で評価し、通った要求だけ進める」に従い、拒否の応答は [effect](../effect/README.md) が定める外部へ公開するエラーの形に従って汎用的に返す。
拒否された要求は、保護対象の変更と公開に到達させない。
認可の評価のために保護入口が読む内部の資源は、評価に必要な範囲に限り、読んだ内容を拒否の応答へ載せない。
対象の存在が機微な文脈では、見つからない場合と許されない場合を外から区別させない。
拒否の詳細は応答でなくサーバ側のログに残す。

### 根拠
拒否を業務の処理の中で扱うと、保護対象を変更または公開してから止めることになる。
保護入口で止めれば、未許可の変更と公開が業務の処理に届かない。
評価のための内部の読取は変更でも公開でもないので、拒否の保証と区別できるが、読んだ内容を応答へ載せると公開になる。
拒否の応答に内部の手がかりが載ると、攻撃者に探索の足場を与える。
対象の存在を漏らすと、許否の差から対象の有無を列挙できる。
詳細をサーバ側のログに残せば、クライアントに明かさずに調査と監査ができる。

### 完了条件
拒否の応答の形が、[effect](../effect/README.md) の外部へ公開するエラーの規律に従っている。
拒否された要求が、保護対象の変更と公開に到達していない。
認可の評価のために読んだ内部の資源の内容が、拒否の応答に載っていない。
対象の存在が機微な文脈で、見つからない場合と許されない場合が外から区別できない。
拒否の詳細が、サーバ側のログに残っている。

### 禁止事項
拒否の詳細を記録に残さず、調査と監査をできなくすること。
認可の評価のために読んだ内部の資源の内容を、拒否の応答へ載せること。

### 行動
拒否は保護入口で止め、応答の形は [effect](../effect/README.md) に従う。
評価のための内部の読取は評価に必要な範囲に絞り、読んだ内容を応答へ出さない。
詳細はサーバ側のログへ残し、対象の存在が機微な文脈では未検出と未許可を同じ応答にする。

### 例

内部情報やスタックトレースを応答へ載せると、対象の存在や実装の詳細が漏れる。

```
if (!found) return "そのIDの注文は存在しません"; return error(stackTrace)
```

クライアントには汎用の応答を返し、詳細はログへ記録する。
機微な文脈では未検出と未許可を区別しない。

```
log({ denied: true, subjectId, target, reason }); return forbidden()
```
