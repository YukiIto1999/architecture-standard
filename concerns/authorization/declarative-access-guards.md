## 認可の宣言を公開入口で強制する

### 要求
認可は、操作、対象、policy、適用点を宣言として表し、その宣言を公開入口へ束ねた保護入口で強制する。
宣言は、保護する操作、その操作が対象とする資源の選び方、適用する policy、policy を評価する適用点を持つ。
適用点は、[evaluate-at-entry](./evaluate-at-entry.md) の「入口で評価し、通った要求だけ進める」が定める要求の入口と、対象を取り出す境界から選ぶ。
policy は、役割・属性・関係などの方針モデルで表し、業務の処理から切り離す。
同じ操作は、呼び出し元が HTTP、CLI、worker、workflow のいずれであっても、同じ保護入口を通す。
保護入口を外部の公開契約への adapter の公開入口に置く場合も、業務の判断は業務の処理に残し、adapter へ移さない。
宣言のない公開入口と、保護入口を通らない別経路は、拒否する。
誰にでも公開する入口は、匿名公開として宣言する。
業務の処理は、認可の呼出、認可の port、許可結果の引数を持たず、認証方式、認可の engine、許可結果を知らない。
判定できないときは、拒否に倒す。

### 根拠
認可の判定を業務の処理へ埋め込むと、方針の変更が業務へ波及し、業務の処理が認証方式と認可の engine の型を知る。
認可を宣言として入口へ外付けすれば、方針を業務と独立に変えられ、業務の処理は認証方式やアクセス可否を判定せず、必要な業務入力から業務の判断を行える。
宣言のない入口を許可で開く既定にすると、宣言の書き漏れが公開になる。
宣言のない入口を拒否し、匿名公開も宣言にすれば、保護の抜けと意図した公開を区別できる。
呼び出し元の種類ごとに認可を書くと、HTTP で保護した操作が CLI や worker から迂回される。
同じ保護入口を通せば、操作の保護が呼び出し元の経路に依存しない。
方針を役割・属性・関係で表し、宣言を一覧できる形に集めれば、規則が散らばらない。

### 完了条件
全ての公開入口が、操作、対象、policy、適用点の宣言を持つか、匿名公開として宣言されている。
公開入口の一覧と宣言の一覧が一対一で対応し、宣言のない入口と保護入口を通らない別経路が拒否されている。
同じ操作が、HTTP、CLI、worker、workflow のどの呼び出し元からも同じ保護入口を通っている。
保護入口が外部の公開契約への adapter の公開入口に置かれていても、業務の判断が adapter へ移されていない。
業務の処理が、認可の呼出、認可の port、許可結果の引数を持たず、認証方式と認可の engine の型を参照していない。
policy が、役割・属性・関係などの方針モデルで表され、業務の処理から切り離されている。
判定できないとき、拒否になっている。

### 禁止事項
認可の判定の詳細を、業務の処理へ埋め込むこと。
認可の呼出または許可結果を受ける引数を、業務の処理へ必須とすること。
宣言のない公開入口を、許可で開いたままにすること。
保護入口を通らない別経路から、保護した操作を実行できる状態にすること。
認可の宣言を理由に、業務の判断を保護入口の外側へ移すこと。
framework の既定の認可を、この概念の要求と照合せずに信頼すること。
判定不能を、許可へ倒すこと。

### 行動
公開入口を洗い出し、入口ごとに操作、対象、policy、適用点を宣言して保護入口へ束ねる。
匿名公開する入口は、匿名公開として宣言する。
CLI、worker、workflow を含む全ての呼び出し元を同じ保護入口へ通し、宣言のない入口と迂回する経路を拒否する。
業務の処理から認可の呼出と許可結果の引数を除く。
方針は役割・属性・関係で表し、判定不能のときは拒否へ倒す。

### 例

業務の処理が認可を呼ぶと、方針の詳細と許可結果の扱いが核へ漏れる。

```
function cancelOrder(subject, orderId, authorizer) { authorizer.check(subject, "orders:cancel", orderId); ... }
```

操作、対象、policy、適用点を宣言して保護入口へ束ね、業務の処理は取り出された対象だけを受け取る。

```
protect(cancelOrder, { operation: "orders:cancel", target: orderById, policy: ownerOrManager, apply: afterTargetLoad })
function cancelOrder(order: Order): Result<Order, E> { ... }
```
