## 事実をイベントとして表し、構造化して出す

### 要求
観測の対象となる事実はイベントとして表し、観測はそれらの事実から組み立てる。
観測の出力は、field の名前と型と意味が一貫した構造を持つ形式で表す。

### 根拠
観測を、ログ・計測・トレースの信号として事実から組み立てれば、後から問いを立て直せる。
構造を持つ出力は、機械で集計・検索・異常検知できる。
文字列の継ぎはぎは、機械で解釈できず、観測の価値を下げる。
同じ事象が出力ごとに field の名前や型のばらつく形だと、構造を持っても機械で揃えられない。

### 完了条件
観測の対象となる事実が、イベントとして表されている。
観測の出力が、field の名前と型と意味の一貫した構造を持つ。
ログ・計測・トレースが、相関の識別子でつながっている。

### 禁止事項
観測の出力を、構造を持たない文字列の継ぎはぎで表すこと。

### 行動
観測する事実をイベントとして定義し、構造化された形式で出す。
相関の識別子で、ログ・計測・トレースをつなぐ。

### 例

構造のない文字列は機械で集計も検索もできない。

```
log("user " + id + " did " + action + " at " + time)
```

field の名前と型が一貫した構造で出力し、相関 ID でイベントをつなぐ。

```
log({ event: "order_placed", orderId, actorId, traceId, at })
```
