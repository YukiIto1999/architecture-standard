# experience

## 概要
experience は、利用者に向けた画面の体験を統べる規律である。
適用範囲は、利用者が判断し操作する面である。
GUI の viewer を主に、extension の UI や console の対話にも及ぶ。
principles の [legibility](../principles/legibility.md) が定める明快さと [separation](../principles/separation.md) が定める責務の境界を、利用者に向けた面へ具象化する。
設計の目的は、利用者の判断と操作を、楽に安全に迷いなくすることである。
コードの設計が変更を楽にするのと、同じ型である。

## 判断の易しさを最適化する

### 要求
各画面は、利用者に求める判断を一つに絞り、その判断を自明にする。
次の判断に要る情報と操作を、その場に置く。
選択肢を絞り、クリック数の目安で設計しない。

### 根拠
判断にかかる時間は、選択肢が増えるほど長くなる。
求める判断を一つに絞り自明にすると、利用者は迷わず進める。
クリック数を減らしても、各クリックの判断が曖昧なら速くならない。
判断に要る情報を別の画面へ探しに行かせると、文脈が切れて誤る。

### 完了条件
各画面が、利用者に求める主たる判断を一つ持っている。
その判断に要る情報と操作が、同じ画面の中にある。
主操作に、説明文やツールチップなしで到達できる。

### 禁止事項
一つの画面に、独立した複数の判断を詰め込むこと。
クリック数の少なさのために、各段の判断を曖昧にすること。
冗長な説明文で、自明でない操作を補うこと。

### 行動
画面ごとに、独立した複数の判断が混じっていないか確認する。
混じっていれば、判断ごとに画面を分ける。
判断に要る情報と操作を同じ画面へ集め、説明文で補う操作を自明な形へ直す。

## 主操作と既定値を先に示し、頻用操作に近道を備える

### 要求
画面の主操作は一つにし、見つけやすい位置に、押しやすい大きさで置く。
予測できる既定値を選択済みで提示し、変えたい利用者だけが触る形にする。
前提が揃うまでは、その操作を段階的に開く。
頻繁に使う操作には、熟達した利用者のための近道を添える。

### 根拠
主操作が一つで大きく見つけやすいと、利用者は次の一手に迷わず、押す動作も速い。
妥当な既定値を先に出すと、多くの利用者は確認だけで進める。
予測できる妥当な既定値が無いなら、選択済みにせず空で出す。
前提が欠けたまま操作を見せると、押せない操作に時間を奪われる。
頻用操作の近道は、初学者には隠れ、熟達者の速度だけを上げる。

### 完了条件
各画面の主操作が一つで、他の操作より大きく、強い視覚的重みを持つ位置に置かれている。
既定値が、選択済みで示されている。
既定値を選ぶ基準は project が定める。
前提が欠けた操作が、無効化または非表示になっている。
頻繁に使う操作に、近道がある。

### 禁止事項
同格の操作を画面に複数並べ、主操作を埋もれさせること。
妥当でない既定値を、選択済みにすること。
前提が揃わない操作を、押せる形で長く見せること。

### 行動
画面の操作を見渡し、主操作が複数並んでいないか確認する。
主操作を一つに定め、見つけやすい位置に押しやすい大きさで置く。
妥当な既定値を選択済みで出し、無ければ空で出す。
前提が揃ってから操作を開き、頻用操作に近道を添える。

## 状態と結果を即時に返す

### 要求
システムの現状を、利用者へ常に知らせる。
操作には即時の反応を返す。
時間のかかる処理は、進行を知らせ続ける。

### 根拠
現状が見えないと、利用者は何が起きているか分からず誤る。
操作直後に反応がないと、利用者は効いたか分からず繰り返す。
時間のかかる処理は、進行を知らせないと止まったと誤解される。
反応しない操作は、検証できず利用者の信頼を損なう。

### 完了条件
処理中と成功と失敗の現状が、画面に現れている。
すべての操作が、操作直後に反応を返している。
時間のかかる処理が、進行を示している。

### 禁止事項
現状を知らせずに、利用者を待たせること。
反応しない操作を、画面に置くこと。

### 行動
画面の操作を辿り、反応のない操作と現状の見えない処理がないか確認する。
状態を画面に常に示し、操作直後に反応を返す。
時間のかかる処理は、進行を示す。

## 誤りを防ぎ、起きたら回復を助け、取り返せるようにする

### 要求
不正な値を入力させない形にする。
列挙できる値は選択で、数と日付と真偽は専用の入力で受け、自由入力は値が定型を持たない場合に限る。
誤りが起きたら、平易な言葉で何が問題かを示し、直し方を添える。
誤った操作は、取り消しと脱出で取り返せるようにする。

### 根拠
良いエラー文よりも、誤りが起きない構造の方が確実である。
入力を型と選択で縛ると、不正な場合がそもそも生じない。
それでも利用者は誤るので、起きた誤りには問題と直し方を示し、番号だけのエラーを出さない。
取り消しと脱出がないと、利用者は作業を失う。

### 完了条件
列挙できる値が、選択で受けられている。
数と日付と真偽が、専用の入力で受けられている。
自由入力が、定型を持たない値に限られている。
エラーの表示が、平易な言葉で問題と直し方を示している。
誤った操作に、取り消しか脱出の経路がある。

### 禁止事項
列挙できる値を、自由入力で受けること。
不正な値を入力できる形にすること。
番号や内部の語だけで、エラーを示すこと。
取り返せない操作を、確認なく実行させること。

### 行動
入力ごとに、選択と数と日付と真偽と自由の別を確かめ、不正値を作れない入力にする。
エラーの表示を点検し、問題と直し方を平易な言葉で示す。
主要な操作に、取り消しと脱出を備える。

### 例
```
// 出力形式を自由入力で受け、利用者が不正な値を打てる
outputFormat: 自由入力

// 列挙できる値は選択で受け、不正な値を作れない
outputFormat: 選択(CSV / JSON)
```

## 利用者の語彙と現実に合わせ、操作できることを見える形で示す

### 要求
画面は、利用者の言葉と概念と順序で語る。
内部の用語と実装の都合を、画面に出さない。
操作とその効果の対応を、自然な形にする。
操作できる要素は、操作できると見て分かる形にする。

### 根拠
利用者は、自分の言葉で書かれた画面を理解できる。
内部のジャーゴンを出すと、利用者は意味を推測させられる。
同じ概念に複数の語を当てると、別物と誤解される。
操作と効果の対応が自然なら、利用者は結果を予測できる。
操作できる手掛かりが見えないと、利用者は何が操作できるか分からない。

### 完了条件
画面の語が、利用者の語彙に一致している。
内部の用語と実装の都合が、画面に現れていない。
操作の名前と並びが、実世界の慣習と同じ順序と向きである。
操作できる要素が、操作できると見て分かる形になっている。

### 禁止事項
内部の用語と実装の都合を、画面に出すこと。
同じ概念に、画面ごとに別の語を当てること。
操作できる要素を、操作できると分からない形にすること。

### 行動
画面の語を業務の語彙と照らし、内部の用語を写し替える。
操作と効果の対応を、実世界の慣習に合わせる。
操作できる要素に、操作できると分かる手掛かりを与える。

## 情報を局面と依存でまとめ、余白と階層で導く

### 要求
情報は、利用の局面と前後の依存でまとめ、無関係なものを同列に混ぜない。
視覚の区切りを、責務の境界に一致させる。
構造は、罫線の多用でなく余白と字の強弱で示す。
無関係なものと稀にしか使わないものを、画面に出さない。

### 根拠
局面と依存でまとめると、利用者は今の局面に要るものだけを見られる。
依存の向きをレイアウトで示すと、何が先で何が後かが分かる。
余分な情報は、関連する情報と競合して相対的な見やすさを下げる。
装飾が主題を覆うと、データより様式が前に出る。

### 完了条件
情報が、利用の局面と依存でまとまっている。
視覚の区切りが、責務の境界と一致している。
無関係なものと稀用のものが、画面に出ていない。

### 禁止事項
依存の異なる情報を、同列のフラットな並びに混ぜること。
装飾で、データを覆うこと。
稀にしか使わない情報を、常時画面に出すこと。

### 行動
画面の情報を、利用の局面と依存で見分け、混在を解く。
依存の向きをレイアウトで表し、余白と強弱で階層を示す。
装飾と稀用の情報を削る。

## 同じ目的に同じ画面のパターンを使う

### 要求
同じ目的の操作と表示には、同じパターンを当てる。
同じ目的の部品は、一つにして使い回す。
広く使われている慣習に従う。

### 根拠
同じ目的に同じ形を当てると、利用者は一度学べば全画面で通じる。
目的ごとに別の形を当てると、利用者は画面ごとに学び直す。
利用者は他の製品で多くの時間を過ごすので、慣習に従うと学習が要らない。

### 完了条件
同じ目的の操作と表示が、同じパターンで実現されている。
同じ目的の部品が、一つに集約されている。
同種の操作が、広く使われている形と同じになっている。

### 禁止事項
同じ目的に、画面ごとに別のパターンを当てること。
同じ目的の部品を、画面ごとに作り直すこと。

### 行動
画面を横断し、同じ目的に別のパターンや別の部品が当たっていないか確認する。
同じ目的の操作と表示を、一つのパターンと部品に統一する。
広く使われている慣習に合わせる。

## キーボードで操作でき、色だけに頼らない

### 要求
すべての操作を、キーボードでも行えるようにする。
フォーカスを、どこにも閉じ込めない。
状態は、色とラベルの両方で示す。
前景と背景に、十分な対比を持たせる。

### 根拠
マウスを使えない利用者のために、キーボードで全操作に届く必要がある。
フォーカスが閉じ込められると、キーボードの利用者は先へ進めない。
色だけで状態を示すと、色を見分けにくい利用者に伝わらない。
対比が足りないと、文字が読めない。

### 完了条件
マウスで届く操作が、すべてキーボードでも届く。
フォーカスが、どこにも閉じ込められていない。
状態が、色とラベルの両方で示されている。
前景と背景の対比が、WCAG の対比の基準を満たしている。

### 禁止事項
マウスでしか行えない操作を、置くこと。
状態を、色だけで示すこと。
フォーカスを、閉じ込めること。

### 行動
キーボードだけで画面を辿り、届かない操作とフォーカスの行き止まりを見つける。
すべての操作にキーボードの経路を与え、フォーカスの順路を保つ。
状態を色とラベルの両方で示し、対比を確保する。

## 情報構造を作業の流れに沿わせ、現在地を示す

### 要求
画面の構成と並びを、利用者の作業の流れに沿わせる。
一覧と詳細は、多数を検索して開くならルート分割、短い設定を頻繁に行き来するなら並置で組む。
利用者が今どこにいるかを、常に示す。

### 根拠
作業の流れに沿った構成は、利用者が次にどこへ行くかを予測できる。
多数を検索して開く画面は、一つずつ route で開くと戻ると共有がしやすい。
短い設定を頻繁に行き来する画面は、一覧と詳細を並置すると移動が要らない。
現在地が見えないと、利用者は全体の中で自分の位置を見失う。

### 完了条件
画面の構成と並びが、作業の流れに沿っている。
一覧と詳細が、用途に応じてルート分割か並置のどちらかで組まれている。
現在地が、常に画面に示されている。

### 禁止事項
作業の流れに反する順序で、画面を並べること。
現在地を、利用者から隠すこと。

### 行動
画面の並びを作業の流れと照らし、合わない順序を直す。
一覧と詳細の用途を見分け、ルート分割か並置を選ぶ。
現在地を常に示す。

## 誇張せず、効かないものを見せない

### 要求
画面は、製品の能力を実際以上に見せない。
文脈で効かない操作と選べない選択肢を、見せない。
利用者を欺く誘導をしない。

### 根拠
能力を実際以上に見せると、利用者は果たされない期待で誤る。
効かない操作と選べない選択肢は、利用者の判断を増やすだけで意味を持たない。
利用者を欺く誘導は、短期の数字と引き換えに信頼を失う。

### 完了条件
画面の表示が、製品の実際の能力に一致している。
文脈で効かない操作と選べない選択肢が、画面に出ていない。
利用者を欺く誘導が、画面にない。

### 禁止事項
製品の能力を、実際以上に見せること。
文脈で効かない操作と選択肢を、見せること。
利用者を欺く誘導を、置くこと。

### 行動
画面の操作と選択肢を、文脈で実際に効くか確かめ、効かないものを外す。
表示を製品の実際の能力に合わせ、欺く誘導を取り除く。
