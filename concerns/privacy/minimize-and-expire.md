## 個人情報は最小化して載せ、期限で消す

### 要求
記録する事実に個人情報を載せるときは、目的に必要な項目だけに絞る。
本人を特定できる項目は、必要がなければ載せず、必要なら仮名化するか識別子に置き換える。
個人情報を含む記録には、目的、契約、法令ごとに保持の期限を定め、期限を過ぎた記録を消す。
消去の義務を負う個人データは、現在情報の関係に個別に消せる形で保持し、管理操作で対象を消去する。
消去の義務を負う個人データは、消去後も保持する業務事実、outbox、ログ、監査の記録へ写さず、写しを持つ cache や検索 index を含む全ての保持先を消去の対象にする。
消去後も残す識別子と参照は、保持の根拠となる契約が必要とする範囲に限り、他の情報と照合して本人を識別できる識別子にも保持の期限を定める。
保持の根拠が消去の義務と衝突する項目は、保持する範囲と期限と根拠を決定の記録に定め、根拠が尽きた時点で消す。
期限を過ぎた記録の消去は、参照元の記録から先に行い、参照するデータが残る親リソースの識別子を、その後に消す。
消去の監査には個人データを再記録せず、対象を識別できない消去済みの事実だけを残す。
バックアップには保持期限を定め、期限までに消去対象を含む世代を失効させる。

### 根拠
事実に文脈を豊かに載せる規律は、個人情報を無制限に運んでよい理由にはならない。
載せる項目を目的に必要な範囲へ絞れば、記録が漏れたときに及ぶ範囲を狭められる。
本人を特定できる形をそのまま残すと、記録そのものが個人情報の保管先になり、消去の義務を負う対象が記録の置き場にまで広がる。
仮名化や識別子への置き換えは、事後の相関を保ちながら本人の特定を難しくする。
保持の期限がない記録は、消去の義務を果たす手段を欠いたまま個人情報を溜め続ける。
消去の義務を負う個人データを現在情報の関係へ集めれば、業務事実を不変に保ったまま、現在情報を削除するだけで消去を実施できる。
消去後も保持する記録へ個人データを複製すると、不変性の保持と消去の義務が衝突し、どちらかを破ることになる。
識別子が他の情報と照合して本人を識別できる場合、識別子だけを残しても個人情報の保持は続くので、残す理由と期限が要る。
保持の根拠は目的、契約、法令ごとに期間が異なり、消去の義務と衝突する項目だけを個別に定めれば、一律の長期保持も一律の即時消去も避けられる。
参照元より先に親の識別子を消すと、残すべき参照が宙に浮くので、参照元から消す順序が要る。
管理操作とバックアップの期限を同じ消去義務へ結び付ければ、稼働中の正本だけを消して古い複製へ残す状態を防げる。

### 完了条件
記録する事実に含まれる個人情報が、目的に必要な項目だけに絞られている。
本人を特定できる項目が、仮名化されているか識別子に置き換えられているか、必要がなければ載っていない。
個人情報を含む記録に、目的、契約、法令ごとの保持の期限が、決定の記録に定められている。
期限を過ぎた記録が、消えている。
消去対象の個人データが、現在情報の関係にあり、管理操作で個別に消去されている。
消去対象の個人データが、消去後も保持する業務事実、outbox、ログ、監査の記録になく、cache や検索 index の写しを含む全ての保持先から消えている。
消去後も残る識別子と参照が、保持の根拠が必要とする範囲に限られ、それぞれに保持の期限がある。
保持の根拠が消去の義務と衝突する項目に、保持する範囲、期限、根拠が決定の記録に定められている。
期限を過ぎた記録が参照元から先に消え、親リソースの識別子が、それを参照するデータの消去より後に消えている。
消去対象を含むバックアップが、保持期限までに失効している。

### 禁止事項
目的に必要でない個人情報を、記録する事実に載せること。
個人情報を含む記録を、期限を定めずに保持し続けること。
消去した個人データを、消去の監査記録へ複製すること。
契約が履歴を求めない個人情報の変更履歴を追記して保持する禁止は、[data](../../principles/data/preserve-facts-and-current-state.md) の禁止事項に従う。
消去後も保持する業務事実、outbox、ログへ、消去の義務を負う個人データを載せること。
消去の義務と衝突する保持を、根拠も期限も決定の記録に定めずに続けること。
消去対象を含むバックアップを、定めた保持期限の後まで復元可能に保つこと。

### 行動
記録へ載せる項目を洗い出し、目的に必要な範囲を確認する。
本人を特定できる項目は、仮名化するか識別子に置き換える。
個人情報を含む記録に、目的、契約、法令ごとの保持の期限を設定し、期限で消す仕組みを用意する。
消去の義務を負う個人データを、業務事実やログへ載せず、現在情報の関係に置く。
写しを持つ cache や検索 index を含む全ての保持先を洗い出し、消去の手順へ含める。
個人データを個別に消去する管理操作を用意し、個人データを含まない消去済みの事実だけを監査へ残す。
消去の義務と保持の根拠が衝突する項目は、保持する範囲、期限、根拠を決定の記録へ残す。
期限を過ぎた記録の消去は、参照元から先に実行し、参照するデータが尽きた親リソースの識別子を最後に消す。
バックアップの保持期限と失効を消去手順へ含める。
期限や消去の契約による削除は、[data](../../principles/data/preserve-facts-and-current-state.md) の「業務事実と現在情報を分けて保持する」に従い、追記の規律からの逸脱でなく通常の操作として扱い、保持期間、根拠、消去の方法を project の決定記録に残す。

### 例

個人情報をそのままログへ載せると、漏えい時に本人を特定できる範囲が広がる。

```
log({ event: "order_placed", customerName, customerEmail, amount })
```

ログへ載せる情報を目的に必要な範囲へ絞り、本人を特定できる項目は識別子で扱う。

```
log({ event: "order_placed", customerId, amount })
```

退会の業務事実へ氏名とメールアドレスを写すと、現在情報を消しても退会の事実に個人データが残る。

```sql
CREATE TABLE user_withdrawals (
  user_id BIGINT PRIMARY KEY REFERENCES users (id),
  withdrawn_at TIMESTAMP WITH TIME ZONE NOT NULL,
  display_name VARCHAR(100) NOT NULL,
  email VARCHAR(255) NOT NULL
);
```

退会の業務事実は、親リソースの識別子と出来事の時刻だけを持ち、氏名とメールアドレスは現在情報の関係に置いて退会の確定で消す。

```sql
CREATE TABLE user_withdrawals (
  user_id BIGINT PRIMARY KEY REFERENCES users (id),
  withdrawn_at TIMESTAMP WITH TIME ZONE NOT NULL
);
CREATE TABLE user_emails (
  user_id BIGINT PRIMARY KEY REFERENCES active_users (user_id) ON DELETE CASCADE,
  email VARCHAR(255) NOT NULL
);
```
