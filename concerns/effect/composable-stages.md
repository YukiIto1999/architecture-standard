## 合成して部分代替できるようにする

### 要求
失敗しうる処理は、合成できる段の連なりとして組む。
失敗しうる純粋な判断は Result の段で、効果は記述の段で連ねる。
失敗し得ない純粋な写像は、Result で包まず、値を返す関数のまま連ねる。
後段が前段の出力を入力にする依存では、前段が想定内の失敗で終えたら後段を実行せず、その失敗を後段へ短絡して伝播させる。
同じ入力に対する、互いの出力に依存しない検証の想定内の失敗は、先頭の失敗で打ち切らず、全て蓄積して返す。
蓄積した違反は、その operation が宣言する想定内の失敗の型に載せ、共有の汎用の失敗型を新設しない。
蓄積した検証が全て成功した場合にだけ、その出力を使う後段へ進む。
蓄積の対象は外部の状態を変えない検証に限り、外部の状態を変える段は、先行する想定内の失敗の後に起動しない。
欠陥と取り消しは、蓄積も検証の失敗への変換もせず、後段を短絡して伝播させ、握り潰さない。
終了の分類は [failure-defect-cancellation](./failure-defect-cancellation.md) の「失敗と欠陥と取り消しを分ける」に従う。
蓄積は結果の合成の規則であり、並行に実行することを求めない。
並行に実行する場合の寿命と合流は [structured-concurrency](../concurrency/structured-concurrency.md) の「構造化並行で寿命をスコープに束ねる」に従う。
各段を差し替え・追加・除去できる形にし、差し替えの条件と段の形は [immutable-transformations](../../principles/construction/immutable-transformations.md) の「値を不変に扱い、変換の連なりで組む」に従う。

### 根拠
各段が Result または効果の記述で、成功と失敗の二線で連なるので、合成でき、差し替え・追加・除去ができる。
後段が前段の出力を入力にするなら、前段が失敗した後には後段へ渡す入力が無い。
失敗・欠陥・取り消しが後段を短絡して伝播すると、誤った状態のまま処理が進まない。
途中の失敗を握り潰すと、誤った状態のまま処理が続く。
互いに独立した検証は、一方の失敗が他方の入力を欠かさないので、先頭の失敗で打ち切る理由が無い。
打ち切ると、呼び出し側は違反を一つずつ直して再実行するしかない。
蓄積して返せば、一度に全ての想定内の失敗を知らせられる。
蓄積の対象は、回復できる入力の不正である想定内の失敗だけである。
欠陥は直すべき誤りの証拠であり、取り消しは失敗でも成功でもないので、検証の失敗へ写すと、情報が落ち、誤りを入力の不正と取り違える。
書き込みなど外部の状態を変える段は、先行する失敗の後に起動すると、誤った入力で効果が起きる。
失敗し得ない写像を Result で包むと、起きない失敗の分岐を呼び出し側が処理することになる。
蓄積は結果をどう合成するかの規則であり、評価の順序も並行度も定めないので、独立した検証を逐次に評価しても規則は変わらない。

### 完了条件
処理が、Result または効果の記述の段の連なりとして組まれている。
後段が前段の出力を入力にする依存で、前段が想定内の失敗で終えたとき、後段が実行されず、その失敗が返っている。
同じ入力に対する互いに独立した検証の想定内の失敗が、複数が同時に起きても、全て一つの結果に残っている。
蓄積した違反が、operation の想定内の失敗の型で表され、共有の汎用の失敗型に畳まれていない。
蓄積した検証が全て成功した場合にだけ、その出力を使う後段が実行されている。
外部の状態を変える段が、先行する想定内の失敗の後に起動されていない。
欠陥と取り消しが、蓄積にも検証の失敗にも写されず、後段へ伝播し、握り潰されていない。
失敗し得ない純粋な写像が、Result で包まれていない。
各段が独立した記述で、差し替え・追加・除去ができる。

### 禁止事項
途中の失敗・欠陥・取り消しを、握り潰して処理を続けること。
成功と失敗の分岐を、一つの関数に手続き的に散らすこと。
前段が失敗しているのに、未初期化の値や既定値を入力にして後段を実行すること。
互いに独立した検証の想定内の失敗を、先頭の一つだけ返して残りを落とすこと。
欠陥や取り消しを、検証の失敗として蓄積し、または変換すること。
失敗し得ない純粋な写像を、Result で包むこと。
独立した検証の蓄積を理由に、並行の実行を課すこと。

### 行動
処理を段に分け、各段が前段の出力を入力にするか、同じ入力に対して独立かを見分ける。
依存する段は連ねて合成し、前段の想定内の失敗を後段へ短絡させる。
独立した検証は、想定内の失敗を一つの結果へ蓄積して合成し、全て成功した場合にだけ後段へ進める。
欠陥と取り消しは、蓄積せず後段へ短絡させる。
失敗し得ない純粋な写像は、Result の段にせず、値を返す関数のまま連ねる。
起点の読みと終点の書きを殻に置く。

### 例

互いに独立した検証を `andThen` で連ねると、前の検証が失敗した時点で次を実行せず、名前が不正な入力ではメールの不正が返らない。
呼び出し側は違反を一つずつ直すことになる。

```
validate(input) = checkName(input) |> andThen(checkEmail(input))
```

独立した検証は失敗を蓄積して合成し、全て成功した出力だけを依存する後段へ渡す。
後段の失敗は短絡して伝播し、失敗し得ない `toEvents` は `map` で連ねて `Result` で包まない。
読み取りと書き込みの効果は殻へ置く。

```
validate(input) = accumulate(checkName(input), checkEmail(input))
validate(input) |> flatMap(decide) |> map(toEvents)
```
