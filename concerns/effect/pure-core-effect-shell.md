## 純粋核と効果の殻に分ける

### 要求
純粋核と効果の殻の分離は、[separation](../../principles/separation/effects-at-boundaries.md) の「副作用を境界に集める」に従う。
処理が純粋な核に属するかは、シグネチャでなく、その処理と推移的な呼び出し先が実際に起こす効果で決める。
推移的な呼び出し先には、依存する library と、引数で受けて呼ぶ関数を含む。
自身または推移的な呼び出し先で、原始効果、外界との接点である port の呼出し、可変なグローバル状態の参照を行う処理は、シグネチャが入出力の型や要求を宣言していなくても殻に置く。
入出力の型が現れないことと、要求が空であることは、純粋であることの根拠にしない。
純粋核は効果の記述で包まず、純粋な値と関数のままにする。
処理は、読む・判断する・書く、の順に並べ、書き始めたら入力の読みへ戻らない。

### 根拠
核と殻を分ける理由と、殻だけが核を呼べる非対称は、[separation](../../principles/separation/effects-at-boundaries.md) に従う。
この非対称が、核と殻の配置を一意に決める。
純粋な核を効果の記述で包むと、不要な殻の語彙が核に侵入し、再現性と単純さを損なう。
読む・判断する・書くの順を崩し、書いた後にまた読むと、状態への依存が増えて複雑になる。
シグネチャが示すのは宣言した入出力の型と要求だけであり、本体や呼び出し先が時刻・乱数・入出力・外部通信を直接行っても現れない。
入出力の型が現れないことや要求が空であることを根拠にすると、効果を持つ処理が核に置かれ、核の再現性とテストの単純さが失われる。
効果は呼び出し先から推移的に及ぶので、本体だけを見て分類すると、呼び出し先の効果を見落とす。
実際の効果で分類すれば、核の配置は宣言の書き方に左右されず、一意に決まる。

### 完了条件
純粋な核の処理が、自身にも推移的な呼び出し先にも、原始効果、外界との接点である port の呼出し、可変なグローバル状態の参照を持たない。
それらを推移的に持つ処理が、すべて殻に置かれている。
処理の分類が、入出力の型や要求が空であることに依らず、実際の効果で決められている。
純粋な核が、効果の記述で包まれていない。
殻が薄く、業務判断を持たない。
処理が、読む・判断する・書くの順に並んでいる。

### 禁止事項
純粋な核を、効果の記述で包むこと。
判断と効果の記述を、同じ関数に混ぜること。
書き込みを始めた後に、入力の読み出しへ戻ること。
原始効果、外界との接点である port の呼出し、可変なグローバル状態の参照を推移的に持つ処理を、純粋な核に置くこと。
入出力の型が現れないことや要求が空であることだけを根拠に、処理を純粋な核に分類すること。

### 行動
処理ごとに、呼び出し先を推移的にたどり、原始効果、外界との接点である port の呼出し、可変なグローバル状態の参照があるかを見る。
無ければ核へ、有れば殻の読みか書きへ分類する。
入出力の型と要求は分類の根拠にせず、実際の効果との食い違いを探す手がかりにする。
判断を純粋な関数へ切り出し、決定を値で返させ、効果は殻へ移す。

### 例

シグネチャに入出力の型も要求も現れない処理でも、呼び出し先が現在時刻を読めば、殻の処理である。

```
isExpired(token) = token.expiresAt < currentTime()
currentTime() = readSystemClock()
```

時刻を殻が読んで値で渡せば、判断は核に置ける。

```
isExpired(token, now) = token.expiresAt < now
```

読み取りと書き込みを殻へ置き、核は受け取った値から判断だけを返す。

```
existing = read(input)
decision = decide(existing, input)
write(decision)
```
