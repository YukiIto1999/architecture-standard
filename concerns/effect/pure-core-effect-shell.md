## 純粋核と効果の殻に分ける

### 要求
純粋核と効果の殻の分離は、[separation](../../principles/separation/effects-at-boundaries.md) の「副作用を境界に集める」に従う。
純粋核は効果の記述で包まず、純粋な値と関数のままにする。
処理は、読む・判断する・書く、の順に並べ、書き始めたら入力の読みへ戻らない。

### 根拠
核と殻を分ける理由と、殻だけが核を呼べる非対称は、[separation](../../principles/separation/README.md) に従う。
この非対称が、核と殻の配置を一意に決める。
純粋な核を効果の記述で包むと、不要な殻の語彙が核に侵入し、再現性と単純さを損なう。
読む・判断する・書くの順を崩し、書いた後にまた読むと、状態への依存が増えて複雑になる。

### 完了条件
シグネチャに入出力の型が現れない処理が、すべて純粋な核に置かれている。
純粋な核が、効果の記述で包まれていない。
殻が薄く、業務判断を持たない。
処理が、読む・判断する・書くの順に並んでいる。

### 禁止事項
純粋な核を、効果の記述で包むこと。
判断と効果の記述を、同じ関数に混ぜること。
書き込みを始めた後に、入力の読み出しへ戻ること。

### 行動
関数ごとに、入出力の型が要るかを見る。
要らなければ核へ、要れば殻の読みか書きへ分類する。
判断を純粋な関数へ切り出し、決定を値で返させ、入出力は殻へ移す。

### 例

読み取りと書き込みを殻へ置き、核は受け取った値から判断だけを返す。

```
existing = read(input)
decision = decide(existing, input)
write(decision)
```
