## secret を分けて専用の型に封じる

### 要求
secret は、機密でない設定や一般状態と分けて扱い、通常の表示と直列化を塞ぐ専用の型に封じる。
資格情報は、その値で認証や権限の行使ができる secret として扱い、接続先や公開 client ID のような機密でない設定と区別する。
secret の永続保管は、平文を残さず、値と復号鍵へのアクセスを制限する専用の仕組みに委ねる。
認証や通信に必要なメモリ上の保持は、永続保管と区別し、consumer と生存期間を限定する。
consumer は、secret の取得、保管、認証、または認可済みの通信を担う境界とし、値を使わない業務処理や UI へ渡さない。
設定から供給する secret は、設定に値でなく参照を置き、起動時に専用の仕組みから解決する。
対話認証で取得する資格情報は、起動時の設定解決とは別の取得経路とし、取得、更新、再取得を取得側の専用の consumer が所有する。
受け取った資格情報を検証して actor を構築する [authentication](../authentication/README.md) の責務と、取得側の lifecycle の責務を分ける。
secret は回転、失効、期限、監査の対象とし、保持の終了、期限切れ、発行元や server における失効を別の条件として定める。
secret をログ、例外、診断、通常の業務応答へ出さない。
資格情報を応答で発行・交換する専用の認証 protocol は、発行・交換の権限、受信者、認証 transaction との対応、対象、scope を検証してから、許可された受信者へ必要な資格情報だけを渡す。
HTTP による資格情報の発行・交換は HTTPS で行い、資格情報を含む応答に `Cache-Control: no-store` と `Pragma: no-cache` を付け、専用の encoder と consumer 以外に値を露出させない。

### 根拠
secret を一般の設定や状態と同じに扱うと、表示や診断へ紛れて漏れる。
専用の型で通常の表示と直列化を塞ぎ、値を使う consumer を限定すれば、認証や通信に必要な露出を境界の内に閉じられる。
永続保管とメモリ上の保持は、漏洩する経路と残る期間が異なるため、同じ保存という語だけでは保護の充足を判定できない。
保持の終了は手元の値を使えなくする処理であり、既に持ち出された資格情報を発行元や server で失効させる処理ではない。
値でなく参照を設定へ置けば、設定由来の secret が設定やコードに残らず、対話認証を別の取得経路にすれば、取得後の更新と失効も境界で管理できる。
回転と期限を定め、失効が効く時点と範囲を明示すれば、漏れた secret を利用できる期間を評価できる。
正当な資格情報の発行・交換は認証 protocol の責務であり、業務応答へ既存の secret を返すこととは異なる。
OAuth の token response とキャッシュ禁止は [RFC 6749 の 5.1 節](https://www.rfc-editor.org/rfc/rfc6749.html#section-5.1) に、token endpoint の TLS は [3.2 節](https://www.rfc-editor.org/rfc/rfc6749.html#section-3.2) に従う。

### 完了条件
secret が、機密でない設定や一般状態と分けられ、専用の型で通常の表示と直列化を塞がれている。
永続保管の値が平文で残らず、値と復号鍵の保管先、アクセスできる主体、保護する漏洩経路が明示されている。
メモリ上に保持する secret ごとに consumer、利用目的、保持の上限、期限切れと失効への対処、破棄条件が定められている。
不要になった値と参照が破棄され、保持期間外や失効を認識した後の再利用が拒否されている。
メモリからの破棄を、発行元や server における失効の証拠として扱っていない。
設定由来の secret は値でなく参照を持ち、起動時に解決され、対話認証で取得する資格情報は取得後の更新と再取得まで取得側の専用の consumer に閉じている。
secret が、回転、失効、期限と、誰がいつ何に使ったかの監査の対象になっている。
ログ、例外、診断、通常の業務応答に secret が含まれていない。
資格情報の発行・交換応答がある場合は、権限、受信者、transaction、対象、scope の検証と、HTTPS、キャッシュ禁止、専用の encode と consume の経路を確認できる。
リポジトリを公開しても、資格情報が漏れない。

### 禁止事項
secret を、平文の設定、コード、または永続保管に置くこと。
secret を、ログ、例外、診断、通常の業務応答に出すこと。
正当な資格情報の発行・交換を理由に、通常の業務応答から secret を取り出す経路を設けること。
必要な検証、HTTPS、キャッシュ禁止を欠く資格情報の発行・交換応答を返すこと。
メモリ上の保持を理由に、永続保管の機密性を弱めること。
consumer と生存期間を限定せずに secret を保持すること。
secret を、値を使わない業務処理や UI へ渡すこと。
secret を使い、任意の宛先や操作を実行する汎用の代理機能を公開すること。
secret を、ビルドの成果物やイメージへ焼き込むこと。
secret を、必要のない子プロセスへまで継承させること。

### 行動
機密でない設定と secret を分類し、secret を専用の型へ封じる。
設定由来の参照解決と対話認証による取得を分け、どちらも専用の consumer が値を受け取る。
永続保管は専用の仕組みに委ね、値と復号鍵を別に保護する。
メモリ上の保持には所有者と終了条件を定め、期限切れ、失効、logout、利用終了で不要になった値と参照を破棄する。
保持の終了と server 側の失効を別々に確認し、失効後も利用できる資格情報がある場合は、その上限を期限の契約で明示する。
資格情報の発行・交換を実装する境界では、専用の検証、encoder、consumer を定め、値を含めずに発行、利用、拒否、失効を監査できるようにする。
