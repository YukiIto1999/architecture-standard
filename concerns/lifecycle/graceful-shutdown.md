## 合図を受けたら受付をやめ、期限内で終える

### 要求
停止の合図を受けたら新しい仕事の受付をやめ、進行中の仕事は期限の中で完了させる。
期限の中で終わらない仕事は再実行できる形で返して止まり、確定の途中で処理を打ち切らない。
停止時の仕事には request に閉じる処理だけでなく、host が所有する常駐処理も含める。
処理の所属、取り消し要求と完了の区別、資源解放前の合流は [concurrency](../concurrency/structured-concurrency.md) の「構造化並行で寿命をスコープに束ねる」に従う。
期限切れだけで正常停止を宣言せず、停止できない処理と未完了の後始末を識別する。
期限内に協調停止できない処理の隔離は [concurrency](../concurrency/cooperative-cancellation.md) の「取り消しを協調的に伝える」に従い、強制終了時の回復は [crash-tolerance](./crash-tolerance.md) の「突然死に耐える」に従う。

### 根拠
合図の後も受付を続けると、停止が終わらない。
受付をやめ進行中だけを期限内で終えれば、安全に止まれる。
期限内で終わらない仕事を再実行できる形で返せば、別のインスタンスが引き継げる。
確定の途中で打ち切ると、状態が不整合になる。

### 完了条件
停止の合図の後、新しい仕事を受け付けず、外部のトラフィックの振り分けから外れている。
進行中の仕事が、期限の中で完了するか、再実行できる形で返されている。
確定の途中で、処理が打ち切られていない。
host の常駐処理が停止対象へ含まれ、資源解放前の合流が concurrency の正本に従って完了している。
期限を超えて残る処理または後始末がある停止を、正常停止として報告していない。

### 禁止事項
停止の合図の後に、新しい仕事を受け付けること。
期限を設けずに、進行中の仕事を待ち続けること。
確定の途中で、処理を打ち切ること。
停止期限の到来を、処理の完了または資源解放の完了とみなすこと。

### 行動
合図で受付を止め、進行中を期限の中で終える。
終わらない仕事には取り消しを伝え、再実行できる形への返却と後始末の完了を確認する。
request と常駐処理の所有者を停止経路へ接続し、全ての子の合流後に host の依存資源を解放する。
期限内に終えられない処理は未完了として報告し、突然死後の回復契約に接続する。
