## 突然死に耐える

### 要求
合図のない停止の後も、再実行と再配送で回復できるように作る。
重要な状態はプロセス内に持たず、専用の永続化へ外出しして、プロセスを捨てて作り直せるようにする。
回復の前提は、確定した状態が永続化へ commit 済みであることと、再実行と再配送が冪等であることに置く。
状態の保存の形が追記か更新かは、回復の要件にしない。
回復が履歴の再生を要する対象だけ、その履歴を回復の契約が求める業務事実として定める。
回復の経路は、毎回の起動で通す。

### 根拠
プロセスは、合図なく落ちうる。
優雅な停止だけに頼ると、突然死で状態が失われる。
プロセス内に溜めた状態は突然死で失われるので、重要な状態を専用の永続化へ外出しすれば、プロセスは捨てて作り直せる。
停止の後に読めるのは commit 済みの状態だけであり、未確定の作業は再実行と再配送で同じ結果へ収束させる。
回復に要る前提を commit と冪等性に置けば、現在値だけでよい状態は更新で保存でき、履歴の保持を回復のために負わなくてよい。
履歴の再生が回復に要る対象だけを業務事実として保持すれば、回復の契約と保持の契約が一致する。
回復の経路を毎回の起動で通せば、回復のコードが常に検証される。

### 完了条件
合図のない停止の後も、再実行と再配送で回復できる。
回復の前提が、確定した状態の永続化への commit と、再実行と再配送の冪等性で満たされている。
履歴の再生を回復に要する対象が、その履歴を保持期間の間、業務事実として保存している。
再実行や再配送での回復に必要な状態が、プロセス内に保持されず専用の永続化へ外出しされている。
回復の経路が、毎回の起動で通っている。

### 禁止事項
優雅な停止だけに頼り、突然死で回復できない状態を作ること。
重要な状態をプロセス内に溜め、突然死で失われる形にすること。
commit 前の状態を、回復の起点にすること。
回復の成立を、状態の保存の形が追記であることに依存させること。

### 行動
重要な状態を専用の永続化へ外出しし、プロセス内に溜めない。
確定した状態を commit 済みの永続化から読み、冪等性で再実行と再配送の重複を吸収して、突然死からの回復の前提を満たす。
履歴の再生を回復に要する対象を洗い出し、その履歴の保持期間を回復の契約として決定の記録へ残す。
冪等性と再実行は [resilience](../resilience/README.md)、確定点は [transaction](../transaction/README.md)、保持する状態の形は [data](../../principles/data/preserve-facts-and-current-state.md) に従う。
