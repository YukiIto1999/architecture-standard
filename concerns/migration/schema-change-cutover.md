## 新旧の併存に応じてスキーマを切り替える

### 要求
schema の変更は、新旧の program が同時に稼働する併存の有無で切替の手順を分け、どちらを選ぶかを決定の記録に残す。
併存とは、変更の適用から切替の完了までに、旧い構造だけを読み書きする program と新しい構造を読み書きする program が同時に動くことである。
複数の instance を順に入れ替える配備は併存であり、旧い構造を読む replica、バッチ、外部の接続が残る場合も併存である。
無停止は、project の要件が求める場合の条件であり、全ての schema の変更の前提ではない。
schema migration は、停止切替でも併存でも forward-only の artifact とし、戻す場合も既存 artifact を逆実行せず、新しい forward migration で戻す。
旧い構造を読み書きする全ての経路を止められる場合は、停止切替を選んでよく、新旧の構造への二重書きと旧い構造を残す段を要件にしない。
停止切替は、変更の前に、旧い構造を読み書きする全ての経路(複数の instance、バッチ、外部の接続を含む)が止まり、新たな読み書きが入らないことを確かめる。
停止切替は、変更の前に、適用履歴を含めて停止の時点の状態を復元できる復旧点を取り、復元の手順を確かめる。
停止切替は、変更の適用の後に、移行の前に定めた基準で意味と値を照合し、通過した後にだけ新しい program を起動して受付を再開する。
停止切替で適用または照合に失敗した場合は、復旧点へ戻して旧い program で受付を再開する。
停止中に届く要求は、失わずに保持するか、再試行可能な失敗として拒否する。
受付を再開した後は、復旧点へ戻すと再開後の書き込みを失うので、戻しは新しい forward migration で行う。
併存する場合の互換を保てる変更は、旧い program の読み書きを壊さないことを確かめて適用してよい。
併存する場合の互換を保てない変更は、新しい構造を加える段、新旧の構造へ両方とも反映して既存データを移す段、旧い構造を落とす段の三段に分ける。
読み出しを新しい構造へ切り替える段より前は、いつでも旧い構造へ戻せる状態を保つ。
既存データの移送は、途中で失敗しても再実行でき、併存中の新しい書き込みを古い値で上書きしない。
読み出しを新しい構造へ切り替える前に、新旧の構造の意味と値を全ての行で照合する。
拡張の段で加える列や表は、移行が終わるまでの一時的なものであり、任意項目として恒久的に残さない。
保存済みの事実の関係を移す場合は、停止切替でも三段でも、意味と値の保持を [persistence](../persistence/fact-preserving-migrations.md) の「保存済みの事実を意味と値を保って移行する」に従って守る。

### 根拠
併存しない切替では、新しい構造しか読めない program と旧い構造しか書かない program が同時に存在しないので、互換のための中間の構造と二重書きは要らない。
二重書きと旧い構造を残す段は併存の費用であり、停止して切り替えるときに課すと、新旧の食い違いと後始末を増やすだけになる。
停止切替が安全なのは、旧い経路が残らないこと、戻す先があること、結果を照合できることを、事実で確かめてから再開するからである。
旧い経路が一つでも残ると、停止切替の前提が崩れ、併存と同じく、どちらかの program が失敗する。
受付を再開すると復旧点より後の書き込みが生まれ、復旧点へ戻すとそれを失うので、再開より後は復旧点へ戻れない。
再開の前に照合を済ませるのは、この戻れない点の手前で、進むか戻るかを事実で決めるためである。
段階に分ける理由と拡張・移行・収縮という一般の形は [evolution](../../principles/evolution/README.md) に従い、ここでは関係の変更として具象化する。
併存する稼働中の関係を一度で置き換えると、新しい構造しか読めない実行中のコードと、旧い構造しか書かない実行中のコードが同時に存在する間、どちらかが失敗する。
新しい構造を先に加えて両方へ反映すれば、新旧のコードが並行して動き続けられる。
読み出しを新しい構造へ切り替えた後は、旧い構造だけに残る更新が届いても現在状態に反映されなくなるため、そこから先は戻れない。
参照が消えたことを確かめてから旧い構造を落とせば、両立の期間を必要最小限に閉じられる。
移送が途中で止まって再実行できなければ、新旧の構造の一部だけが移った状態が残り、古い値による上書きは併存中の新しい書き込みを失わせる。
拡張で加えた列を任意項目のまま恒久的に残すと、移行が終わったのかを判別できず、収縮の段が永遠に来ない。
互換を保てる変更は、旧い program の読み書きが壊れないので、段に分ける理由がない。

### 完了条件
切替の方式と、停止切替を選んだ場合に旧い構造の全ての経路を止められる根拠が、決定の記録から追える。
schema migration の artifact が forward-only であり、戻しが既存 artifact の逆実行でなく新しい forward migration で行われている。
停止切替で、旧い構造を読み書きする全ての経路が止まったことが、変更の前に確かめられている。
停止切替で、適用履歴を含む復旧点が取られ、復元の手順が確かめられている。
停止切替で、変更の後の照合の通過が、新しい program の起動と受付の再開より前にある。
停止切替で、適用または照合の失敗が復旧点へ戻され、再開後の戻しが新しい forward migration で行われている。
併存する互換を保てない変更が拡張・移行・収縮の段で進み、収縮まで到達していることの判定は、[evolution](../../principles/evolution/README.md) の完了条件に従う。
併存する互換を保てる変更の適用の後も、旧い program の読み書きが壊れていない。
読み出しの切り替えより前の各段で、旧い構造への後戻りができる。
既存データの移送が再実行でき、併存中の新しい書き込みを古い値で上書きしていない。
読み出しを切り替える前に、新旧の構造の意味と値が全ての行で照合されている。
旧い構造を落とす収縮の段が、読み出しの切り替えと参照の消滅を確かめた後に行われている。
拡張の段で加えた列や表が、収縮の段で落とされているか、恒久の構造として制約を備え直されている。

### 禁止事項
旧い構造を読み書きする経路が残る間に、互換を保てない変更を、拡張・移行・収縮の三段を経ずに一度で置き換えること。
旧い構造を読み書きする経路が残っているのに、停止切替として変更を適用すること。
復旧点を取らず、または復元の手順を確かめずに、停止切替で変更を適用すること。
照合の通過より前に、停止切替の後の受付を再開すること。
受付を再開した後に、復旧点へ戻して再開後の書き込みを失うこと。
旧い構造を、参照が残っている間に落とすこと。
拡張の段の列を、任意項目として恒久的に残すこと。
併存中の移送で、新しい書き込みを古い値で上書きすること。

### 行動
schema を変えるときは、旧い構造を読み書きする経路が変更の間に動くかを確かめ、停止切替か併存かを決めて、根拠を決定の記録に残す。
旧い構造を読み書きする全ての経路を止められる場合は、全ての経路の停止を確かめ、復旧点を取り、変更を適用し、照合して、通過後に新しい program を起動して受付を再開する。
併存する互換を保てない変更は、新しい構造を一時的な nullable として加え、旧い構造と併存させる。
新旧どちらの書き込みも新しい構造に反映され、移送が再実行でき新しい書き込みを上書きしないことを確かめ、新旧の意味と値を全ての行で照合してから、読み出しを新しい構造へ切り替える。
参照が消えたことを確認し、旧い構造を落とす。
保存済みの事実の関係を移す場合は、意味と値の保持を [persistence](../persistence/fact-preserving-migrations.md) の「保存済みの事実を意味と値を保って移行する」に従って確かめる。
適用の手段と配備から分離した順序は [process/migration](../../process/migration.md) が定める。

### 例

併存する稼働中に列の名前を一度で変えると、旧版のコードによる書き込みが失敗する。

```sql
ALTER TABLE payments RENAME COLUMN amount TO paid_amount;
```

拡張では、新しい名前の列を一時的に nullable として加え、古い列と併存させる。

```sql
ALTER TABLE payments ADD COLUMN paid_amount NUMERIC(12, 2);
```

移行では新旧両方の列へ書き込み、既存行を新しい列へ移し、読み出しを切り替える前に新旧の値が全ての行で一致することを照合する。

```sql
UPDATE payments SET paid_amount = amount WHERE paid_amount IS NULL;
SELECT COUNT(*) FROM payments WHERE paid_amount IS NULL OR paid_amount <> amount;
```

読み出しを新しい列へ切り替えた後、収縮で古い列を落とし、新しい列の制約を備え直す。

```sql
ALTER TABLE payments DROP COLUMN amount;
ALTER TABLE payments ALTER COLUMN paid_amount SET NOT NULL;
```

全ての読み書きを止められる場合は、二重書きと旧い列を残す段を置かず、停止、復旧点、変更、照合、再開の順に進める。
照合の通過が再開の条件であり、再開が復旧点へ戻れない点になる。

```text
全ての読み書きを止める -> 復旧点を取る -> 列の名前を変える -> 照合する -> 新しい program で再開する
```
