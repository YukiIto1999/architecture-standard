## 資格情報を検証して actor を構築する

### 要求
資格情報を受け取るすべての信頼境界は、単一の認証境界を持つ。
認証境界は資格情報を未検証の入力として受け取り、その契約が定める発行元、対象、完全性、期限と失効条件を含む有効性を検証してから actor を構築する。
actor は業務が主体を識別するための型とし、資格情報、principal、token、claim、認証方式の型、検証前の属性を含めない。
資格情報の検証済みの許可範囲は actor と分けて境界内の認可評価へ渡し、操作と対象への制約は [evaluate-at-entry](../authorization/evaluate-at-entry.md) の「入口で評価し、通った要求だけ進める」に従う。
core の公開 API へは、認証境界が構築した actor と境界で検証した入力だけを渡す。
資格情報を検証できない要求は、actor を構築せず core の手前で拒否する。

### 根拠
資格情報の検証を信頼境界ごとの単一の認証境界に閉じれば、検証の抜けと経路ごとの食い違いを同じ境界で防げる。
資格情報から actor への変換を認証境界で終えれば、core は資格情報の形式と認証方式を知らず、業務に必要な主体だけを受け取る。
主体の確定と資格情報の許可範囲を分けて引き渡せば、認証方式を core へ漏らさずに、限定された資格情報を広い業務権限へ昇格させることを防げる。
検証に失敗した要求で actor を構築しなければ、未確認の主体が保護対象の処理へ到達しない。

### 完了条件
資格情報を受け取るすべての信頼境界に、認証境界が一つずつある。
認証境界が、資格情報の発行元、対象、完全性、期限と失効条件を含む有効性を検証してから actor を構築している。
actor が、資格情報、principal、token、claim、認証方式の型、検証前の属性を含んでいない。
資格情報の検証済みの許可範囲が actor とは別に境界内の認可評価へ渡され、actor の構築によって失われていない。
core の公開 API が、認証境界の構築した actor と境界で検証した入力だけを受け取っている。
資格情報を検証できない要求が、actor を構築せず core の手前で拒否されている。

### 禁止事項
資格情報の検証と actor の構築を、同じ信頼境界の複数箇所へ分散させること。
未検証の資格情報または属性から、actor を構築すること。
資格情報、principal、token、claim、認証方式の型、検証前の属性を、actor または core の公開 API へ渡すこと。
actor を構築したことだけを理由に、資格情報の許可範囲を捨てること。
要求側が指定した actor を、認証境界で再構築せずに受け入れること。

### 行動
信頼境界ごとに資格情報の入口を洗い出し、検証と actor の構築を単一の認証境界へ集める。
資格情報の契約に従って発行元、対象、完全性、期限と失効条件を含む有効性を検証し、検証済みの値から actor を構築する。
core の公開 API から資格情報、principal、token、claim、認証方式の型を除き、actor と検証済み入力だけを渡す。
資格情報の許可範囲は境界内に保持し、actor の業務権限とは別に認可評価へ引き渡す。
検証に失敗した要求は、actor を構築する前に拒否する。

### 例

資格情報を core へ渡すと、業務処理が主体の確定まで担う。

```
core.handle(request.credential, request.input)
```

認証境界で検証と actor の構築を終え、入口の認可を通った後に core へ渡すのは actor と検証済み入力だけにする。

```
identity = authenticationBoundary.verify(request.credential)
actor = authenticationBoundary.toActor(identity)
entry.authorize(identity.permissions, actor, request.operation)
core.handle(actor, parse(request.input))
```
