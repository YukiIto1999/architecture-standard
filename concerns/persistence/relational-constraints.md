## 関係の意図を制約で表す

### 要求
外部キー・一意・NOT NULL・検査で関係の意図を表す。
属性の配置は [normalization](./normalization.md) に従い、同じ変更・保持・消去の単位の任意属性は、その関係の nullable な列で値の不在を表す。
独立した存在意味やライフサイクルを持つ任意の関係は、行の有無で存在を表す。
外部キーの参照先は、参照元が残るべき期間を持つ関係から選ぶ。
退会後も残すデータは親リソースの識別子を参照して親の削除を拒み、同じ集約で現在関係に従属するデータは現在関係を参照して現在関係の削除とともに消す。
連鎖削除は、同じ集約内で、親が消えたら単独で存在する意味がない従属データだけに付ける。
別の集約の現在関係を参照する場合は連鎖削除を付けず、その集約の書き込みパスによる削除が済むまで参照先の削除を拒む。
関係をまたぐ排他のように、外部キー・一意・NOT NULL・検査では表せない不変条件は、決定の記録に列挙し、全ての書き込み経路が従う競合制御を [transaction](../transaction/single-write-path.md) の「整合性を一つの書き込みパスに閉じる」に従って割り当てる。
整合性をデータ層で守る規則は、[data](../../principles/data/database-integrity.md) に従う。

### 根拠
データ層の制約で守る理由は [data](../../principles/data/database-integrity.md) に従う。
外部キーは関係の意図そのものを表し、NOT NULL と一意は欠けてはならない値と重複してはならない値を保証する。
nullable な列を使う制約は、NULL が値の不在を表すことと三値論理を踏まえて設計し、欠如を許す範囲を明示する。
外部キーの参照先と削除規則が、参照元の存続期間を決める。
親リソースの識別子を参照する行は現在関係が消えても残り、現在関係を参照する行は現在関係とともに消える。
消すべき個人データの関係を現在関係でなく親リソースの識別子へ従属させると、現在関係を削除しても連鎖せず、消去し忘れた行が残る。
独立して存在できるデータへ連鎖削除を付けると、親の削除が無関係な行まで消す。
各関係の制約は自分の関係の行だけを検査するので、別の関係の行との同時成立は表せない。
たとえば現在関係の行と退会の業務事実の行が同じ利用者に両方あることを、双方が親リソースの識別子を参照する外部キーは拒めない。

### 完了条件
業務上必要な関係が、外部キー制約で表されている。
欠けてはならない値に NOT NULL、重複してはならない値に一意制約が付いている。
任意属性の値の不在と、独立した関係の不在が区別され、任意性だけを理由に同じ変更・保持・消去の単位の属性が分割されていない。
退会後も残すデータの外部キーが、親リソースの識別子を参照し、親の削除を拒む削除規則を持つ。
同じ集約の現在関係に従属するデータの外部キーが、現在関係を参照し、現在関係の削除で連鎖して消える削除規則を持つ。
連鎖削除が、同じ集約内で親に従属するデータだけに付いており、別集約の参照はその集約の書き込みパスで解除するまで参照先の削除を拒んでいる。
外部キーで表せない関係をまたぐ不変条件が、決定の記録に列挙され、それぞれに書き込み経路の競合制御が割り当てられている。

### 禁止事項
任意性だけを理由に、同じ変更・保持・消去の単位の属性を別の関係へ分割すること。
NULL の扱いを定めず、nullable な列への一意制約や検査制約だけで欠如や重複を拒めるとみなすこと。
残すべき参照を現在情報へ向ける禁止は、[data](../../principles/data/preserve-facts-and-current-state.md) の禁止事項に従う。
消すべき個人データの関係を、現在関係でなく親リソースの識別子だけへ従属させ、現在関係の削除の連鎖から外すこと。
独立に存在できるデータや、別の集約が所有するデータへ、連鎖削除を付けること。
関係をまたぐ排他を、外部キーまたは一つの関係の制約で守られているとみなすこと。

### 行動
データ間の関係を確認し、外部キーで表せる関係を制約にする。
欠けてはならない値と重複してはならない値に、NOT NULL と一意制約を付ける。
任意属性は変更・保持・消去の単位で配置し、nullable な列の欠如と独立した関係の行の有無を区別する。
外部キーごとに、参照元が残るべき期間を確かめ、親リソースの識別子と現在関係のどちらを参照するかを選び、削除規則を付ける。
外部キーで表せない不変条件を洗い出して決定の記録に列挙し、書き込みパスの競合制御へ割り当てる。

### 例

関係をアプリケーションの規約だけで守ると、データベースが不正な参照や数量を拒否できない。

```sql
order_lines(id, order_id, sku, qty, note)
```

関係と一意性を制約で守る。
この例のメモは、明細と異なる編集と消去の単位を持つため別の関係に置く。

```sql
order_lines(
  id,
  order_id  REFERENCES orders(id),
  sku       NOT NULL,
  qty       NOT NULL CHECK (qty > 0),
  UNIQUE(order_id, sku)
)
order_line_notes(line_id REFERENCES order_lines(id) PRIMARY KEY, note NOT NULL)
```

注文を現在関係へ向けると、退会で現在関係を削除するときに注文を連鎖で消すか、削除が失敗する。

```sql
CREATE TABLE orders (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES active_users (user_id) ON DELETE CASCADE
);
```

注文は親リソースの識別子を参照して親の削除を拒み、プロフィールは現在関係を参照して現在関係の削除とともに消える。

```sql
CREATE TABLE orders (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users (id) ON DELETE RESTRICT
);
CREATE TABLE user_profiles (
  user_id BIGINT PRIMARY KEY REFERENCES active_users (user_id) ON DELETE CASCADE,
  display_name VARCHAR(100) NOT NULL
);
```
