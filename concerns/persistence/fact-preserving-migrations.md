## 保存済みの事実を意味と値を保って移行する

### 要求
保存済みの事実で不変にするのは、何がいつどの値で起きたかという意味と内容であり、保存形式(構造・項目名・型・版)ではない。
意味と内容には、事実の値、活動の時刻、同一性を表すキー、他の行への参照を含む。
保存形式を互換の保てない形へ変えるときは、保存済みの行を新しい形へ書き換える移行か、旧い版の行を残して読み出しで現在の構造へ変換する方式で、事実の意味と値を保つ。
書き換える移行は、契約が元の保存形そのものの保持を求めず、移行の前後で全ての事実の意味と値の一致を照合でき、新しい形の全ての値が旧い形の記録とその意味を示す契約から定まる場合に選ぶ。
この三つのいずれかを満たさない行は、旧い版の行を残して読み出しで変換する。
書き換える移行は、移行の前に照合の基準(件数、不変条件、意味と値の正規形の checksum)を定め、移行の後に同じ基準で全ての事実を照合する。
書き換える移行は、業務の書き込み経路でなく移行だけの経路で行い、業務の書き込み経路の権限を移行のために広げない。
活動の時刻は元の値のまま移し、移行の実行時刻や既定値で置き換えない。
移行と読み出しの変換は、値を丸め、切り捨て、欠落させず、旧い形でしか表せない意味も落とさない。
旧い形に記録がない値は、移行でも読み出しの変換でも既定値で埋めず、不明として表す。
旧い形が暗黙に表していた意味を新しい形で明示するのは、その意味を旧い形の契約から示せる場合に限る。
事実の内容の訂正と取り消しは移行で行わず、[data](../../principles/data/preserve-facts-and-current-state.md) の追記の規律に従う。
旧い版の行を残す方式では、行の版を判別できる形で保ち、旧い版から現在の構造への変換を読み出しの一箇所に集め、変換後の構造だけを内側へ渡す。
保持・監査・回復の契約が旧版の解釈を必要とする間は、読み出し変換を維持する。
書き換える移行の後も、旧い形の行を入力として受ける保存先、分離保管、回復入力が契約上残る間は、その旧い形の解釈を維持する。
撤去は、その契約が対象とする保存先、分離保管、回復入力に、旧版の解釈を必要とする入力がなくなったことを確認して行う。
稼働中の切替の安全条件は [migration](../migration/schema-change-cutover.md) の「新旧の併存に応じてスキーマを切り替える」に従う。
wire 上のイベント契約の版の進化は [messaging](../messaging/event-contract-versioning.md) の「イベント契約を版で進化させ、寛容に読む」が正本であり、この規律は保存済みの事実の移行だけを扱う。

### 根拠
保存済みの事実を保持する理由は [data](../../principles/data/preserve-facts-and-current-state.md) の「業務事実と現在情報を分けて保持する」に従う。
その理由が守るのは、起きた事実の意味と内容であり、保存形式である構造・項目名・型は、技術上の都合で後から変わる。
保存形式の固定を求めると、技術上の変更のたびに旧い形を永久に保ち、旧い版の解釈を積み上げる負担を負う。
意味と値が移行の前後で一致していれば、行を書き換えても起きた事実は失われず、一致は照合で判定できる。
照合できない移行は、意味が保たれたかを後から確かめられない。
値の丸めや欠落は、起きた値を失い、元の値を取り戻せない。
取り戻せない変換を意味を保った移行と呼ぶと、失われた事実が見えなくなる。
旧い形に記録がない値を既定値で埋めると、起きていない事実が起きたように残る。
不明を不明のまま表せば、事実の範囲が変わらない。
旧い形が暗黙に表していた意味は、契約から示せれば、新しい形で明示しても事実を作らない。
移行で内容を直すと、訂正の事実が残らず、元の判断と訂正の経緯が失われる。
業務の書き込み経路の権限を移行のために広げると、同じ権限で通常の更新も通り、追記だけを受け付ける形が崩れる。
契約が元の保存形そのものの保持を求める行は、書き換えると契約の対象そのものが変わる。
旧い版の行を残して読み出しで変換すれば、保存済みの行を書き換えずに構造を進化でき、版の解釈が読み手ごとに割れない。
変換が内側へ散ると、全ての読み手が全ての版を知り、版の追加が全ての読み手へ波及する。
保存期間中の形式を読むことと、現在の業務処理を旧い方式で動かすことは異なり、前者を消すために事実を失わせない。
書き換える移行の後も、バックアップ、分離保管、回復入力に旧い形が残れば、その入力を読むために旧い形の解釈が要る。

### 完了条件
保存形式を変えた後も、保持対象の全ての事実で、値、活動の時刻、キー、参照が移行の前と同じ意味を表している。
書き換える移行で、移行の前に定めた基準により全ての事実の移行の前後が照合され、一致している。
移行と読み出しの変換の結果に、値の丸め、切り捨て、欠落がなく、旧い形に記録のない値が既定値で作られていない。
旧い形に記録がない値が、不明として表されている。
活動の時刻が、移行の実行時刻や既定値に置き換わっていない。
書き換える移行が移行だけの経路で行われ、業務の書き込み経路の権限が広がっていない。
選んだ方式と、書き換える移行を選んだ根拠が、決定の記録から追える。
旧い版の行を残す方式で、旧い版の行が書き換えられていない。
旧い版の行を残す方式で、旧い版の読み出しが一箇所の変換を通って現在の構造になっている。
読み出しの変換より内側の処理が、版の分岐を持たない。
保持対象の各版について、契約に基づく変換結果が実行検査で照合されている。
変換の存続根拠または撤去の判定が、対象とする保存先、分離保管、回復入力を含んでいる。

### 禁止事項
保存形式の移行や変換で、事実の値を丸め、切り捨て、欠落させること。
情報を失う変換を、意味を保った移行として扱うこと。
保存されていない事実や値を、移行や変換で創作し、既定値で過去の事実として埋めること。
活動の時刻を、移行の実行時刻や既定値へ置き換えること。
キーが指す同一性と参照の対応を、移行で変えること。
移行の前後の照合なしに、保存済みの事実の行を書き換えること。
契約が元の保存形そのものの保持を求める行を、書き換える移行の対象にすること。
事実の内容の訂正や取り消しを、移行で行うこと。
移行のために、業務の書き込み経路へ事実の行の更新権限を与えること。
旧い版の行を残す方式で、版を判別できない行へ互換の保てない構造の変更を加えること。
版の分岐を、読み出しの変換より内側へ持ち込むこと。
旧版の入力の残存を確かめずに、一括の書き換えや台帳のリセットを理由として、読み出し変換を撤去すること。

### 行動
保存形式を変える前に、変更が同じ意味と値の表し方を変えるものか、事実の値や意味を変えるものかを区別し、後者は移行でなく事実の追記で表す。
契約が元の保存形そのものの保持を求めるか、移行の前後を照合できるか、新しい形の全ての値が旧い形の記録から定まるかを確かめ、書き換える移行か旧い版の行を残す読み出し変換かを選び、根拠を決定の記録に残す。
書き換える移行は、照合の基準を移行の前に定め、移行だけの経路で書き換え、移行の後に同じ基準で全ての事実を照合する。
旧い形に記録がない値は、不明として表す。
旧い版の行を残す方式は、読み出しの変換に旧い版から現在の構造への変換を足す。
内側に散った版の分岐を見つけたら、読み出しの変換の一箇所へ集める。
読み出し変換を撤去するときは、保持・監査・回復の契約と対象入力の残存を照合し、必要な版の解釈を残す。

### 例
支払いの金額を小数の列から最小単位の整数の列へ移す。
この例の金額は `NUMERIC(12,2)` で表し、100倍して最小単位の整数へ移す。
旧い列の型だけを変えると、小数部が丸められて値が失われる。

```sql
ALTER TABLE payments ALTER COLUMN amount TYPE INTEGER;
```

移行だけの経路が、最小単位の整数の列を加え、換算した値を移し、活動の時刻には触れない。
換算が小数部を失わないことを全ての行で照合し、不一致の件数が 0 になってから旧い列を落とす。

```sql
ALTER TABLE payments ADD COLUMN amount_minor_unit BIGINT;
UPDATE payments SET amount_minor_unit = amount * 100;
SELECT COUNT(*) FROM payments
 WHERE amount_minor_unit IS NULL
    OR CAST(amount_minor_unit AS NUMERIC) / 100 <> amount;
```

受注に税率を加えるとき、過去の受注の税率を現在の税率で埋めると、記録のない事実を作る。
旧い版の行は税率なしのまま残し、読み出しの変換が税率を不明として現在の構造へ渡す。
