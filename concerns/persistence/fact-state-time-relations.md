## 事実・状態・時間を別の関係に落とす

### 要求
データは [data](../../principles/data/fact-state-time.md) の分類に従い、種類ごとに別の関係へ落とす。
リソースはキーの列を主キーとする関係に置き、追加を行の挿入で表し、人を表すリソースの属性はキーの行と別の関係に置く。
業務事実は活動ごとの関係に置き、[data](../../principles/data/fact-state-time.md) が一つに限る活動の時刻を一つの列に置く。
一回だけ起きる業務事実と、取り消せない期間の終わりの業務事実は、対象のキーの行や期間の始まりの行のキーを主キーにして参照し、一回だけであることを主キーで守る。
繰り返し起きる業務事実は、活動ごとの代理キーを主キーにする。
取り消した後に再び起こせる業務事実(取り消せる終わりの業務事実や、取り消せる解約の申し入れなど)は、繰り返し起きる業務事実として代理キーを主キーにし、取り消されていないものが一つまでであることを、書き込み経路が集約の鍵の下で確かめて守る。
一つの期間を閉じる終わり方が複数ある場合は、一つの終わりの関係に置いて、終わり方を定義を参照する列で表し、取り消せない終わりでは始まりの行のキーを主キーにして終わりが一度だけであることを主キーで守る。
終わり方ごとに異なる値は、終わりの行を主キーで参照する別の関係に置く。
繰り返す期間の各回は、互いを参照しない始まりの行として置く。
削除を業務事実として残すリソースと関係は、キーの行を残し、削除をその行を参照する業務事実の関係に置く。
可変属性は、値が一つに決まる範囲の行のキーに付けて置く。
期間ごとに分かれず、リソースに常に一つだけある値は、変わる値であっても、期間の関係でなくリソースのキーを主キーとする関係(リソースの関係自身を含む)に置き、関係の分け方は [normalization](./normalization.md) の「正規化して一つの事実を一箇所に置く」に従う。
ただし、人を表すリソースと削除を業務事実で表すリソースでは、キーの行を書き換えないので、変わる値をキーの行と別の関係に置く。
期間ごとに異なる値と期間の中でだけ成り立つ値は、その期間の始まりの行のキーを参照する関係に置く。
業務事実に伴う値のうち消去の義務を負うものは、業務事実の行を主キーで参照する別の関係に置く。
現在関係は、行の挿入と削除で表す。
期間の中でだけ成り立つ現在関係は、外側の期間を終わりの業務事実で閉じる確定でその行を削除する。
予定の終わりで閉じうる期間の中の現在関係は、行の有無と外側の期間が開いていることを合わせて判定し、閉じた後に残った行を削除の経路で消す。
定義は移行だけが変更する関係に置き、業務の書き込み経路に変更の権限を与えない。
業務の区分を表す定義は、区分の意味の正本と定義の識別子との対応を一か所で定め、移行と保存の変換がその対応を使う。
業務事実が参照する定義の行は、参照する行がある間は削除せず、廃止する定義では廃止を定義の行の列で表す。
参照のために保持する定義と、新しい業務の選択に使う定義を別の集合として扱う。
定義の変更は、その定義を検証で読む書き込み経路を先に止めてから、移行で行う。
状態を表す列や関係を置かず、今の状態は [period-state-views](./period-state-views.md) の「期間の判定を一か所のビューに定義する」に従って導く。
停止、退会、消去、復帰、再参加の遷移ごとに、始まりの行、終わりの業務事実、繰り返し起きるか、取り消せるかを定義し、一つの削除操作へまとめない。
繰り返す期間の重なりを拒むことは、書き込み経路が集約の鍵の下で、新しい回と重なる開いた回がないことを確かめて守り、決定の記録に列挙する。
予定の始まりを持たない期間では、これは開いた回を一つまでに限ることに当たり、予定の始まりと終わりを持つ期間では、時刻の範囲が重ならないことに当たる。
予定の始まりを持つ期間で同時に成り立つ回の数を限る不変条件は、開いた回の数でなく、どの時点でも範囲が重なる回の数で数える。

### 根拠
分類の理由は [data](../../principles/data/fact-state-time.md) に、今の状態を記録しない理由は [data](../../principles/data/derive-state-from-facts.md) に従う。
人を表すリソースの関係にキー以外を置かなければ、個人データを消すためにキーの行を書き換えずに済み、キーを参照する他の行が残る。
一つの期間の終わり方ごとに別の関係を置くと、同じ回に二つの終わりがあることを主キーで拒めない。
定義の変更をそれを読む書き込みと同時に行うと、検証が読んだ定義と確定時の定義が食い違う。
区分の意味と保存する識別子の一覧を別々に保守すると、区分を追加しても対応する定義の行がなく、型の判断と保存の制約が食い違う。
終わりの業務事実が始まりの行を主キーで参照すれば、どの回が閉じたかが行ごとに定まり、二度目の終わりを主キーが拒む。
参加と脱退を対象の組だけで記録すると、一回目の脱退が二回目の参加の判定を狂わせる。
繰り返す期間の回どうしを参照させて重なりを制約で拒むと、始まりと終わりの関係が互いを参照する循環になり、最初の回のための空にできる列と、古い回を消すための参照の書き換えが要る。
範囲の値と重なりを拒む制約で守る形は、解除や脱退のたびに始まりの行の範囲を更新する。
どちらの形も [data](../../principles/data/precedence.md) の順位で上位の原則を退けるので、重なりは書き込み経路で守る。
範囲を書き換えない期間でも、終わりの業務事実は別の関係にあるので、範囲の制約は早く閉じた回との重なりまで拒み、開いた回との重なりだけを拒む条件を表せない。
期間ごとの値を始まりの行のキーに付ければ、閉じた期間の値は判定から外れ、次の回の値と混ざらない。
業務事実に伴う消去対象の値を別の関係に置けば、業務事実を書き換えずに値だけを消せる。
定義の行を削除して廃止すると参照する業務事実の参照先が失われ、参照を付け替えると事実の行を書き換える。
退会、停止、消去は、今の状態への作用、復帰できるか、個人データを消す義務の有無が違う。
一つの削除操作や一回限りの出来事にまとめると、ある遷移の都合が別の遷移の保持と消去を決めてしまう。

### 完了条件
キーの不変、人を表すリソースのキーの行、業務事実の時刻の数の判定は、[data](../../principles/data/fact-state-time.md) の完了条件に従う。
リソースの関係がキーの列を主キーにし、人を表すリソースの属性がキーの行と別の関係にある。
一回だけ起きる業務事実と、取り消せない期間の終わりの業務事実の関係の主キーが、参照するキーの列である。
繰り返し起きる業務事実の関係が、活動ごとの代理キーを主キーに持ち、同じ対象への二回目以降の追記を受け入れる。
複数の終わり方を持つ期間の終わりが一つの関係にあり、取り消せない終わりではその主キーが始まりの行のキーである。
繰り返す期間の回どうしを参照する列がない。
状態を表す列や関係がない。
可変属性が、値が一つに決まる範囲の行のキーに付いている。
業務事実に伴う消去対象の値が、業務事実の行を主キーで参照する別の関係にある。
業務の書き込み経路が定義の関係を変更できず、業務事実が参照する定義の行が残っている。
現在の処理が扱う業務区分と定義の識別子が対応し、移行と保存の変換でその対応を独立して定義していない。
参照が残る廃止の定義が保持され、新しい業務の選択に使う集合には含まれていない。
定義の変更が、それを検証で読む書き込み経路を止めた後の移行で行われている。
停止、退会、消去、復帰、再参加の各遷移について、始まりの行、終わりの業務事実、繰り返し起きるか、取り消せるかが、project の決定の記録の遷移表に定められている。
繰り返す期間の重なりを守る書き込み経路の規則が、決定の記録に列挙されている。
期間の中でだけ成り立つ現在関係の行が、閉じた期間について今の結び付きとして読まれていない。

### 禁止事項
今の状態を表す列や関係を置く禁止は、[data](../../principles/data/derive-state-from-facts.md) の禁止事項に従う。
人を表すリソースのキーの行と業務事実の時刻の数についての禁止は、[data](../../principles/data/fact-state-time.md) の禁止事項に従う。
一つの期間の終わり方ごとに、始まりの行のキーを主キーとする別々の関係を置くこと。
繰り返し起きる業務事実の関係に、対象の識別子だけの主キーや一意制約を置き、二回目の追記を拒むこと。
繰り返す期間の回どうしを参照させること。
業務の書き込み経路に、定義を変更する権限を与えること。
業務区分と定義の識別子の対応を、移行と保存の変換で独立した一覧として保守すること。
業務事実が参照する定義の行を、削除して廃止すること。
遷移ごとの定めを持たない一つの削除操作で、停止、退会、消去を処理すること。
期間の中でだけ成り立つ現在関係の行を、外側の期間が閉じた後も、外側の期間を確かめずに今の結び付きとして読むこと。

### 行動
対象データを [data](../../principles/data/fact-state-time.md) の分類に照らして、リソース、業務事実、可変属性、現在関係、定義へ見分ける。
定義ごとに、業務区分の意味の正本、保存する識別子との対応、保持する廃止の定義、新しい業務で選べる定義を確かめる。
リソースの関係にはキーを置き、人を表すリソースの属性は別の関係へ移す。
業務事実ごとに活動の時刻の列を一つに絞り、一回だけ起きるものは参照するキーを、繰り返すものは代理キーを主キーにする。
期間ごとに始まりの行と終わりの業務事実の関係を定め、取り消せない終わりには始まりの行のキーを主キーとして持たせる。
状態の列や関係を見つけたら、その状態を導く始まりの行と終わりの業務事実へ置き換える。
遷移ごとに、始まりの行、終わりの業務事実、繰り返し起きるか、取り消せるかを遷移表へ書き出す。
繰り返す期間ごとに、重なりを確かめる書き込み経路と集約の鍵を決め、決定の記録に列挙する。
更新日時や削除フラグを足したくなったら、隠れた活動が契約の保持対象かを確かめ、対象なら業務事実へ切り出す。

### 例

削除フラグで退会を表すと、退会という活動も時刻も残らず、フラグを立てても氏名が消えない。

```sql
CREATE TABLE users (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  display_name VARCHAR(100) NOT NULL,
  is_deleted BOOLEAN NOT NULL
);
```

この例では、利用者は複数のメールアドレスを登録でき、退会は一度だけ起き、再登録には別の識別子を発行する。
停止は理由を伴って何度でも起き、解除で終わる。
退会と停止と解除の時刻の保持を契約が求め、登録の時刻は求めない。
利用者の関係はキーだけを持ち、登録はその行の挿入で表すので、登録の業務事実を置かない。
プロフィールとメールアドレスは利用者のキーを参照する可変属性であり、退会の書き込み経路が同じトランザクションで削除する。
退会は利用者のキーを、解除は停止のキーを主キーにして参照し、一回だけであることを主キーで守る。
有効な利用者の関係も停止中の列も置かず、有効かと停止中かは期間の判定で導く。
停止の理由は定義であり、廃止した理由も参照する停止がある間は行を残す。
時刻の列は、行を書く文の時点以後の時刻を返す datastore の既定値で付け、その関数は languages が定めるので、例では既定値を省く。
退会は登録の期間の終わりの業務事実なので、利用者のキーの行の削除から連鎖して消える。

```sql
CREATE TABLE users (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
);
CREATE TABLE user_profiles (
  user_id BIGINT PRIMARY KEY REFERENCES users (id),
  display_name VARCHAR(100) NOT NULL
);
CREATE TABLE user_emails (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users (id),
  email VARCHAR(254) NOT NULL UNIQUE
);
CREATE TABLE user_withdrawals (
  user_id BIGINT PRIMARY KEY REFERENCES users (id) ON DELETE CASCADE,
  occurred_at TIMESTAMP WITH TIME ZONE NOT NULL
);
CREATE TABLE suspension_reasons (
  id BIGINT PRIMARY KEY,
  name VARCHAR(50) NOT NULL UNIQUE,
  retired BOOLEAN NOT NULL
);
CREATE TABLE user_suspensions (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users (id),
  reason_id BIGINT NOT NULL REFERENCES suspension_reasons (id),
  occurred_at TIMESTAMP WITH TIME ZONE NOT NULL
);
CREATE TABLE user_reinstatements (
  suspension_id BIGINT PRIMARY KEY REFERENCES user_suspensions (id) ON DELETE CASCADE,
  occurred_at TIMESTAMP WITH TIME ZONE NOT NULL
);
```

参加と脱退を繰り返せる業務で、参加を対象の組で一意にすると、再参加を追記できない。

```sql
CREATE TABLE membership_joins (
  user_id BIGINT NOT NULL REFERENCES users (id),
  organization_id BIGINT NOT NULL REFERENCES organizations (id),
  joined_at TIMESTAMP WITH TIME ZONE NOT NULL,
  PRIMARY KEY (user_id, organization_id)
);
```

所属は利用者と組織の関係であり、その追加を所属の行で表し、再参加は新しい行になる。
所属の時刻を残す契約がないので、所属の行は時刻を持たない。
脱退は所属の行を主キーで参照し、一回だけ起きる。
組織は管理者が一人以上いるという件数の不変条件を持つので、所属は組織の集約が所有し、利用者の退会では暗黙に閉じない。
退会の前に組織の書き込み経路で脱退させ、退会の書き込み経路は開いた所属が残っていないことを確かめる。
同じ組織への開いた所属を一つまでに限ることは、組織の集約の鍵の下で書き込み経路が確かめる。

```sql
CREATE TABLE memberships (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users (id),
  organization_id BIGINT NOT NULL REFERENCES organizations (id)
);
CREATE TABLE membership_ends (
  membership_id BIGINT PRIMARY KEY REFERENCES memberships (id) ON DELETE CASCADE,
  occurred_at TIMESTAMP WITH TIME ZONE NOT NULL
);
```
