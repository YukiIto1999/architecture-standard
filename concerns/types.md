# types

## 概要
types は、型で全系の不変条件を守る規律である。
principles の [modeling](../principles/modeling.md) が定める、業務の意味の型封入・不正な状態の排除・境界での parse を、全系の型の扱いとして具象化する。
全系を貫く鎖は一つである。
境界で一度だけ外部の表現を型へ変換し、通った値だけが内側へ入り、内側は再検証せず型が保証する。

## 不正な状態を型で構築できなくする

### 要求
全系の状態を表す型に、[modeling](../principles/modeling.md) の不正な状態の排除を適用する。
状態の追加や変更の漏れが、型検査に現れる形に保つ。

### 根拠
表現できる状態が業務上ありうる状態より多いと、全系のどこかで不正な状態が生まれる。
各処理が同じ前提検査を書かされるのは、型が緩い兆候である。
状態を型で絞れば前提検査は不要になり、状態の追加は網羅の漏れとして型検査に現れる。

### 完了条件
全系の状態を表す型に、業務上ありえない値の組み合わせが構築できない。
状態固有のデータが、その状態の型にだけ存在し、他の状態から見えない。
場合分けが網羅され、状態の追加で漏れが型検査に出る。

### 禁止事項
型検査が及ばない場所へ、網羅の判定を既定の分岐や例外で逃がすこと。

### 行動
状態を表す型ごとに、表現可能な状態数と業務上 valid な状態数を比べる。
余剰があれば判別子つきの直和へ組み替え、状態固有のデータを各ケースへ移す。
分岐は網羅で書き、既定の枝で未知の状態を受けない。

### 例
```
// 4 状態が表現可能だが valid は 2。全処理が前提検査を書く
type Target = { email?: Address; toAll?: boolean }

// valid な状態だけ構築できる。受け手は 2 ケースだけ処理する
type Target = { kind: "all" } | { kind: "specific"; email: Address }
```

## 境界で一度だけ parse する

### 要求
外部から入る値の検証は、[modeling](../principles/modeling.md) の境界で検証して型に通すに従う。
どの経路の入力も一つの変換器の集合を通して検証済みの型へ変換し、内側では再検証しない。

### 根拠
外部入力は HTTP・CLI・メッセージ・外部 API など複数の経路から入り、経路ごとに別々の検証基準を持つと、通った値の信頼度が経路によって揺れる。
経路を横断して一つの変換器の集合に検証を集約すれば、全系を貫く鎖が一つに保たれる。
境界で検証相と実行相を分ける理由は [modeling](../principles/modeling.md) に従う。
自システムが検証して保存したデータの読出しも同じ変換器を通すが、その不正は外部入力の不正でなく欠陥である。
判別は [effect](./effect.md) に従う。
形式の検証は境界で行い、資源の照会を要する検証は方針の側で行う。
検証の証明責任は、必要な範囲で最も上流の境界に置く。
利用者の入力補助のための検証は契約の検証と目的が異なり、前者があっても後者を省かない。

### 完了条件
HTTP・CLI・メッセージ・外部 API のどの経路も、同じ変換器の集合を通って検証済みの型になっている。
内側の処理が、未検証の生の値や DTO を受け取らない。
証明責任が、必要な範囲で最も上流の境界に置かれている。
資源の照会を要する検証が、境界の変換器でなく方針の側で行われている。

### 禁止事項
境界の検証を迂回して、外部の値を内部の型として構築すること。
入力補助の検証があることを理由に、契約の境界の検証を省くこと。

### 行動
外部との接点を境界として特定し、そこに変換器を一つ置く。
未検証の型と検証済みの型を分け、検証済みの型は変換器を通してしか構築できないようにする。
経路が増えたら、既存の変換器の集合へ、その経路を検証済みの型に変換する処理を加える。

### 例
```
// 境界の変換器を通った型だけが内側へ入る
parseUser(input: unknown): ValidUser | Error   // 境界で一度だけ
sendWelcome(user: ValidUser)                    // 内側は再検証しない。型が証明する
```

## 境界の直後で単一の正準形へ収束させる

### 要求
複数の処理系や表現形式を扱う経路は、境界の直後で単一の正準形へ変換する。
複数の形式が並走する区間は、最短にする。
正準形以外の表現を、内側へ露出しない。

### 根拠
異種の外部処理系や表現形式が避けられない経路では、境界で一度検証しても、どの形式へ揃えるかを決めなければ、複数の形式が内側にまで並んで残る。
複数の形式が内側まで並走すると、同じ意味の値が経路ごとに違う型・違う変換規則で扱われ、コンテキスト間で写像が割れる。
境界の直後に収束点を置き、そこで単一の正準形へ変換すれば、内側の処理は一種類の表現だけを相手にでき、経路の違いを覚えずに済む。
境界で一度だけ parse する規律は、どこで検証するかという空間の規律であり、この収束は、いつまでに一つの形へ揃えるかという時間の規律である。
二つは対で働く。

### 完了条件
内側の処理が受け取る表現が、正準形の一種類である。
複数の形式が並走する区間が、境界のモジュールに閉じている。
正準形以外の表現が、内側のどこにも現れない。

### 禁止事項
複数の表現形式を、内側の処理まで並走させること。
正準形への変換を、境界から離れた場所まで遅らせること。
正準形以外の表現を、内側の関数の引数や戻り値に使うこと。

### 行動
経路ごとに異なる処理系・表現形式を洗い出し、単一の正準形を決める。
境界の直後に収束点を置き、そこで全ての経路の値を正準形へ変換する。
内側の関数の入出力を、正準形だけに絞る。

### 例
```
// 避けたい形: 複数形式が内側まで並走する
handle(request: FormatA | FormatB | FormatC): Result   // 内側の全処理が3形式を意識する

// 望ましい形: 境界の直後で正準形へ収束させる
toCanonical(request: FormatA | FormatB | FormatC): Canonical   // 境界の直後、一度だけ
handle(value: Canonical): Result                                // 内側は正準形しか知らない
```

## 意味と単位を型で区別する

### 要求
意味や単位の異なる値は、別の型として区別し、同じ構造でも意味が違えば互いに代入できないようにする。

### 根拠
意味ごとに別の型にすれば、取り違えが型検査で弾かれ、その型を受け取る全処理に区別が行き渡る。
ただし意味が同じものへ別名を与えるだけでは型安全にならず、型は必要な分だけ精密にする。

### 完了条件
識別子・金額・数量・期間・単位付きの値が、意味ごとに別の型で区別されている。
同じ構造でも意味の異なる値が、互いに代入できない。

### 禁止事項
意味や単位の異なる値を、同じ汎用の型として交換可能にすること。
意味が同じものへ別名を与えるだけで、精密にしたと見なすこと。

### 行動
値が意味・単位・制約を持つか、取り違え可能かを確認する。
持つなら意味ごとに別の型へ区別する。
値の構築と不変条件の検証は、[modeling](../principles/modeling.md) が定める値オブジェクトに従う。

### 例
```
// 同じ数でも意味が違えば別の型にし、取り違えを型で弾く
Meters と Seconds を別の型として定義する
march(distance: Meters)   // Seconds を渡すと型検査が拒む
```

## 型安全の穴を開けない

### 要求
型検査を無効化する型消去・任意型・無検査のキャストは、境界の最上位の報告に限り、内側へ穴を開けない。
外部入力は、操作の前に絞り込みを強制する型で受ける。

### 根拠
内側で型検査を切ると、その点から先へ型が情報を伝播できなくなる。
検証済みの型を無検査のキャストで構築できると、境界で parse する規律が崩れる。
外部入力を、操作前に絞り込みを強制する型で受ければ、検証を省けない。

### 完了条件
外部入力が、無条件には操作できない型で受けられ、絞り込みを経て使われている。
検証済みの型への無検査のキャストが、変換器の内側にだけ存在する。
型消去や任意型が、外界への報告など最上位の境界に限られている。

### 禁止事項
任意型で、型検査を黙らせること。
変換器の外で、検証済みの型へ無検査のキャストをすること。
型消去や任意型で、内側へ型の穴を開けること。

### 行動
外部入力を、操作前に絞り込みを強制する型で受ける。
検証済みの型の構築点を変換器へ集約し、その外のキャストを lint で検出する。

### 例
```
// 外部入力は操作前に絞り込みを強制する型で受け、キャストは変換器の中だけに置く
function parseUser(input: unknown): ValidUser | Error { /* ここだけが検証済み型を構築する */ }
```
