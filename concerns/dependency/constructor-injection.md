## 依存は構成子で受け取る

### 要求
依存は構成子の引数で受け取る。
効果の記述が要求を型に宣言する計算は、環境の提供を組立点で行う。
構成子注入は、効果を持たない構成要素の配線に用いる。
動的に選ぶ依存は、注入したファクトリで生成する。

### 根拠
構成子で必須の依存を受け取れば、依存が欠けた状態を作れない。
依存をその場で探す解決は、依存をシグネチャから隠し、コンパイル時の誤りを実行時の誤りに変える。
構成子で受ければ、依存はシグネチャに現れ、欠けた配線がコンパイル時に分かる。
効果の記述は要求する依存を型そのものに宣言するので、構成子注入と同じ役割を型のシグネチャで果たし、両者は競合せず対象で住み分ける。
動的な生成は、目的の型だけを要求できる注入したファクトリで行う。
構成子で受ける主目的は生成方法の隠蔽であり、テストのしやすさはその帰結である。
生成の過程が複雑な依存ほど、注入は生成の知識を利用側から消す価値を持つ。
単一インスタンスの静的な取得口も、その場で探す解決の一形態である。

### 完了条件
必須の依存が、構成子の引数または効果の型の要求として宣言され、組立点で配線されている。
依存が、シグネチャに現れている。
動的な生成が、注入したファクトリで行われている。
依存の受け渡しの方式が、依存グラフの全体で一貫している。

### 禁止事項
依存を、その場で探す解決(service locator)で取得すること。
依存を、暗黙のグローバルや ambient な機構で解決すること。
任意の型を要求できる仕組みで、動的生成を行うこと。

### 行動
依存を構成子の引数に移し、シグネチャに現す。
その場で探す解決やグローバルを、構成子注入と組立点での配線に置き換える。
動的生成は、目的の型に絞った注入ファクトリにする。

### 例

依存はシグネチャに現す。

```
class PricingPolicy { constructor(private rates: RateRepository) {} }
```

実行箇所で依存を探索したり、グローバルな状態から取得したりしない。
