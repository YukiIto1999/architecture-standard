## 供給網を保証する

### 要求
release する成果物は、署名・SBOM・SLSA provenance を備える。
版は semver で付け、一意かつ不変とする。
署名のない成果物を、release しない。
依存する部品の版は、lock ファイルで固定してリポジトリへ commit し、build と検査の入力を再現可能にする。
依存する部品の既知の脆弱性を SBOM から検査し、見つかったら release を止める。
生成と検査の機構の採用は、[tools](../../tools/README.md) が定める。

### 根拠
成果物の出所と組成を証明できないと、改竄や混入を配布の後から検出できない。
署名と provenance は、成果物が定めた過程から生まれたことを証明する。
SBOM は、成果物を構成する部品を明かし、既知の脆弱性との照合を可能にする。
同じ版の中身が変わると、検証した成果物と配布された成果物の対応が崩れる。
一意で不変な版は、検証と配布の対応を固定する。

### 完了条件
依存の版が、commit された lock ファイルで固定されている。
release された成果物が、署名・SBOM・SLSA provenance を備えている。
版が semver で付けられ、一意で不変である。
依存する部品の既知の脆弱性が、SBOM から検査されている。
脆弱性が見つかった release が、止まっている。

### 禁止事項
署名のない成果物を、release すること。
release した版を、付け直すこと。
既知の脆弱性の検査を経ずに、release すること。

### 行動
release の経路に、SBOM の生成・provenance の生成・署名を組み込む。
依存する部品の既知の脆弱性を SBOM から検査し、見つかったら release を止め、部品を直してから改めて release する。
