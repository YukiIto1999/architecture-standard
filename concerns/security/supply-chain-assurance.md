## 供給網を保証する

### 要求
release する成果物は、署名・SBOM・SLSA provenance を備える。
release は、成果物を、build した所有者以外の利用者、または build した計算機の外の配備先へ渡すことを指す。
所有者は成果物を build し実行する責任を負う一人の人または一つの組織を、計算機は build を実行した一台の計算機とその上で動く VM や WSL などの guest を指す。
build した所有者だけが、build した計算機の上で成果物を実行する利用は release に含めず、release しない利用と呼ぶ。
成果物を公開または配布するかの選択は [structure/deploy](../../structure/deploy/layout.md) が定める。
版は semver で付け、一意かつ不変とする。
署名のない成果物を、release しない。
依存する部品の版は、lock ファイルで固定してリポジトリへ commit し、build と検査の入力を再現可能にする。
release しない利用も、build の経路で成果物の SBOM を生成して依存する部品の既知の脆弱性を検査し、脆弱性が見つかった成果物を実行環境へ入れない。
依存する部品の既知の脆弱性を SBOM から検査し、見つかったら release を止める。
生成と検査の機構の採用は、[tools](../../tools/README.md) が定める。

### 根拠
成果物の出所と組成を証明できないと、改竄や混入を配布の後から検出できない。
署名と provenance は、成果物が定めた過程から生まれたことを証明する。
SBOM は、成果物を構成する部品を明かし、既知の脆弱性との照合を可能にする。
同じ版の中身が変わると、検証した成果物と配布された成果物の対応が崩れる。
一意で不変な版は、検証と配布の対応を固定する。
署名と provenance は、build した計算機の外や所有者以外の利用者へ成果物が渡る経路での改竄を検出するためのものであり、release しない利用には、その経路がない。
依存の部品の脆弱性は、成果物を渡すかどうかに関わらず実行環境へ入るため、release しない利用でも検査する。

### 完了条件
依存の版が、commit された lock ファイルで固定されている。
release された成果物が、署名・SBOM・SLSA provenance を備えている。
版が semver で付けられ、一意で不変である。
依存する部品の既知の脆弱性が、SBOM から検査されている。
脆弱性が見つかった release が、止まっている。
release しない利用で、成果物が build した所有者以外の利用者へ渡らず、build した計算機の外へ出ておらず、SBOM から既知の脆弱性の検査を経た成果物だけが実行環境へ入っている。

### 禁止事項
署名のない成果物を、release すること。
release した版を、付け直すこと。
既知の脆弱性の検査を経ずに、release すること。
build した所有者以外の利用者や、build した計算機の外の配備先へ渡す成果物を、release しない利用として署名と provenance なしに渡すこと。

### 行動
release の経路に、SBOM の生成・provenance の生成・署名を組み込む。
依存する部品の既知の脆弱性を SBOM から検査し、見つかったら release を止め、部品を直してから改めて release する。
release しない利用でも、build の経路で SBOM を生成して既知の脆弱性を検査し、脆弱性が見つかった成果物を実行環境へ入れない。
