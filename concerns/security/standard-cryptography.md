## 標準の暗号に任せる

### 要求
暗号と鍵の扱いは検証された標準のアルゴリズムと実装に任せ、自前で実装しない。
プロセスをまたぐ伝送は、暗号化された経路を前提にする。
secret の伝送も、この暗号化された経路の要求に含まれる。

### 根拠
暗号の自前実装は、わずかな誤りで安全を失う。
検証された標準の実装は、広く検査され攻撃に耐えている。
プロセス間の伝送を暗号化すれば、経路上の盗聴と改竄を防ぐ。

### 完了条件
暗号と鍵の扱いが、検証された標準のアルゴリズムと実装で行われている。
プロセスをまたぐ伝送が、暗号化された経路で行われている。

### 禁止事項
暗号のアルゴリズムやプロトコルを、自前で実装すること。
標準のライブラリに任せきりにして、方式・鍵長・乱数源・伝送の版を確かめないこと。

### 行動
暗号は標準のライブラリに任せ、鍵の管理は専用の仕組みへ委ねる。
鍵をデータと分けて保管し、鍵の更新の手順を必要になる前に用意する。
プロセスをまたぐ伝送を、暗号化された経路にする。

### 例

独自の暗号処理やハッシュ処理を実装しない。

```
const hash = myXor(password, key)
```

検証された標準の実装に委ねる。

```
const hash = argon2id(password)
```
