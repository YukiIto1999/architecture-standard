## 多層で防御する

### 要求
安全は単一の対策に頼らず、複数の層で重ねて守る。
層は異なる種類の防御で重ね、同じ対策の重複や数の増やしすぎにしない。

### 根拠
単一の対策は、破られると無防備になる。
複数の層で重ねれば、一つが破られても別の層が被害を抑える。
同じ種類の対策を重ねても、同じ穴で同時に破られる。
重ねるほど機構が複雑になり、新たな穴を生む。

### 完了条件
project が重要と定めた資産が、複数の層で重ねて守られている。
一つの層が破られても、別の層で被害が抑えられる。

### 禁止事項
安全を単一の対策へ集約し、迂回で無防備になる形にすること。

### 行動
重要な資産を、境界の検証・認可・最小権限・暗号など複数の層で守る。
どれか一つに依存していないかを確かめる。

### 例

入口の検証だけに依存すると、その検証を抜けた後は無防備になる。

```
validateAtGateway()
```

入口の検証に加え、認可、最小権限、データ層の制約で防御を重ねる。

```
validateAtGateway(); authorize(); leastPrivilege(); dbConstraints()
```
