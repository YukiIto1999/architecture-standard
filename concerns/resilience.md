# resilience

## 概要
resilience は、障害への耐性を全系で統べる規律である。
principles の [data](../principles/data.md) が定める事実の追記と、[separation](../principles/separation.md) が定める副作用の境界隔離を、全系の障害耐性として具象化する。
冪等・再試行・行き止まりの正本は resilience であり、[transaction](./transaction.md) は書き込みパスへの適用を、[messaging](./messaging.md) はイベント消費への適用を書く。

## 信頼性を観測可能な目標として定める

### 要求
信頼性を、観測できる指標と目標として定め、対策の追加や除去をその目標で判断する。
目標の具体的な値は、project が定める。

### 根拠
目標が無いと、どこまで信頼できればよいかが定まらず、対策の過不足を判断できない。
信頼性を観測できる指標と目標にすれば、対策が目標を満たすか、過剰かを測れる。
目標の値は系ごとに違うので、標準は目標を持つことを定め、値は project に委ねる。

### 完了条件
信頼性が、観測できる指標と目標として定められている。
対策の追加や除去が、その目標で判断されている。

### 禁止事項
信頼性の目標を持たずに、対策の過不足を勘で決めること。

### 行動
信頼性を観測できる指標にし、目標を定める。
目標の値は project が定める。
対策の追加や除去を、目標を満たすかで判断する。
観測は [observability](./observability.md) に従う。

## 再実行のある操作を冪等にする

### 要求
再実行のある操作は冪等の鍵を持ち、同じ意図の再実行が重複した結果を生まないようにする。
冪等の鍵は呼び出し側で生成し、再試行をまたいで同じにする。
適用済みの記録は有限の寿命を持たせ、再送が届きうる最長の間隔より長く取って刈り取る。

### 根拠
障害の後の回復は、再実行と再配送に頼るため、同じ操作が複数回届く。
冪等なら、再実行しても結果は一度の実行と同じになる。
冪等の鍵で重複を検出すれば、再実行を安全に行える。
適用済みの記録は重複の検出のためだけに持つので、無期限に積むと保管を圧迫する。
寿命を再送の届く最長の間隔より長く取れば、保管を有界に保ちつつ重複を検出できる。

### 完了条件
再実行のある操作が、冪等の鍵を持つ。
冪等の鍵が呼び出し側で生成され、再試行をまたいで同じである。
同じ意図の再実行が、重複した結果を生まない。
適用済みの記録に有限の寿命があり、再送の届く最長の間隔より長く、寿命を過ぎた記録が刈り取られている。

### 禁止事項
再実行のある操作を、冪等にせずに公開すること。
適用済みの記録を、寿命を定めず無期限に保持すること。

### 行動
操作に冪等の鍵を付け、適用済みを記録して重複を排除する。
適用済みの記録に寿命を持たせ、再送の届く間隔より長く取り、定期に刈り取る。
寿命の値は project が定める。

## 外部依存の呼び出しを制御する層に置く

### 要求
外部依存への呼び出しは port を包む層で制御し、時間の上限・再試行・遮断をその層に置く。
これらを業務の処理へ持ち込まない。
port 層の時間上限は、文脈で伝わる絶対期限と合成し、短い方を採る。
期限の意味は [concurrency](./concurrency.md)、carrier の伝播は [context-propagation](./context-propagation.md) に従う。
一つの呼び出しの再試行は、port を包む層のうち一箇所だけが担い、それより上流の層は同じ呼び出しを重ねて再試行しない。

### 根拠
時間の上限・再試行・遮断を業務の処理に埋めると、業務判断と障害制御が混ざる。
port を包む層に集めれば、業務は判断に専念し、障害制御を独立に調整できる。
時間の上限のない呼び出しは、依存の停止で自分も止まる。
port 層だけの上限を文脈の期限と独立に持つと、上流が諦めた後も port 層が待ち続ける。
短い方を採れば、上流の期限を越えて待たない。
呼び出しは複数の層を通ることがあり、層ごとに同じ呼び出しを再試行すると、試行の回数が層の数だけ掛け算で膨らむ。
下流が既に諦めた呼び出しを上流がなお再試行すると、下流が最も弱っている時に負荷が積み増される。
再試行を一箇所に決めれば、その呼び出しの総試行回数を見積もれる。

### 完了条件
外部依存への呼び出しが、port を包む層で制御されている。
呼び出しに、時間の上限がある。
再試行・遮断・時間の上限が、業務の処理に埋まっていない。
port 層の時間上限が、文脈で伝わる絶対期限と合成され、短い方が採られている。
同じ呼び出しの再試行が、port を包む層のうち一箇所に限られている。
その一箇所より上流の層が、同じ呼び出しを重ねて再試行していない。

### 禁止事項
再試行や遮断の制御を、業務の処理へ埋め込むこと。
時間の上限のない外部呼び出しを行うこと。
同じ呼び出しを、複数の層で重ねて再試行すること。

### 行動
port を包む層に、時間の上限・再試行・遮断を置く。
業務には、呼び出しの結果だけを返す。
呼び出しを再試行する層をひとつ決め、それ以外の層は再試行せず結果をそのまま伝える。

### 例

業務処理に時間上限と再試行を埋め込むと、判断と障害制御が混ざる。

```
function place(order) { for (i in 0..3) try { return api.call(order) } catch {} }
```

時間上限、再試行、遮断は port を包む層で制御し、業務には結果だけを返す。

```
class ResilientRateClient implements RateClient { ... }
```

## 失敗を区画に閉じる

### 要求
外部依存の失敗はその依存の失敗として閉じ、独立した他の処理単位をその失敗で止めない。
依存ごとに、呼び出しの資源を接続やスレッドの区画として分ける。

### 根拠
一つの依存の失敗が全体を止めると、局所の障害が全系へ広がる。
資源を区画に分け、失敗を区画に閉じれば、他の処理は動き続ける。

### 完了条件
外部依存の失敗が、その依存の失敗として閉じている。
独立した他の処理単位が、その失敗で止まっていない。
依存ごとに、呼び出しの資源が接続やスレッドの区画として分かれている。

### 禁止事項
一つの外部依存の失敗を、独立した処理単位の停止へ直結させること。

### 行動
処理の資源を区画に分け、一つの区画の枯渇を他へ広げない。
依存ごとに失敗を閉じ、独立した処理は動かし続ける。

## 障害を別経路で覆い隠さない

### 要求
依存の障害のとき、ふだん使わない専用の fallback 経路へ逃げず、主経路を信頼できるようにする。
代替が要るなら、ふだんから動く経路で用意する。

### 根拠
障害のときだけ動く専用の fallback は、ふだん動かないので検証されず、いざ使うと別の壊れ方をする。
fallback が主経路と別の依存を叩くと、部分的な障害が全体の障害へ広がる。
ふだんから動く経路で代替を用意すれば、その経路も常に検証される。

### 完了条件
障害のときだけ動く専用の fallback 経路が、主経路の代わりに置かれていない。
代替が、ふだんから動く経路で用意されている。

### 禁止事項
障害を、ふだん使わない専用の fallback 経路で覆い隠すこと。

### 行動
主経路の信頼性を上げることを第一にする。
代替が要る場合は、冗長な系への切り替えやデータの事前複製のように、ふだんから動く経路で用意する。

### 例

障害時だけ別の依存先を呼ぶ fallback は平常時に検証されず、障害時の集中によって依存先全体を倒す。

```
try { return cache.get(key) } catch { return database.get(key) }
```

代替手段は平常時から使う経路に組み込み、冗長化と事前複製によって主経路を堅くする。

```
return store.get(key)
```

## 過負荷を抑える

### 要求
再試行は回復の見込みがある一時的な失敗にのみ行い、上限と後退する間隔を設けて設定として外から与える。
後退する間隔には乱数を加え、複数の呼び出し側の再試行が同じ時刻に集中しないようにする。
回復していない依存への呼び出しは、遮断で抑える。

### 根拠
回復しない失敗への再試行は、負荷を増やすだけで成功しない。
上限と後退する間隔を設ければ、再試行が依存を圧迫しない。
後退する間隔だけを揃えると、複数の呼び出し側の再試行が同じ時刻に重なり、回復の直後に殺到が再現する。
間隔に乱数を加えれば、再試行の時刻が散り、同期した集中を防げる。
回復していない依存を遮断すれば、無駄な呼び出しと待ちを避けられる。

### 完了条件
再試行が、回復の見込みのある一時的な失敗にのみ行われている。
再試行に上限と間隔があり、設定として外から与えられている。
後退する間隔に乱数を加え、再試行の同期した集中を避けている。
回復していない依存への呼び出しが、遮断で抑えられている。

### 禁止事項
上限のない再試行で、過負荷を広げること。
回復しない失敗を、再試行で繰り返すこと。
後退する間隔に乱数を加えず、再試行を同じ時刻に集中させること。

### 行動
失敗が一時的か恒久的かを見分け、一時的なものだけを上限つき・後退する間隔つきで再試行する。
後退する間隔に乱数を加え、再試行が同じ時刻に集中しないようにする。
回復していない依存は遮断し、回復を確かめてから戻す。

### 例

上限も間隔もない再試行は、回復しない依存先を圧迫する。

```
while (true) try { return call() } catch {}
```

乱数を含まない後退では、複数の呼び出しが同じ時刻に揃い、回復直後に殺到する。

```
retry({ max: config.maxRetries, backoff: exponential }, call)
```

一時的な失敗だけを、回数の上限、後退する間隔、乱数を設定して再試行する。

```
retry({ max: config.maxRetries, backoff: exponentialWithJitter }, call)
```

## 流入を制限する

### 要求
外部へ公開する面と共有する資源には流入の上限を設け、内部のキューの滞留にも上限を設ける。
内部のキューが上限へ達したときは、新しい流入を明示的に拒否し、滞留量と拒否を観測する。
期限切れの仕事を捨ててよいのは、未着手で取り消せ、結果の省略が安全な read または新しい仕事に置き換えられた仕事に限る。
受領済みの write、外部効果、全件が必要な入力は、期限切れを理由に捨てない。
期限切れになった受領済みの write、外部効果、全件が必要な入力は、冪等に完了するか durable queue へ戻して再配送する。

### 根拠
流入に上限がないと、急増で資源が枯渇し全体が倒れる。
上限を設ければ、負荷が上限に収まる。
満杯時の流入を拒否して観測すれば、保存できない仕事を受領済みと誤認せず、上限へ達する前後の運用介入を判断できる。
省略しても状態を変えない read や新しい仕事に置き換えられた未着手の仕事を実行すると、利用者へ返せない結果のために資源を使い、後続を遅らせる。
受領済みの write や外部効果を期限切れで捨てると、呼び出し側の認識と確定した状態が食い違う。
全件が必要な入力を期限切れで捨てると、後から再構成できない欠落が生じる。
区画は、「失敗を区画に閉じる」に従う。

### 完了条件
外部へ公開する面と共有する資源に、流入の上限がある。
内部のキューの滞留に、上限がある。
内部のキューが上限へ達したとき、新しい流入が明示的に拒否され、滞留量と拒否が観測されている。
未着手で取り消せ、結果の省略が安全な read または新しい仕事に置き換えられた期限切れの仕事が、実行されずに捨てられている。
期限切れになった受領済みの write、外部効果、全件が必要な入力が、冪等に完了するか durable queue から再配送されている。

### 禁止事項
流入の上限を設けず、急増で資源を枯渇させること。
上限へ達した内部のキューへ新しい仕事を受け入れること、または拒否を観測不能にすること。
未着手で取り消せ、結果の省略が安全な read または置換済みの期限切れの仕事を、実行すること。
受領済みの write、外部効果、全件が必要な入力を、期限切れを理由に捨てること。

### 行動
公開面と共有資源に流入の上限を設ける。
内部のキューに滞留の上限を設ける。
内部のキューが上限へ達したら新しい流入を拒否し、滞留量と拒否を監視する。
期限切れの仕事が未着手で取り消せ、read または置換済みで省略安全かを判定する。
省略安全なら実行せずに捨てる。
受領済みの write、外部効果、全件が必要な入力は、冪等に完了するか durable queue へ戻して再配送する。

## 再試行の出口を持つ

### 要求
上限まで失敗した仕事は取り除いて行き止まりへ送り、内容と失敗の理由と試行の回数を残す。
再試行しても成功しない失敗は上限を待たず直ちに行き止まりへ送り、送った仕事は原因を直した後に手順を経て再投入する。
行き止まりへの到達は監視の対象にし、再投入は冪等の再実行を前提にする。

### 根拠
出口のない再試行は、失敗した仕事が滞留して後続を止める。
行き止まりへ送って記録を残せば、後続を流しつつ原因を調査できる。
回復しない失敗を上限まで再試行するのは無駄なので、直ちに行き止まりへ送る。
原因を直す前に自動で再投入すると、同じ失敗を繰り返す。

### 完了条件
上限まで失敗した仕事が、行き止まりへ送られ、内容と理由と試行の回数が残っている。
回復しない失敗が、上限を待たず直ちに行き止まりへ送られている。
行き止まりへの到達が、監視の対象になっている。
再投入が、冪等にして再実行できることを前提にしている。

### 禁止事項
失敗した仕事を、記録を残さずに捨てること。
原因を直す前に、行き止まりの仕事を自動で再投入すること。

### 行動
再試行の上限を超えた仕事を行き止まりへ送り、内容と理由と試行回数を残す。
行き止まりへの到達を監視し、原因を直してから手順を経て再投入する。
