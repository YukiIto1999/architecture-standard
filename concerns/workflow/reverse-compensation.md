## 連鎖の失敗を、逆順の補償で打ち消す

### 要求
複数の集約にまたがる連鎖が途中の段で失敗したときは、既に完了した段の効果を、打ち消す事実の追記で戻す。
打ち消しは、完了した段を逆順に辿って行い、打ち消す操作自体も冪等にする。
打ち消しが完了しない段は、[resilience](../resilience/README.md) の行き止まりへ送り、人が原因を調べて手動で収める。

### 根拠
連鎖は複数の集約にまたがるため、一つのトランザクションでまとめて戻せない。
連鎖の途中を放置すると、完了した段の効果だけが残り、系が矛盾した状態のままになる。
効果を戻す手段が値の上書きでなく打ち消したという事実の追記に限られる理由は [data](../../principles/data/README.md) に従う。
後続の段は先行の段が残した結果に依存することがあるため、依存の向きと逆に辿ってはじめて、戻す順序と作った順序が食い違わない。
打ち消しの配送や実行も重複しうるので、冪等でなければ同じ効果を二重に打ち消してしまう。
打ち消しそのものが失敗する段は、通常の消費が失敗したときと同じ扱いであり、行き止まりへ送って人の判断に委ねる以外に、系を整合させる手段がない。

### 完了条件
連鎖の途中の失敗が、完了済みの段を打ち消す事実の追記で戻されている。
打ち消しが、完了した段の逆順に辿られている。
打ち消す操作が、冪等になっている。
打ち消しが完了しない段が、行き止まりへ送られ、手動の介入を経て収められている。

### 禁止事項
連鎖の失敗を、完了済みの段の記録を消して戻すこと。
打ち消しを、完了した段と無関係な順序で行うこと。
打ち消す操作を、冪等にせず重複を許すこと。

### 行動
連鎖を構成する各段に、その段を打ち消す操作を対にして用意する。
失敗を検知したら、完了済みの段を逆順に辿り、それぞれの打ち消す事実を追記する。
打ち消しが完了しない段は、resilience の行き止まりへ送る。

### 例

注文の確定、与信の確保、出荷の依頼と進んだ連鎖で出荷依頼に失敗した場合は、完了済みの段を逆順に打ち消す。

```
function compensate(saga) {
  if (saga.creditReserved) publish(CreditReleased.from(saga))
  if (saga.orderPlaced)    publish(OrderCancelled.from(saga))
}
```
