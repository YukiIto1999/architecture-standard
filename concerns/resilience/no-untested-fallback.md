## 障害を別経路で覆い隠さない

### 要求
依存の障害のとき、ふだん使わない専用の fallback 経路へ逃げず、主経路を信頼できるようにする。
代替が要るなら、ふだんから動く経路で用意する。

### 根拠
障害のときだけ動く専用の fallback は、ふだん動かないので検証されず、いざ使うと別の壊れ方をする。
fallback が主経路と別の依存を叩くと、部分的な障害が全体の障害へ広がる。
ふだんから動く経路で代替を用意すれば、その経路も常に検証される。

### 完了条件
障害のときだけ動く専用の fallback 経路が、主経路の代わりに置かれていない。
代替が、ふだんから動く経路で用意されている。

### 禁止事項
障害を、ふだん使わない専用の fallback 経路で覆い隠すこと。

### 行動
主経路の信頼性を上げることを第一にする。
代替が要る場合は、冗長な系への切り替えやデータの事前複製のように、ふだんから動く経路で用意する。

### 例

障害時だけ別の依存先を呼ぶ fallback は平常時に検証されず、障害時の集中によって依存先全体を倒す。

```
try { return cache.get(key) } catch { return database.get(key) }
```

代替手段は平常時から使う経路に組み込み、冗長化と事前複製によって主経路を堅くする。

```
return store.get(key)
```
