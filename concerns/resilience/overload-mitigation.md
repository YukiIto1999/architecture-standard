## 過負荷を抑える

### 要求
再試行は回復の見込みがある一時的な失敗にのみ行い、上限と後退する間隔を設けて設定として外から与える。
後退する間隔には乱数を加え、複数の呼び出し側の再試行が同じ時刻に集中しないようにする。
回復していない依存への呼び出しは、遮断で抑える。

### 根拠
回復しない失敗への再試行は、負荷を増やすだけで成功しない。
上限と後退する間隔を設ければ、再試行が依存を圧迫しない。
後退する間隔だけを揃えると、複数の呼び出し側の再試行が同じ時刻に重なり、回復の直後に殺到が再現する。
間隔に乱数を加えれば、再試行の時刻が散り、同期した集中を防げる。
回復していない依存を遮断すれば、無駄な呼び出しと待ちを避けられる。

### 完了条件
再試行が、回復の見込みのある一時的な失敗にのみ行われている。
再試行に上限と間隔があり、設定として外から与えられている。
後退する間隔に乱数を加え、再試行の同期した集中を避けている。
回復していない依存への呼び出しが、遮断で抑えられている。

### 禁止事項
上限のない再試行で、過負荷を広げること。
回復しない失敗を、再試行で繰り返すこと。
後退する間隔に乱数を加えず、再試行を同じ時刻に集中させること。

### 行動
失敗が一時的か恒久的かを見分け、一時的なものだけを上限つき・後退する間隔つきで再試行する。
後退する間隔に乱数を加え、再試行が同じ時刻に集中しないようにする。
回復していない依存は遮断し、回復を確かめてから戻す。

### 例

上限も間隔もない再試行は、回復しない依存先を圧迫する。

```
while (true) try { return call() } catch {}
```

乱数を含まない後退では、複数の呼び出しが同じ時刻に揃い、回復直後に殺到する。

```
retry({ max: config.maxRetries, backoff: exponential }, call)
```

一時的な失敗だけを、回数の上限、後退する間隔、乱数を設定して再試行する。

```
retry({ max: config.maxRetries, backoff: exponentialWithJitter }, call)
```
