## 外部依存の呼び出しを制御する層に置く

### 要求
外部依存への呼び出しは port を包む層で制御し、時間の上限・再試行・遮断をその層に置く。
これらを業務の処理へ持ち込まない。
port 層の時間上限は、文脈で伝わる絶対期限と合成し、短い方を採る。
期限の意味は [concurrency](../concurrency/README.md)、carrier の伝播は [context-propagation](../context-propagation/README.md) に従う。
一つの呼び出しの再試行は、port を包む層のうち一箇所だけが担い、それより上流の層は同じ呼び出しを重ねて再試行しない。

### 根拠
時間の上限・再試行・遮断を業務の処理に埋めると、業務判断と障害制御が混ざる。
port を包む層に集めれば、業務は判断に専念し、障害制御を独立に調整できる。
時間の上限のない呼び出しは、依存の停止で自分も止まる。
port 層だけの上限を文脈の期限と独立に持つと、上流が諦めた後も port 層が待ち続ける。
短い方を採れば、上流の期限を越えて待たない。
呼び出しは複数の層を通ることがあり、層ごとに同じ呼び出しを再試行すると、試行の回数が層の数だけ掛け算で膨らむ。
下流が既に諦めた呼び出しを上流がなお再試行すると、下流が最も弱っている時に負荷が積み増される。
再試行を一箇所に決めれば、その呼び出しの総試行回数を見積もれる。

### 完了条件
外部依存への呼び出しが、port を包む層で制御されている。
呼び出しに、時間の上限がある。
再試行・遮断・時間の上限が、業務の処理に埋まっていない。
port 層の時間上限が、文脈で伝わる絶対期限と合成され、短い方が採られている。
同じ呼び出しの再試行が、port を包む層のうち一箇所に限られている。
その一箇所より上流の層が、同じ呼び出しを重ねて再試行していない。

### 禁止事項
再試行や遮断の制御を、業務の処理へ埋め込むこと。
時間の上限のない外部呼び出しを行うこと。
同じ呼び出しを、複数の層で重ねて再試行すること。

### 行動
port を包む層に、時間の上限・再試行・遮断を置く。
業務には、呼び出しの結果だけを返す。
呼び出しを再試行する層をひとつ決め、それ以外の層は再試行せず結果をそのまま伝える。

### 例

業務処理に時間上限と再試行を埋め込むと、判断と障害制御が混ざる。

```
function place(order) { for (i in 0..3) try { return api.call(order) } catch {} }
```

時間上限、再試行、遮断は port を包む層で制御し、業務には結果だけを返す。

```
class ResilientRateClient implements RateClient { ... }
```
