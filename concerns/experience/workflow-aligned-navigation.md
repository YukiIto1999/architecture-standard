## 情報構造を作業の流れに沿わせ、現在地を示す

### 要求
利用者面の構成と並びを、利用者の作業の流れに沿わせる。
visual UI の一覧と詳細は、多数を検索して開くなら route を分け、短い設定を頻繁に行き来するなら並置で組む。
利用者が今どこにいるかを、常に示す。
異なる利用面（売り手と買い手、管理者と一般等）で同一概念の集合を扱う一覧画面は、命名の基準を対称に保ち、特定の画面だけに冗長な修飾句を付けない。
詳細画面から親の一覧へ戻る導線の文言は、遷移先の一覧画面の正式な見出しと一致させる。

### 根拠
作業の流れに沿った構成は、利用者が次にどこへ行くかを予測できる。
visual UI で多数を検索して開く場合は、一つずつ route で開くと戻る操作と共有がしやすい。
visual UI で短い設定を頻繁に行き来する場合は、一覧と詳細を並置すると移動が要らない。
現在地が見えないと、利用者は全体の中で自分の位置を見失う。
同じ業務の異なる面で命名基準が異なると、利用者は機能の範囲が別物であると誤解し、画面遷移時の現在地把握を誤る。

### 完了条件
利用者面の構成と並びが、作業の流れに沿っている。
visual UI の一覧と詳細が、用途に応じて route の分割か並置のどちらかで組まれている。
現在地が、常に利用者面に示されている。
異なる利用面の間で、同一概念の一覧探索画面の命名基準が対称になっている。
親一覧への戻りリンクの文言が、親画面の見出しと一致している。

### 禁止事項
作業の流れに反する順序で、利用者面を並べること。
現在地を、利用者から隠すこと。
同一概念の一覧探索画面に利用面ごとに異なる命名規則を適用したり、特定の画面だけに冗長な修飾句を付与すること。
親画面への戻りリンクに、親画面の見出しと異なる表現を用いること。

### 行動
利用者面の並びを作業の流れと照らし、合わない順序を直す。
visual UI では一覧と詳細の用途を見分け、route の分割か並置を選ぶ。
現在地を常に示す。
利用面をまたぐ一覧画面の命名を照合し、命名基準を対称に揃える。
詳細画面の戻りリンクを点検し、親一覧の見出しと一致させる。
