## 誤りを防ぎ、起きたら回復を助け、取り返せるようにする

### 要求
不正な値を入力させない形、選択、専用の入力、自由入力に関する要求、完了条件、禁止事項は対話入力に適用し、CLI の引数や stdin の不正な値の拒否は [types](../types/parse-once-at-boundary.md) の「境界で一度だけ parse する」に従う。
不正な値を入力させない形にする。
契約または保持しているデータから選択肢が確定している値は、固定の選択肢も、システムが既に保持している実体も、選択で受ける。
数と日付と真偽は専用の入力で受ける。
自由入力は、選択肢が確定しておらず、値を網羅して並べることが現実的でない値に限る。
例を挙げられるだけでは、選択肢が確定したとは見なさない。
誤りが起きたら、平易な言葉で何が問題かを示し、直し方を添える。
誤った操作は、取り消しと脱出で取り返せるようにする。

### 根拠
良いエラー文よりも、誤りが起きない構造の方が確実である。
入力を型と選択で縛ると、不正な場合がそもそも生じない。
それでも利用者は誤るので、起きた誤りには問題と直し方を示し、番号だけのエラーを出さない。
取り消しと脱出がないと、利用者は作業を失う。

### 完了条件
選択肢が確定している値が、選択で受けられている。
数と日付と真偽が、専用の入力で受けられている。
自由入力が、選択肢が確定しておらず網羅して並べることが現実的でない値に限られている。
エラーの表示が、平易な言葉で問題と直し方を示している。
誤った操作に、取り消しか脱出の経路がある。

### 禁止事項
選択肢が確定している値を、自由入力で受けること。
システムが既に保持している実体を、再入力させること。
不正な値を入力できる形にすること。
番号や内部の語だけで、エラーを示すこと。
取り返せない操作を、確認なく実行させること。

### 行動
入力ごとに、選択と数と日付と真偽と自由の別を確かめ、不正値を作れない入力にする。
エラーの表示を点検し、問題と直し方を平易な言葉で示す。
主要な操作に、取り消しと脱出を備える。

### 例

出力形式を自由入力で受けると、利用者が不正な値を入力できる。

```
outputFormat: 自由入力
```

選択肢が確定している値を選択肢で受ければ、不正な値を作れない。

```
outputFormat: 選択(CSV / JSON)
```

担当者を氏名の自由入力で受けると、保持している担当者と異なる氏名を入力できる。

```
assignee: 自由入力
```

保持している担当者を選択肢として選択で受ければ、不正な値を作れない。

```
assignee: 選択(保持している担当者の一覧)
```

個数を数える単位は、個、箱、袋、ダースのように語彙が開いており、網羅して並べることが現実的でない。
選択肢が確定していないので、自由入力で受けてよい。

```
quantityUnit: 自由入力
```
