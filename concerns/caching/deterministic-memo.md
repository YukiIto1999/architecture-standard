## 決定的な結果の再利用を依存の同一性で閉じる

### 要求
memo は、結果が入力と依存だけで決まり、外部への効果を伴わない計算の結果を、古い結果を許さずに再利用する。
再利用してよいのは、計算の同一性と、結果を決める全ての入力と依存が、保持した結果を作ったときと同一であると確定できる場合に限る。
計算の同一性は、実行する計算の定義である。
結果を決める入力と依存は、引数の値のほか、計算が読む設定、規則の定義、時刻、乱数、外部の照会の結果、可変な正本の値を含む。
計算の定義が保持の間に変わりうる場合は、定義の版を同一性に含める。
同一性の確定は、結果を決める全ての入力と依存を覆い、確定の機構は問わない。
実行基盤が追跡する依存も、結果を決める全ての入力と依存を覆う限り、同一性の確定に使える。
同一性を確定できない入力や依存がある計算は、確定できるまで再利用しない。
項目の妥当性は同一性の確定で決め、期限と無効化の操作に頼らない。
期限による失効は、保持の資源を回収するために使ってよく、同一性の確定の代わりにしない。
memo の保持量は、件数または大きさに上限を置き、保持を所有する対象の寿命を越えて残さない。
保持する値が一つの memo は、その一つを件数の上限として扱う。
保持の上限と、上限超過や所有者の終了時の回収を設計から説明できるようにする。
memo は正本にせず、項目の欠落は再計算で補う。

### 根拠
計算と入力と依存が、保持した結果を作ったときと同一な場合に限れば、結果も同一になり、時間が経っても、古い結果を許さずに妥当なままである。
そのため memo の妥当性は、期限と無効化でなく、同一性の確定が担う。
結果を決める入力や依存が再利用の判定から欠けると、その入力や依存だけが違う二つの要求が同じ結果を共有する。
期限は、誤った結果が残る時間を区切るだけで、誤りそのものを防がない。
同一性の確定は、結果を決める全ての入力と依存を覆えば妥当性を保証するので、機構の形でなく、覆う範囲を問う。
入力や依存が変わっても結果が変わらない場合はあり、memo が保証するのは、結果を決める入力や依存が変わった後に、古い結果を返さないことである。
計算の定義が保持の間に変わりうるのに同一性へ含めなければ、定義を変えた後も、旧い定義の結果が新しい定義の結果として返り続ける。
定義が保持の間固定されるなら、その固定が計算の同一性を確定する。
同一性を確定できない入力や依存があるまま期限を付けても、結果がどの値に依存するかは分からず、期限は古さの上限を与えるだけで妥当性を与えない。
古さを許す要件があり、依存する正本と許容する古さと無効化の対象が分かる再利用は、取得 cache として、それらを根拠に期限と無効化で閉じられる。
時間で古くならない結果でも、保持する量は入力と依存の種類の数だけ増えうるので、所有者の寿命だけでは保持量を制限できない。
保持する値が一つなら、その一つが件数の上限である。
期限による失効は、時間で古くならない結果の資源も回収できるが、依存の保証を置き換えない。
項目の欠落を再計算で補えるので、上限や所有者の終了時に回収しても計算の結果は変わらない。
外部への効果を伴う計算の結果を再利用すると、命中した呼び出しでは効果が起きない。
memo を正本にすれば、回収や再起動で結果が失われる。

### 完了条件
結果を決める全ての入力と依存が、再利用の判定に覆われている。
結果を決める入力または依存を変えた後の結果が、memo を介さずに独立に求めた期待値と一致している。
計算の定義が保持の間に変わりうる memo で、定義を変えた後の結果が、新しい定義で独立に求めた期待値と一致している。
同一性を確定できない入力や依存がある計算が、再利用されていない。
memo の保持量が件数または大きさの上限を超えず、所有者の終了後に残らず、上限と回収の規則を設計から説明できる。
memo の項目の欠落が再計算で補われ、memo が正本として扱われていない。
外部への効果を伴う計算が、memo の対象に含まれていない。

### 禁止事項
入力または依存の変化で結果が変わるのに、変わる前の結果を返すこと。
同一性を確定できない入力や依存がある計算の結果を、期限を付けて再利用すること。
計算の定義が保持の間に変わるのに、新しい定義での妥当性を確かめず以前の結果を返すこと。
期限による失効を、入力と依存の同一性の確定の代わりにすること。
memo の保持量に上限を置かず、所有者の終了時の回収だけで入力と依存の種類の数だけ増え続ける保持を正当化すること。
外部への効果を伴う計算の結果を memo にして、命中した呼び出しで効果を省くこと。
memo を正本として扱うこと。

### 行動
再利用する計算ごとに、結果を決める入力と依存を引数、設定、規則、時刻、乱数、外部の照会、可変な正本から洗い出し、再利用の判定が全てを覆うことを確かめる。
計算の定義が保持の間に変わりうるかを確かめ、変わりうるなら定義の版を同一性に含める。
同一性を確定できない入力や依存が残る計算は、確定できるまで再利用しない。
古さを許す要件があり、依存する正本と許容する古さと無効化の対象を特定できる場合は、取得 cache として扱い、[cache-aside](./cache-aside.md) の「可変な正本の取得 cache の古さを期限と無効化で閉じる」に従う。
結果を決める入力と依存を一つずつ変え、変えた後の結果が独立に求めた期待値と一致することを確かめる。
結果が変わらない変更では、期待値との一致だけを確かめる。
保持量の上限と回収の規則を定め、上限を超える入力の列でも保持量が増え続けず、所有者の終了時にも回収されることを確かめる。
外部への効果を伴う処理を計算から分け、効果を伴わない計算だけを memo の対象にする。
効果と純粋な計算の分離は [effect](../effect/README.md) に従う。

### 例
料金表を読んで利用者の料金を計算する関数の結果を、利用者の識別子が同じことだけを条件に再利用すると、料金表が変わっても同じ識別子へ旧い料金が返る。

```text
price(userId) = compute(userId, read rateTable)
reuse when userId is same
```

結果が、再利用の条件に入っていない可変な料金表の値にも依存している。
古さを許さない要件なら、料金表の版の同一を再利用の条件に加えて memo にする。
古さを許す要件があるなら、料金表を依存する正本として、許容する古さと無効化の対象を記録し、取得 cache として期限と無効化で古さを閉じる。

```text
reuse when userId and version of rateTable are same
```
