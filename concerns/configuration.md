# configuration

## 概要
configuration は、設定の扱いの方針を全系で統べる規律である。
principles の [separation](../principles/separation.md) が定める副作用の隔離と関心の隠蔽を、全系の設定の扱いとして具象化する。
secret の正本は [secrets](./secrets.md) であり、configuration は secret 参照の型と起動時の解決を書く。

## 設定を型付きの値で扱う

### 要求
設定は型付きの値として扱い、処理は型付き設定を通してのみ設定を読む。

### 根拠
裸の文字列や環境変数を各所で読むと、誤った値や欠落が実行時まで残る。
型付きの値にし、読み口を一つに絞れば、設定の意味と制約がコードに現れ、誤りを早く弾ける。

### 完了条件
設定が、型付きの値として表されている。
処理が、型付き設定を通してのみ設定を読む。
既定値が、型付き設定の一箇所に宣言され、各所のインラインの既定に散っていない。

### 禁止事項
設定を、型のない裸の値として扱うこと。
処理の途中で、外部の設定を直接読むこと。
同じ文字列を、各所で型へ解釈し直すこと。

### 行動
外部の設定を直接読む箇所を検索で洗い出す。
設定を型付きの構造へまとめ、処理には型付き設定を渡す。

### 例

環境変数を各所で直接読むと、欠落や誤りが実行時まで残る。

```
const port = process.env.PORT
```

設定を一度読み取って検証し、型付きの値として参照する。

```
const config: Config = loadConfig(); serve(config.port)
```

## 定めた源からまとめて読む

### 要求
設定は定めた源からまとめて読み込み、環境変数を設定や secret の供給源にしない。
設定の源は、project が定める。
設定の源は、ADR に記録する。

### 根拠
設定の源が散らばると、どこで何が決まるか追えない。
一つの源にまとめれば、設定の全体を一箇所で読める。
設定の源を ADR に記録すれば、採用した源と変更理由を追える。
設定をコードから分けて環境から読む点は広く行われる作法と同じだが、その供給を環境変数に置かない。
環境変数は名前空間が平坦で型がない。
ログやダンプに紛れ、子プロセスへ既定で継承され、誰が変えたか追えない。
だから設定や secret の源にしない。

### 完了条件
設定が、定めた源からまとめて読み込まれている。
設定の源が、ADR に記録されている。
環境変数が、設定や secret の供給源になっていない。
設定が、コードに焼き込まれていない。

### 禁止事項
環境変数を、設定や secret の供給源にすること。
設定の源を、ADR に記録せず運用すること。

### 行動
設定の源を一つに定め、ADR に記録する。
定めた源から、起動時に設定をまとめて読み込む。

## 環境差分を設定値で表す

### 要求
環境ごとの差分は型付き設定の値として表し、コードの分岐で環境を判定しない。

### 根拠
コードで環境を判定すると、環境ごとの分岐が各所に散り、新しい環境の追加が全分岐に波及する。
差分を設定値にすれば、環境はコードでなくデータで切り替わる。
設定を環境の名前で束ねると、デプロイが増えるたびに束が増え、組み合わせが膨れて脆くなる。
差分は直交した個別の値として持つ。

### 完了条件
環境ごとの差分が、型付き設定の値として表されている。
コードの分岐で、環境を判定していない。

### 禁止事項
コードの分岐で、環境を判定すること。
設定を、本番や検証のような名前の環境の束として持ち、束ごとコードで切り替えること。

### 行動
環境差分を設定の値として外に出し、コードは設定を読むだけにする。

### 例

コードで環境を判定すると、環境ごとの分岐が各所へ散る。

```
if (env === "prod") timeout = 1000; else timeout = 100;
```

環境差分は設定値で表す。

```
timeout = config.timeout
```

## 起動時に検証する

### 要求
設定は起動時に全体を検証し、不正な設定は理由を知らせる。
検証に失敗した起動の停止は、[lifecycle](./lifecycle.md) に従う。

### 根拠
設定の誤りを実行時に初めて検出すると、稼働中に倒れる。
設定を遅延して読むと、誤りは最初に使う要求まで隠れ、本番で初めて倒れる。
一部だけ検証して起動を続けると、未検証の設定が後で倒す。

### 完了条件
設定の全体が、起動時に検証されている。
不正な設定が、理由とともに知らされている。

### 禁止事項
一部の設定だけを検証して、起動を続けること。

### 行動
起動時に設定の全体を検証し、不正なら理由を知らせる。
停止は [lifecycle](./lifecycle.md) に従う。

## 起動時設定と実行時 flag を分ける

### 要求
起動時に確定する設定と、実行時に切り替える flag は別の機構で扱う。
flag は、振る舞いの切り替えと実験にのみ用いる。
flag の判定は一点に集約し、不要になった flag は在庫として把握して除去する。

### 根拠
起動時の設定と実行時の flag は、寿命も変更の主体も違う。
flag は寿命と動性の二軸で性質が分かれ、起動時設定とは扱いの力学が違う。
寿命は一時的から年単位、動性は静的から要求ごとに振れる。
同じ機構で扱うと、起動時の前提が実行時に崩れる。
flag を設定の代替や構造の切り替えに使うと、依存の向きが実行時に揺れる。

### 完了条件
起動時の設定と実行時の flag が、別の機構で扱われている。
flag が、振る舞いの切り替えと実験にのみ使われている。
不要になった flag が在庫として把握され、除去されている。
flag の判定が一点に集約され、各所の分岐に撒かれていない。

### 禁止事項
flag を、設定の代替や、構造と依存の向きの切り替えに使うこと。
flag の判定を各所の分岐に撒き、判定の地点と判定のロジックを結びつけること。

### 行動
起動時に確定するものは設定へ、実行時に切り替えるものは flag へ分ける。
flag の判定を一点に集約し、不要になった flag を在庫として除去する。
