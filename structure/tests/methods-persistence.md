# tests の方法: 実依存と永続化

この file は、[methods](./methods.md) が対象別に分けた技法のうち、実依存の adapter、生存と準備の面、故障の注入による再現と、永続化・transaction・messaging の保存と再構築の検証を定める。
検査の選択、性質と入力領域、規範から検証への割当は [methods](./methods.md) に従う。

## 実依存

adapter は、実の依存をコンテナで起動して検証する。
採用された store([concerns/persistence](../../concerns/persistence/README.md) に従う)を実コンテナで起動する。
生存と準備の面は、プロセスをコンテナで起動し、面の観測で確かめる。
故障は、effect を型付きで注入して再現する。
副作用の境界の規律は [concerns/effect](../../concerns/effect/README.md) に従う。

## 永続化の技法

replay は、履歴から導出する projection に対して、保存したイベント列から再構築して検証する。
再構築の決定性は、同じ正本の入力を空の派生読みモデルまたは今の状態の控えへ二度適用して結果が一致することで検証する。
二度の一致は決定性の証明ではなく、実行時の入力と外部への効果を早期に見つける検査である。
現在情報の保持は replay の対象とせず、[concerns/persistence](../../concerns/persistence/README.md) と [concerns/transaction](../../concerns/transaction/README.md) の不変条件を実 datastore で検証する。
期間の判定は、[concerns/persistence](../../concerns/persistence/period-state-views.md) の「期間の判定を一か所のビューに定義する」が定めるビューに対し、終わりの業務事実のある回とない回、外側の期間が閉じた回、開いた回が複数ある組を実 datastore に置いて、その結果で検証する。
繰り返す期間の重なりと件数の不変条件は、競合する遷移と属性の作成を全書込経路から並行に実行し、不正な組み合わせが確定しないことで検証する。
退会や消去では、残すべきキーの行と参照の存続、今の状態の控えと派生読みモデルを含む全保持先での消すべき個人情報の不在、必要な業務事実の確定を別々に観測する。
事実の行の不変性と保持期限の削除は、業務の書き込みの主体による更新と削除の拒否と、削除の主体による消せる行のビューの外の削除の拒否で検証する。
datastore が付ける時刻の列(活動の時刻と記録の時刻が一致する業務の業務事実の時刻と、別の業務事実にしない記録の時刻)への書き込み権限の不在は、datastore の権限の一覧を読む構造検査で検証する。
活動の時刻を後から指定して記録する業務は、その列を書き込み経路が受け取るので権限の不在の対象に含めず、遅れて指定した時刻が指定のまま保存されることと、契約が許す範囲と前後関係を破る時刻が書き込み経路で拒まれ状態が変わらないことを実 datastore で観測する。
記録の時刻を保持する場合は、指定した活動の時刻と datastore が付けた記録の時刻が別の値で残ることも観測する。
利用者が定義した手続きの不在は、時刻の付け方によらず datastore の定義の一覧を読む構造検査で検証する。
現在情報の変更と必要な業務事実の追記の間に失敗を注入し、双方が確定するか双方が確定しないことを検証する。
今の状態の控えは、同じ確定で更新する控えと、確定の後に別の経路で更新する派生読みモデルを分けて検証する。
同じ確定で更新する控えは、事実の追記と控えの更新の間に失敗を注入し、双方が確定するか双方が確定しないことと、確定後に控えの反映した事実の版が事実の現在の版と一致することを実 datastore で観測する。
同じ集約への書き込みを競合させ、反映した事実の版がずれた更新が確定せず競合または不整合として中止されることと、古い値が新しい値を上書きしないことを観測する。
控えの行を欠落させた状態と、反映した事実の版をずらした状態を作り、書き込みの検証がその控えで判定せず、中止するか事実からの導出へ切り替わることを観測する。
控えを捨てて事実の行だけから外部への効果なしに作り直し、結果が事実から直接導いた独立した期待値と一致することを検証する。
版が一致したまま値だけを誤らせた控えは、再構築した結果との照合で食い違いが検出され、再構築した値へ置き換わることを観測する。
時刻の経過や別の集約の変更で判定が変わる場合は、控えの反映した事実の版を変えずにその境界を越え、書き込みの許否が判定時点の条件に従うことを検証する。
確定の後に別の経路で更新する派生読みモデルは、更新を止めて事実より古くした状態で、書き込みの許否と参照の制約が事実から導いた結果と一致し、その読みモデルの値で許可されないことを観測する。
保持する事実の版の読み出し変換は、対象の各版を契約から定めた独立した期待値へ照合し、保存行が変更されないことと、現在の検証済み構造だけが内側へ渡ることを観測する。
永続化された queue の版契約は実際の受信経路へ入力を渡し、未知の追加項目の受容と、必須項目の欠落、不正な null、既知項目の不正の拒否を別々に観測し、拒否時に業務処理が始まらないことを確かめる。
一時的な旧版対応の撤去は、宣言した全配送先と発行・再投入経路を照合し、停止後に未完了の旧版が残らないことで検証する。
互換のために宣言した構造と変換箇所の参照境界は型と構造検査で照合し、項目の業務的必要性、保持範囲、変換の意味、宣言の意味的な完全性はレビューで判断する。
問い合わせ数は [bounded-query-count](../../concerns/persistence/bounded-query-count.md) の「読み取りと確定の単位で問い合わせ数を制限する」に照合し、読み取り要求の対象件数と、一つの確定の内の関連件数を変えて、件数によらない上限を保つことを検証する。
同一コンテキスト内の独立した複数集約を変更する処理は、対象列挙の各頁、各確定、全体の問い合わせを別々に数え、全体の上限が対象列挙と各確定の和に対応することを確かめる。
