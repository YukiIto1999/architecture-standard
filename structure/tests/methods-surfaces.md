# tests の方法: 利用者面と CLI

この file は、[methods](./methods.md) が対象別に分けた技法のうち、利用者面の受入と smoke、利用者面の自動検査の境界、CLI と terminal の検証を定める。
検査の選択、性質と入力領域、規範から検証への割当は [methods](./methods.md) に従う。

## 利用者面の受入

利用者面の受入では、要求と変更が影響する業務 task ごとに、確認する条件と期待結果を対応させる。
業務の振る舞いは、[layout](./layout.md) の「実行可能な仕様」に定めた事例を根拠にし、初期状態、データ、利用者と権限、入力、途中と完了の状態遷移、期待する業務結果を確定する。
画面の操作経路は現在の実装と実画面から選び、期待結果は実装や観測結果から逆算しない。
変更時の受入だけのために、業務仕様を画面の操作台本へ写したり、継続実行する test を追加したりしない。
期待する業務結果は、文言、値、件数、集計、状態と外部への効果のうち契約が保証するものを、存在の確認ではなく正確な内容として定める。
拒否する入力や操作が契約または変更の影響範囲にある場合は、拒否の理由と表示、変えてはいけない状態と副作用を確かめる。
回復経路がその範囲にある場合は、訂正、再試行、取り消し、脱出のうち契約が提供する経路を辿り、保持すべき入力と回復後の結果を確かめる。
保存の保証がその範囲にある場合は、契約が定める再読込、再訪問、再起動などの条件で再取得し、保存した業務結果と一致することを確かめる。
表示と入力の条件は、対応範囲、実際の content、layout や操作が変わる境界から代表を選び、要求に明示された条件を省かない。
全 viewport の固定した一覧や条件の数を、網羅の目標にしない。

新規または変更した画面の受入では、対象の表示条件で描画した screenshot を開いて点検し、実際に読める文言や値、欠落、重なり、切れなどの観測を、同じ状態の公開観測面から得た正確な業務結果と対応させる。
Web では DOM、native surface では公開された accessibility tree や操作後の状態を使い、存在の確認だけを結果の判定にしない。
page を開いたこと、操作の成功、request の成功、DOM 上の存在、画像の保存先だけを、利用者が結果を見て task を完了できる証拠にしない。
既存の baseline との一致は描画の退行の判定に使い、初回の正しさや変更後の要求への適合の代わりにしない。
新規または変更した画面の受入では、公開観測面から、操作要素のラベル、画面見出しの直下に常時置く文と副見出し、空状態の文を機械で列挙する。
日本語で表示する操作要素のラベルの末尾の語が動詞、形容詞、助詞でないことは、列挙したラベルの末尾の語の品詞を判定する構造検査で確かめる。
空状態に正常完了の事実または次に行う操作が表示されることは、UI の test で確かめる。
画面見出しの直下の文と副見出しが画面名から自明でないこと、空状態の文が単なる否定文だけでないこと、説明文の要否は、文の意味を画面名と画面の作りに照らして読む必要があり、型、静的検査、実行テスト、計測では判定できないため、列挙した一覧を見るレビューで判定する。
これらの規律の内容は [concerns/experience](../../concerns/experience/README.md) に従う。
critical path の smoke は、代表する一つの業務 task を利用者の操作から完了まで辿り、利用者面に現れる正確な結果を到達点とする。

要求ごとの判定は、実行した条件と観測の証拠を添えた合格、不合格、未確認に分け、実行しなかった重要な状態、経路、表示や入力の条件とその理由を残す。
実行した条件には、利用者面を検査した境界を含める。
業務結果、描画、accessibility、performance、security の合否を互いの代替にせず、それぞれの保証に割り当てた検証で判定する。
console と network の診断は、失敗した要求の原因を絞るために使い、error の不在や通信の成功を受入の証拠にしない。

## 利用者面の検査境界

利用者面の自動検査は、実際に描画した状態を観測し、結合する範囲は検査する保証を壊しうる原因から選ぶ。
layout、style、focus、accessibility tree を計算しない描画の代替と、描画を伴わない mock の結果は、focus、contrast、pointer target、名前と役割の合否の根拠にしない。
markup、style、focus の管理、操作の処理のように、描画した component または page の内側だけに原因がある保証は、実 browser で描画したその component または page を境界にして検査し、server、datastore、route の遷移を結合しない。
modal dialog の focus の循環、Escape での閉鎖、閉鎖後の復帰先、名前と役割、状態の色以外の表現、contrast、pointer target がこれに当たる。
route の遷移、認証や権限、実際の応答、datastore、構成の組立にも原因がある保証は、それらを制御した値へ置き換えず、実際の結合を通す e2e で検査する。
遷移後の focus の位置、route をまたぐ focus の復帰、権限と実際の応答が決める表示と操作の有無がこれに当たる。
component または page の境界の検査は、route と構成の不具合の検出と、結合した経路の利用者面の受入を代替しない。
e2e は、component または page の境界で成り立つ状態の組合せの網羅に使わない。
境界の配置は [layout](./layout.md) に従う。

## CLI と terminal

CLI の契約は、同じ呼び出しについて stdout、stderr、終了 status、状態変化を別々に観測する。
terminal の所有は、実際の PTY と process を使い、取得済みの mode の復元、失敗、取り消し、一時引き渡しからの復帰を確かめる。
PTY の実測は、その実依存に従って配置し、状態遷移の property や描画 snapshot の成功で置き換えない。
