# devenv

用途は、project のビルドと検証に必要な実行環境および開発用の依存サービスを、版を固定した宣言から再現する道具である。
採用は、devenv である。
判断基準は、複数言語のツールを同じ環境に供給し、container engine を前提にせず、ローカルの依存サービスを起動・停止して準備完了を判定できることである。
撤回条件は、判断基準を満たさなくなることであり、依存の固定またはローカルサービスの監督機構の互換性喪失と保守の停止を再評価のトリガーとする。

## 開発環境と依存サービスを再現する

### 要求
project のビルド、検証、開発用サービスの再現に必要な SDK・ツールとサービス設定を、環境を解決する入力の固定情報とともに repository で版管理する。
ツールやライブラリの版が言語の manifest と lockfile で固定される場合は、その版を devenv の宣言で再定義しない。
開発用の依存サービスを起動する場合は、接続先、準備完了の判定、状態の保存先と初期化条件を宣言する。
永続と宣言した開発データは、通常の停止と再起動で保持する。
同時に動く checkout では、接続先と変更する状態を取り違えない。
依存を共有するときは、各 checkout が変更できる状態を分離する。
task の定義と実行の正本は [Nx](./nx.md) の「task の正本」に従う。

### 根拠
ツールを供給する宣言から、開発者やエージェントが同じ版を取得できる。
接続先と状態の寿命が明示されていれば、別の checkout のサービスを掴むことと、再起動を初期化として扱うことを防げる。

### 完了条件
新しい checkout から、個人のツール設定に頼らず、宣言した版の道具を使える。
開発用の依存サービスを起動する project では、宣言した接続先で準備完了を観測でき、通常の停止と再起動を経ても永続とした状態を読める。
同時に使う checkout の通常操作、初期化、回収のいずれからも、別の checkout の状態を書き換えられない。

### 禁止事項
開発用のサービス起動に、本番データまたは本番の資格情報を必要とすること。
開発用の依存サービスを、本番の起動基盤や実依存テストの隔離の代わりにすること。
project のビルド、検証、開発用サービスの再現に不要な、利用者やエージェントが任意に使う補助ツールを project の開発環境の要件に含めること。

### 行動
依存の固定情報と devenv の宣言を配置し、開発の入口から利用する。
開発用の依存サービスを起動する場合は、準備完了、停止後の再起動、同時に使う checkout 間の実際の接続先と書き込み権限を確かめる。
