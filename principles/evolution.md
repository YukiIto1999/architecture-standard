# evolution

evolution は、変更の作法に関する原則を置く。
変更を段階的で可逆にし、影響範囲へ整合的に波及させ、触れた範囲を構造改善し、決まらない決定は先送りして記録に残す。

## 変更は段階的で可逆にする

### 要求
変更は、一度に全体を置き換えるのでなく、小さく可逆な段に分けて進める。
段の大きさは、安全網の緑を保ったまま一段をそのまま戻せる範囲を上限とする。
各段の前に、達成条件と撤退条件を定め、変更を支える安全網を張る。

### 根拠
全体を一度に置き換える変更は、失敗したときに戻す先がなく、被害が大きい。
一括の置き換えは、現行の振る舞いの細部を捉えきれず、しかもその多くは本当は不要で、作ること自体が無駄になる。
小さく可逆な段に分ければ、各段で誤りを検出でき、被害が段の内に収まる。
段の大きさは、一段をそのまま戻せる大きさに合わせる。
基盤へ直接結合した箇所の費用は、丸ごと入れ替える必要が生じた時に一度に顕在化する。
段階的な移行は、変える前に安全網を張って初めて安全になる。
不可逆な操作を含む変更は、その手前に観測できる達成条件と撤退条件を置くことで、進むか戻るかを事実で判断できる。

### 完了条件
一段でそのまま戻せない変更が、小さく可逆な段に分かれている。
各段に、次へ進む達成条件と、戻すための撤退条件と、不可逆点が定められている。
変える前に、変更対象の振る舞いを保つ安全網が備わっている。

### 禁止事項
大きな変更を、一度の置き換えで済ませること。
達成条件・撤退条件・不可逆点を決めずに、移行を始めること。
安全網を張る前に、本番の経路を切り替えること。

### 行動
変更を、達成条件と撤退条件を持つ小さく可逆な段に分ける。
不可逆な操作を特定し、その手前に観測できる達成条件と撤退条件を置く。
変える前に、変更対象の振る舞いを保つ安全網を用意する。

### 例
```text
現状
  -> 可逆な変更。安全網と達成条件を確認する
  -> 可逆な変更。撤退条件を満たしたら現状へ戻す
  -> 不可逆点。手前の観測で進行を決める
  -> 目標の状態
```

## 影響範囲へ整合的に波及させる

### 要求
契約・命名・構造・規約・基盤の変更は、影響範囲の全体へ同じ方針で波及させ切る。
局所のシムや例外で、旧方式と新方式を恒久的に併存させない。

### 根拠
局所で例外を吸収すると、旧方式と新方式が併存し、標準が分裂する。
一つの概念的な変更が複数の箇所への散らばった修正を強いるなら、波及を完了させる合図である。
拡張と移行だけで収縮を省くと、二系統の恒久的な重複が残り、始める前より悪い状態になりうる。
新旧の共存は、取りうる状態を掛け算で増やし、問題が要求しない偶有的な複雑さを生む。
この複雑さは技術者が作ったものであり、波及を完了させれば技術者が消せる。
意味体系の異なる外部との境界では、翻訳を一箇所の隔離層に集約し、各所へ散らさない。
複数の利用者を持つ契約は、利用者が使う要素だけを読み未知を無視する寛容な読み手にし、契約全体への暗黙の結合を避ける。

### 完了条件
変更対象と同種の設定・規約・基盤コード・テスト・ドキュメントへ、同じ方針が適用されている。
同一の責務に対して、二つの異なる方式が併存していない。
拡張と移行のあと、収縮まで到達し、旧方式が消えている。
外部との翻訳が、一箇所の隔離層に集約されている。

### 禁止事項
単一ファイル内の局所修正・例外吸収・暫定シム・重複設定で済ませること。
拡張と移行だけで止め、旧方式を恒久的に残すこと。
外部の都合を翻訳する処理を、各所へ散らすこと。

### 行動
変更した設定・規約・基盤と同種の箇所を横断検索し、同じ方針で更新する。
新旧の分岐は、移行を完了して収縮させ、分岐を消す。
外部との翻訳は、継ぎ目に隔離層を一つ置いて集約する。

### 例
移行を完了させずに新旧の分岐を各所へ残すと、二つの方式を恒久的に保守することになる。

```ts
if (schema === "v1") { } else { }
```

変更をすべての消費者へ波及させ、収縮まで進めれば、旧方式と分岐は残らない。

```ts
process(order);
```

## 触れた範囲を構造改善する

### 要求
修正は、触れた範囲の構造を、来たときより良くして去る。
振る舞いの変更と構造の改善は、別の変更として分ける。

### 根拠
触れる機会に少しずつ構造を整えれば、システムの劣化が止まり、変更のたびに良くなる。
個々の変更が妥当でも、積み重ねは全体の一貫性を必ず崩すので、ずれは変更のたびにその場で直す。
完璧にする必要はなく、どんなに小さくても良い方向への一歩でよい。
振る舞いの変更と構造の改善を混ぜると、どちらが原因で壊れたか切り分けられず、レビューも戻しも汚れる。
構造の改善は、振る舞いを保つテストが緑のときにだけ行える。
構造を変える機会には、深追いして当初の目的を見失わない判断が要る。
触れた範囲とは、当初の目的の達成に必然の関係がある範囲であり、無関係な箇所のついで直しは別の変更に分ける。
変更の名は着手前に決まり、その名が差分に含めてよい範囲を定める。
読み手として耐えられない箇所、名と実の食い違い、責務の混在のような臭いは、規律違反の兆候として知覚し、構造改善の契機にする。
臭いはカタログに一致するとは限らず、標準の完了条件と禁止事項への照合で言語化する。
既存の構造が機能追加を難しくしているなら、先に構造を整えてから足す方が、結局速い。

### 完了条件
変更の名と、その名が差分に含めてよい範囲が、着手前に決まっている。
知覚した臭いが、標準の完了条件と禁止事項への照合で言語化されている。
言語化した臭いのうち触れた範囲に属するものが、差分の改善で解消されているか、名前を付けた別の変更として残されている。
振る舞いの変更と構造の改善が、別の変更に分かれている。
構造の改善が、振る舞いを保つテストの下で行われている。

### 禁止事項
既存の責務混在・重複・例外分岐に合わせて、さらに例外や重複を追加すること。
振る舞いの変更と構造の改善を、同じ変更に混ぜること。
当初の目的の達成に必然の関係がある不整合を、差分を小さく見せるために無視すること。
構造改善の深追いで、当初の変更を見失うこと。

### 行動
修正の前後で、命名・責務・重複・配置・依存方向が改善しているか確認する。
構造の改善と振る舞いの変更を、別の変更に分ける。
機能追加が難しいなら、先に構造を整えてから、易しくなった変更を行う。
臭いを感じた箇所から直し始め、当初の目的の達成に必然の関係がある範囲だけへ整合を波及させる。
目的と因果関係のない不整合は、その場で直さず、名前を付けた別の変更として残す。
制御の混乱した箇所は、入出力の契約だけを固定し、内部を書き直してよい。
作業中に生まれた変更をすべて出荷せず、目的に属する差分だけを選別して仕立てる。

### 例
改名、抽出、機能追加を一つのコミットに混ぜると、不具合が起きても全体を戻すしかない。構造の改善と振る舞いの変更を分ければ、機能追加のコミットだけを戻せる。

```
feat: add discount and rename vars and extract helper

refactor: rename / refactor: extract calcDiscount / feat: add discount
```

## 決まらない決定は先送りし、記録に残す

### 要求
いま決める必要のない決定は、可逆な形に組み替えて先送りし、選択肢を保つ。
採った決定は、記録に残す。
記録の内容と置換の作法は、[documentation](./documentation.md) に従う。

### 根拠
情報が足りないうちに決めると、後で作り直しになり、変更の手間が増える。
後で下す決定ほど、事業と技術の理解が深まった状態で下せる。
決定は、戻れる二方向のものと、戻れない一方向のものに分ける。
戻れる決定は速く下し、戻れない決定は、代替案が消える最終の時点まで慎重に待つ。
良いアーキテクチャは、下す決定よりも、下さずに済ませられる決定を増やす。
機能に対する先送りと、決定に対する先送りは別であり、必要な決定の放置は先送りでない。
変更を容易にする労力は先送りの対象でなく、むしろ先送りを支える土台である。

### 完了条件
いま決める必要のない決定が、可逆な形で先送りされ、選択肢が保たれている。
不可逆な決定が記録に不可逆と明記され、戻れない決定が最終の時点まで待たれている。
採った決定が、記録に残っている。

### 禁止事項
いま必要でない決定を、不確かなまま早まって固定すること。
必要な決定や、変更を容易にする労力を、先送りと称して怠ること。

### 行動
決定ごとに、いま決める必要があるか、戻れるか戻れないかを確かめる。
戻れる決定は速く下し、戻れない決定は代替案が消える時点まで待つ。
できるだけ多くの決定を、後から戻せる形に組み替える。
採った決定は、記録に残す。
記録の内容と置換の作法は、[documentation](./documentation.md) に従う。

### 例
要件が固まる前に DB 製品を固定すると、情報が足りない段階で戻れない前提を置くことになる。永続化を port の裏に置けば、製品の選択を必要になるまで先送りできる。下した決定は ADR に残す。

```md
（DB 製品を初期に固定し、要件が固まる前に不可逆な前提にする）

（永続化を port の裏に置き、製品の選択を後の可逆な決定にする。決定は ADR に残す）
```
