## データの原則は定めた順位で優先する

### 要求
データの設計で原則がぶつかるときは、次の順位で上位の原則を優先する。

1. 個人情報の消去と、理由のない保存をしない最小化の義務を果たす。
2. データ層に文を実行する手続きを置かない。
3. 事実の行を書き換えない。
4. 同じ関心を二か所で宣言しない。
5. 不変条件をデータ層の制約で守る。
6. 判定ごとに読む記録の数を設計の時点で確かめ、性能の目標を満たす。

下位の原則が上位の原則を退けてよいのは、次の二つの場合だけとする。
一つは、固定した負荷での計測で性能の目標を超え、決定の記録がある場合に、導出値の控えを置くことであり、6 が 4 を退ける。
もう一つは、消去の義務で消す記録に業務上の一意性をデータ層で守らせ、消去によって記録の有無が期間と一致することを使って、期間の中での一意性を表すことであり、5 が 4 を退ける。
原則がぶつかった箇所ごとに、優先した原則と退けた原則を決定の記録に残す。

### 根拠
個人情報の消去は法令の義務であり、設計上のどの利点とも交換できず、理由のない保存は消去の対象と漏えいの範囲を広げ続ける。
データ層の手続きは、書き込みの結果を見えない処理に委ね、守る形の単純さを他のどの原則よりも先に壊す。
事実の行を書き換えて守る形は、状態と事実を同じ行に置いて削除や更新で表す形であり、起きた活動を事実として残すという前提そのものを失うので、二重管理を避ける利点や制約で守る利点と交換しない。
同じ関心を二か所で宣言すると、制約を足しても同期がずれ、ずれを防ぐには結局書き込み経路が要るので、二重管理を避けることを制約で守ることより上に置く。
制約で守る範囲は、上位の原則に反しない構造の中で最大にする。
性能は設計の時点で確かめるべきだが、導出の重さを理由に二か所で宣言するのは、計測で必要が示された場合に限る。
消去の義務で記録を消すことは、すでに書き込み経路に課された義務なので、その結果の記録の有無を一意性に使っても、新しい同期を書き込み経路に足さない。
順位がなければ、原則がぶつかるたびに判断が設計者ごとに割れ、同じ問題に別々の形が混ざる。

### 完了条件
原則がぶつかった箇所ごとに、優先した原則と退けた原則が決定の記録から追える。
下位の原則が上位の原則を退けた箇所が、計測と決定の記録を伴う導出値の控えと、消去の義務で消す記録の一意性に限られている。
制約で守るために、消去の義務、手続きの禁止、事実の行の不変性のいずれかを破った箇所がない。
制約で守るために同じ関心を二か所で宣言した箇所が、消去の義務で消す記録の一意性に限られている。

### 禁止事項
制約で守るために、消去や最小化の義務を果たせない形にすること。
制約で守るために、データ層に手続きを置くこと。
制約で守るために、事実の行を書き換えること。
制約で守るために、消去の義務で消す記録の一意性のほかに、事実の行から導ける関心を別の記録として持つこと。
計測と決定の記録なしに、性能を理由に上位の原則を退けること。
二つの場合のほかに、下位の原則で上位の原則を退けること。

### 行動
設計案ごとに、各原則に反するかを確かめ、ぶつかる組を洗い出す。
ぶつかる組では、この順位で上位の原則を満たす案を選び、下位の原則で守れなくなった条件を書き込み経路の規則として決定の記録に残す。
下位の原則で上位の原則を退ける場合は、二つの場合のどちらに当たるかと、その条件を満たす根拠を決定の記録に残す。
消去と最小化は [preserve-facts-and-current-state](./preserve-facts-and-current-state.md) の「業務事実と現在情報を分けて保持する」に、二か所の宣言と控えは [derive-state-from-facts](./derive-state-from-facts.md) の「今の状態を事実の行から導く」に、制約と手続きは [database-integrity](./database-integrity.md) の「整合性をデータ層の制約で守る」に従う。

### 例
繰り返す停止の重なりを、期間を範囲の値として始まりの記録に持たせ、重なりを拒む宣言で守ると、解除のたびに始まりの記録へ終わりを書き込むので、事実の行を書き換える。

```text
suspension(id, userId, period = [startedAt, endedAt))
reject overlapping period for the same userId
reinstate(suspensionId) = update suspension set period.end = now
```

3 を 5 より優先し、停止と解除を別の業務事実として追記し、重なりは書き込み経路が利用者の集約の鍵の下で、開いた停止がないことを確かめて守る。

```text
suspension(id, userId, at)
reinstatement(suspensionId -> suspension, at)

suspend(userId):
  exclusive userAggregate(userId)
  require no open suspension of userId
  add suspension(newId, userId, now)
```
