## 今の状態を事実の行から導く

### 要求
状態の行き来を業務事実として残す対象では、今の状態を事実の行から導き、状態を表す列や記録を事実の行と別の正本として持たない。
状態を表す列や記録とは、その値や有無が、事実の行から導ける関心(期間が開いているか、退会したかなど)を表すものである。
期間が閉じているとは、その期間の取り消されていない終わりの業務事実があるか、判定の時点が予定した終わりの時刻に達したか、同じ集約が所有する外側の期間が閉じていることとする。
予定した終わりの時刻は、期間の始まりの行の値か、それが参照する行の書き換えない値か、その期間を参照する取り消されていない業務事実の値として確定した時刻(休会の終わりの月、予約した回の開始の時刻、解約の申し入れが定めた退去日など)である。
予定した終わりの時刻を定める業務事実は、記録した時点では期間を閉じず、期間はその時刻に達したときに閉じ、保持と削除では終わりの業務事実と同じく扱う。
期間の閉じた時刻は、自身の終わりの時刻と、判定の時点が達した予定の終わりの時刻と、外側の期間の閉じた時刻のうち、最も早いものとする。
外側の期間が閉じたことで閉じる内側の期間には、終わりの業務事実を書き足さない。
内側の期間を別の集約が所有する場合は、外側の期間を閉じる確定の前か同じ確定の中で、その集約の書き込み経路が内側の期間を終わりの業務事実で閉じる。
内側の期間を同じ確定の中で閉じる場合も、所有する集約の規則を検証する。
両方の集約に属する場合は、開いている内側の期間を終わりの業務事実で閉じることと外側を閉じることを同じ確定で行ってよい。
開いた内側の期間を外側と一緒に閉じるか、開いた内側の期間がある間は外側を閉じる書き込みを拒むかは、業務の規則で決め、決定の記録に残す。
今の状態の判定は一か所で定義し、書き込みの検証、読み取り、保持期限による削除が同じ定義を使い、後の判定は前の判定を組み合わせて定義する。
判定ごとに読む記録の数が何に比例するかを、設計の時点で確かめる。
履歴から導けない現在値(可変属性と現在関係)は、現在値が正本であり、この規律の今の状態に当たらない。
試行回数や次に実行してよい時刻のような実行上の進行は、業務事実から導く今の状態に当たらず、[workflow](../../concerns/workflow/resumable-progress.md) の「進行の状態を持ち、停止から再開する」が定める進行の状態として、調整役が正本を持つ。
純粋な導出を既定とし、今の状態の控えは、導出で満たせないアクセス要件がある場合の選択とする。
今の状態の控えは、事実の行から導いた今の状態を保存した値であり、正本は事実の行のまま変えない。
アクセス要件は、判定を読む主体、整合の強さ(確定と同時か、確定の後でよいか)、読む形(一つの対象か、集約をまたぐ一覧か)、目標の応答時間、想定の件数で定める。
導出で満たせないことは、応答時間の目標では固定した負荷での計測で示し、読む形では導出が与えない形を要件で示し、決定の記録に残す。
控えの更新は、同じ確定で行うものと、確定の後に別の経路で行うもの(派生読みモデル)に分け、アクセス要件の整合の強さに合う方を決定の記録に残す。
同じ確定で更新する控えは、事実の追記と同じ確定に含め、その集約の競合制御の下で更新し、反映した事実の版を持つ。
反映した事実の版は、控えが導出に使った事実の行の、集約内の順序の末尾である。
更新前の控えの版が追記前の事実の末尾と一致することを確かめ、更新後の版を追記後の末尾に合わせる。
一致しなければ追記も控えの更新も確定せず、古い値で控えを上書きしない。
同じ確定で更新する控えは、事実を追記する全ての経路が更新し、控えだけを更新する経路は、事実の行から作り直す再構築に限る。
書き込みの検証が控えを読んでよいのは、同じ確定で更新する控えが、鍵の後の同じ確定の中で、反映した事実の版と事実の行の現在の版の一致を確かめられた場合に限る。
判定が時刻の経過や控えの反映範囲の外の値にも依存する場合は、版の一致だけで許否を決めず、判定時点の時刻と必要な依存を同じ判定で確認する。
一致しない控えと欠けた控えでは判定せず、確定を中止して作り直すか、その判定を事実の行から直接導く。
版の一致が検出するのは、欠落、版のずれ、古い値であり、版が一致したまま値だけが誤る内容の破損は、毎回の書き込みの検証でなく、事実の行からの再構築との照合で検出する。
確定の後に別の経路で更新する派生読みモデルは、確定済みの事実を反映する保証がないので、書き込みの検証にも、参照の制約にも使わない。
事実の行や他の記録は、控えを参照先にしない。
控えは、事実の行だけから外部への効果なしに作り直せる形にし、作り直しと照合の手順、更新の失敗と競合の扱いを、決定の記録に残す。
控えが消去の契約が定める情報を含む場合は、その控えを消去の保持先に含める。
消去の義務を果たすために消す個人データの有無を、期間が開いているかの判定や、それを代わりに表す書き込みの検証や参照の条件に使わない。
その記録自身の件数と一意性を守ることは、この条件に当たらず、一意性は [precedence](./precedence.md) の「データの原則は定めた順位で優先する」の二つ目の場合に従う。
消去の後に対象への操作を拒むなど、消去が今の状態に効く場合は、消去を業務事実として残し、その業務事実で判定する。

### 根拠
同じ関心を事実の行と状態の記録の二か所で宣言すると、制約を足しても同期がずれ、ずれを防ぐには結局書き込み経路が要る。
状態の記録を置くと、その記録と業務事実が両立してはならない組(有効なアカウントと退会の事実など)が生まれ、その組を防ぐための排他が増える。
事実の行から導けば、その組そのものが生じない。
業務事実は過去に起きたことを記録するが、始まりの行と終わりの業務事実の有無から、今成り立つことも一意に導ける。
同じ集約が所有する内側の期間に、外側の期間の終わりに合わせて終わりを書き足すと、起きていない終わりを記録し、終わったことを二か所で宣言する。
内側の期間を別の集約が所有する場合に、外側の終わりで暗黙に閉じると、その集約の不変条件を検証しないまま内側が閉じる。
予定した終わりの時刻に達して閉じることは、書き込みでなく期間の定義に含まれるので、不変条件を検証しないまま要素が減ることにならない。
判定を問い合わせや書き込み経路ごとに書き写すと、判定の定義を二か所で宣言することになり、書き込みの検証と読み取りが食い違う。
導出は対象の履歴の長さに比例して読むので、読む数を設計の時点で確かめないと、性能の目標を後から割り込む。
純粋な導出は二つ目の宣言を持たないので、同期のずれが生じる余地がなく、既定にする。
控えは同じ関心の二つ目の宣言であり、正本を事実の行に保つことと、導出で満たせないアクセス要件があることを示せる場合に限る。
性能の目標を理由とする控えを計測なしに入れると、対価を説明できない二つ目の宣言だけが残る。
同じ確定で更新する控えを事実の追記と別の確定にすると、事実だけが進んだ状態が観測され、その控えで判定した結果が事実に反して確定する。
同じ確定で更新し、反映した事実の版を持たせれば、控えがどこまでの事実を反映するかが定まり、欠落した更新や古い値での上書きを、更新が検出して拒める。
控えを読んで書き込みの可否を決めても、控えが事実の行と版で対応し、食い違えば使わず作り直すなら、可否の根拠は事実の行のままである。
版の対応は、欠落とずれを検出するが値の誤りを検出しないので、値の誤りは作り直した結果との照合で別に検出する。
事実の版が変わらなくても、時刻の経過や別の集約の変更で判定は変わるため、反映版は判定に使う全ての値の鮮度を代替しない。
確定の後に別の経路で更新する派生読みモデルは遅れうるので、書き込みの検証に使うと、確定済みの事実を見ない判定が確定する。
控えを参照先にする制約があると、作り直すために参照元を書き換えるか消すことになる。
履歴から導けない現在値は、捨てると失われるので現在値が正本であり、導出の対象に含めると、現在値を履歴から導く要求になる。
実行上の進行は、業務の意味を持たず再実行の判断のために持つので、業務事実から導く対象に含めない。
消去の請求で個人データを消すことは状態の行き来ではないので、その有無で状態を判定すると、消去が状態を変えてしまう。

### 完了条件
状態の行き来を業務事実として残す対象に、状態を表す列や記録が、控えの条件を満たさずに事実の行と別の正本として存在しない。
今の状態の判定が一か所で定義され、書き込みの検証、読み取り、保持期限による削除が同じ定義を参照している。
外側の期間が閉じたことで閉じる内側の期間に、終わりの業務事実が書き足されていない。
別の集約が所有するか両方の集約に属する内側の期間が、外側の期間を閉じる確定の時点で、終わりの業務事実か達した予定の終わりの時刻で閉じている。
判定ごとに読む記録の数と、その根拠になる想定の件数と目標の応答時間が、決定の記録から追える。
今の状態の控えが、アクセス要件と、導出で満たせない根拠(計測、または導出が与えない読む形)と、更新方式を示す決定の記録を伴っている。
同じ確定で更新する控えが、事実の追記と同じ確定に含まれ、追記前後の事実の末尾に更新前後の反映版がそれぞれ一致している。
同じ確定で更新する控えが、事実を追記する全ての経路で更新され、控えだけを更新する経路が再構築に限られている。
書き込みの検証が読む控えが、同じ確定で更新するものに限られ、版の一致を確かめ、一致しない控えと欠けた控えでは判定していない。
時刻の経過や控えの反映範囲の外の値で変わる判定が、版の一致だけでなく、判定時点の条件を確かめている。
確定の後に別の経路で更新する派生読みモデルが、書き込みの検証にも参照の制約にも使われず、事実の行や他の記録の参照先にもなっていない。
控えが事実の行だけから作り直せ、作り直した結果との照合の手順と、更新の失敗と競合の扱いが、決定の記録にある。
現在値と実行上の進行が、事実の行から導く今の状態として扱われていない。
消去の義務で消す個人データの有無が、期間の判定と、それを代わりに表す書き込みの検証や参照の条件に使われていない。
消去が今の状態に効く対象で、消去が業務事実として残され、判定がその業務事実を使っている。

### 禁止事項
事実の行から導ける今の状態を、控えの条件を満たさない状態を表す列や記録として別に持つこと。
同じ集約が所有する内側の期間に、外側の期間の終わりに合わせて終わりの業務事実を書き足すこと。
別の集約が所有する内側の期間を、外側の期間の終わりで暗黙に閉じること。
今の状態の判定を、問い合わせや書き込み経路ごとに書き写すこと。
アクセス要件と導出で満たせない根拠を示す決定の記録なしに、今の状態の控えを置くこと。
性能の目標を理由とする控えを、計測なしに置くこと。
同じ確定で更新する控えを、事実の追記と別の確定で更新し、または事実の追記を伴わずに更新すること(再構築を除く)。
反映した事実の版を確かめずに、控えを書き込みの検証の根拠にすること。
確定の後に別の経路で更新する派生読みモデルを、書き込みの検証や参照の制約に使うこと。
事実の行や他の記録の参照先を、控えにすること。
現在値や実行上の進行を、事実の行から導く今の状態として扱うこと。
消去の義務で消す個人データの有無で、期間が開いているかを判定し、またはそれを代わりに表す検証や参照の条件にすること。
消去が今の状態に効く対象で、消去を業務事実として残さず、記録の有無で消去の後の操作を判定すること。

### 行動
状態の列や記録を見たら、その状態の行き来を業務事実として残しているかを確かめ、残しているなら、控えの条件を満たすかを確かめ、満たさなければ列や記録を除き、判定を事実の行から導く。
期間ごとに、終わりの業務事実、予定した終わりの時刻、外側の期間、所有する集約を特定し、外側の終わりで閉じるか、内側を終わりの業務事実で先に閉じるかを決める。
今の状態の判定を一か所に定義し、書き込みの検証、読み取り、保持期限による削除がそれを参照するようにする。
判定ごとに読む記録の数が何に比例するかを確かめ、想定の件数と目標の応答時間を決定の記録に残す。
導出で満たせないアクセス要件がある判定だけに控えを置き、更新方式、更新の失敗と競合の扱い、作り直しと照合の手順を決定の記録に残す。
書き込みの検証が読む控えは、同じ確定で更新するものに絞り、鍵の後に版の一致を確かめる。
値の誤りは版の一致で検出できないので、作り直した結果との照合を用意する。
現在値は現在値を、実行上の進行は調整役を、履歴から導ける今の状態は事実の行を、それぞれ正本に分ける。
集約の範囲は [aggregate-integrity](./aggregate-integrity.md) の「整合性を集約境界に閉じる」に、確定の範囲は [transaction](../../concerns/transaction/README.md) に従う。
判定の定義、関係への落とし方、datastore に置く控えは [persistence](../../concerns/persistence/README.md) が、短寿命の控えの鮮度と無効化は [caching](../../concerns/caching/README.md) が、確定の後に別の経路で更新する派生読みモデルの配送と順序は [messaging](../../concerns/messaging/README.md) が定める。

### 例
有効な利用者を別の記録として持ち、退会でその記録を消して退会を追記すると、有効であることを二か所で宣言する。
両方がある組や両方がない組を防ぐ排他が、全ての書き込み経路に要る。

```text
activeUser(userId -> user)
withdrawal(userId -> user, at)

withdraw(userId):
  remove activeUser(userId)
  add withdrawal(userId, now)
```

有効かは、利用者のキーの行と退会の業務事実から導く。
停止中かは、終わりのない停止があり、外側の登録の期間が開いていることとして、有効かの判定を組み合わせて導く。
退会した利用者の停止には解除を書き足さず、退会が外側の期間を閉じることで閉じたとみなす。

```text
withdrawal(userId -> user, at)
suspension(id, userId -> user, at)
reinstatement(suspensionId -> suspension, at)

active(userId) = user(userId) exists and no withdrawal(userId)
suspended(userId) = active(userId) and exists suspension s of userId with no reinstatement(s.id)
```

口座の出金の判定が、一口座の全入出金の走査では目標の応答時間を超えると計測で示された場合に、残高の控えを置く。
出金の確定の後に別の経路で控えを更新し、その控えで次の出金を検証すると、確定済みの出金を見ない判定が確定し、残高を超えて出金できる。

```text
add ledger(accountId, nextSeq, -amount, at)
later job: set accountBalance(accountId) = sum of ledger amounts of accountId

withdraw(accountId, amount):
  require accountBalance(accountId) >= amount
  add ledger(accountId, nextSeq, -amount, now)
```

控えは事実の追記と同じ確定で更新し、反映した事実の版を持たせる。
版が一致しない控えでは判定せず、確定を中止して作り直す。

```text
ledger(accountId -> account, seq, amount, at)
accountBalance(accountId -> account, balance, reflectedSeq)

withdraw(accountId, amount):
  exclusive accountAggregate(accountId)
  require accountBalance.reflectedSeq = latest ledger seq of accountId
  require accountBalance.balance >= amount
  add ledger(accountId, nextSeq, -amount, now)
  set accountBalance(accountId) = (balance - amount, reflectedSeq = nextSeq)
```
