## データを事実・状態・時間で分類する

### 要求
データを、リソース・業務事実・可変属性・現在関係・定義・導出値に分けて捉える。
リソースは、時刻を持たない同一性として区別し、その追加をキーの行があることで表す。
リソースのキーは、生成した後に変えない。
人を表すリソースのキーの行には、キー以外の値を置かない。
業務事実は、業務が起きた時刻とともに事実として残すと決めた活動として区別し、その活動の時刻を一つだけ持たせる。
活動を業務事実にするかは、業務・監査・回復・消去の契約が保持を求めるかで決め、決定の記録に残す。
業務事実は、業務上区別する意味ごとの活動として表し、発生回数と取り消せるかを活動ごとに定める。
業務事実が確定した値(注文の価格、返却期限など)は、その業務事実の値として持ち、後の業務事実が値を変える場合は、今の値をそれらの業務事実から導く。
リソースや関係の追加を業務事実にするのは、追加そのものの時刻や値を残す契約がある場合に限る。
追加を業務事実にする場合、キーの行が変わる値を持たず人も表さないなら、キーの行に活動の時刻を一つ持たせて始まりの業務事実とし、そうでなければ、キーの行を参照し活動の時刻だけを持つ業務事実を別に置き、追加されているかの判定にはキーの行だけを使う。
削除を業務事実として残す対象は、キーの行を残し、削除をそのキーの行を参照する業務事実で表す。
事実として残さない削除は、行の削除で表す。
業務事実の行と、削除を業務事実として残すリソースや関係のキーの行を、事実の行として扱う。
状態の行き来を業務事実として残す対象は、始まりの行と、それを参照する終わりの業務事実の対からなる期間として表す。
始まりの行は、追加を表すキーの行か、始まりの業務事実である。
可変属性は、事実の行から導けない今の値として区別し、変更の単位とライフサイクルが同じものを一つにまとめ、異なるものを分ける。
現在関係は、事実として残さない、リソースや定義どうしの今の結び付きとして区別する。
定義は、業務の操作では増減せず、業務の規則や法令の改定に伴ってアプリケーションの処理と一緒に変わる一覧として区別する。
導出値は、正本から計算でき、捨てても正本から取り戻せる値として区別し、事実の行から導ける今の状態もこれに含める。
発生の時刻に加えて記録の時刻を契約が求める場合は、記録を別の業務事実として表す。
未来に向けて適用する変更は、適用の始まりを活動の時刻と別の値として持ち、過去に起きた事実の時刻と混同しない。

### 根拠
契約が保持を求める活動を今の値だけで持つと、起きた事実と時点が失われる。
一方、全ての変更を履歴として持つと、契約が求めない保持を負い、消去の契約と衝突する。
同一性、活動、今の値、一覧は、変わり方と消え方が異なるため、別のものとして分ける。
業務事実が確定した値は、元に合わせて変える必要がないので写しでなく、後の業務事実が変えた今の値は、それらの業務事実から一意に導ける。
変わる値を持つか人を表すキーの行に追加の時刻を足すと、書き換えない事実と更新する今の値が一つの行に混ざるか、人を表すキーの行に値を置くことになる。
追加をキーの行で表せば、追加という事実を別の記録と二か所で宣言せずに済み、存在するものにだけ従属する行が付くことを参照で表せる。
全てのリソースに一律の登録の時刻を持たせる規則は、時刻を要しない追加にまで記録と保持の負担を負わせる。
削除を、残したキーの行を参照する業務事実で表せば、キーとその関連を失わずに、消すべき情報だけを消せる。
人を表すリソースのキーの行に値を置くと、消去の義務を果たすためにキーの行を書き換えるか消すことになり、関連を失う。
事実の行を書き換えないことの理由は、[preserve-facts-and-current-state](./preserve-facts-and-current-state.md) の「業務事実と現在情報を分けて保持する」に従う。
一つの業務事実に複数の時刻を持たせると、どの時刻がその活動を表すかが曖昧になる。
発生と記録は別の活動であり、別の業務事実として持てば、それぞれが一つの時刻で定まる。
業務事実の目印は活動の時刻であり、予定日や有効期限のような活動の時刻でない日付は、リソースにも置かれうる。
日本語で動作として表せるかどうかも、データの意味を分類する条件にはならない。
再登録・復帰・停止・退会・消去は、発生回数、取り消せるか、今の状態への影響が異なる。
これらを同じ一回限りの出来事へ一般化すると、繰り返す出来事や取り消される出来事を表せない。
期間を始まりの行と終わりの業務事実の対で表せば、繰り返す回ごとにどの終わりがどの始まりを閉じるかが定まり、前の回の終わりが次の回の判定を狂わせない。
可変属性と現在関係は捨てると情報を失うのに対し、導出値は捨てても正本から取り戻せるため、両者を区別する。
定義は値ごとに異なる処理を伴い、コードが値を名前で参照するので、業務の操作で増減する一覧と同じ扱いにすると、コードと一覧が食い違う。
事実が実世界で真である時刻と、それをシステムが記録した時刻は、別の時間軸である。
適用の始まりと活動の時刻は時間の向きが異なるため、一つの時刻へ混ぜると、いつ起きたかといつから効くかのどちらも曖昧になる。

### 完了条件
リソース・業務事実・可変属性・現在関係・定義・導出値の分類が、型か schema の区別として表れている。
リソースの追加がキーの行で表され、キーが生成後に変わっていない。
人を表すリソースのキーの行が、キー以外の値を持っていない。
業務事実が、契約が保持を求める活動に限られ、活動の時刻を一つだけ持っている。
リソースや関係の追加を表す業務事実が、追加の時刻や値を残す契約がある対象に限られている。
削除を業務事実として残す対象で、キーの行が残り、削除がそれを参照する業務事実で表されている。
事実として残さない削除が、行の削除で表されている。
状態の行き来を業務事実として残す対象が、始まりの行と、それを参照する終わりの業務事実の対で表されている。
意味の異なる活動が別の業務事実として表され、発生回数と取り消せるかが活動ごとに定められている。
可変属性が、変更の単位とライフサイクルで分けられ、同じ単位の属性が機械的に分割されていない。
定義が、業務の操作で増減する一覧と別に表されている。
記録の時刻を要する対象で、記録が別の業務事実として表されている。
未来に向けて適用する変更を要する対象で、適用の始まりが活動の時刻と別の値として表されている。

### 禁止事項
契約が保持を求める活動を、今の値だけで表すこと。
一つの業務事実に、活動を表す時刻を複数持たせること。
リソースのキーを、生成した後に変えること。
人を表すリソースのキーの行に、キー以外の値を置くこと。
全てのリソースや関係の追加に、一律に登録の時刻や登録の業務事実を持たせること。
業務事実として残す削除を、キーの行の削除や削除フラグで表すこと。
隠れた業務事実を、更新日時や削除フラグで覆い隠すこと。
活動の時刻でない日付の有無や日本語の文法で、業務事実とリソースを分類すること。
同じ変更の単位とライフサイクルの属性を、機械的に別のものへ分けること。
再登録・復帰・停止・退会・消去を、同じ一回限りの出来事へ一般化すること。
導出値を、可変属性や現在関係と混同すること。
業務の操作で増減する一覧を、定義として扱うこと。

### 行動
対象データを、リソース・業務事実・可変属性・現在関係・定義・導出値の観点で分類する。
活動ごとに、業務・監査・回復・消去の契約が保持を求めるかを確かめ、求めるものだけを業務事実にして、決定の記録に残す。
追加と削除ごとに、時刻を残す契約と、削除を事実として残す契約を確かめ、キーの行、業務事実、行の削除のどれで表すかを決める。
状態の行き来を残す対象は、始まりの行と終わりの業務事実を特定し、期間として表す。
再登録・復帰・停止・退会・消去のように意味の異なる出来事は、発生回数と取り消せるかを確かめ、別の業務事実として分ける。
属性は、変更の単位とライフサイクルを確かめ、同じものを一つにまとめ、異なるものを分ける。
変更の単位は、業務の一つの操作が一緒に受け付ける属性の組であり、値が変わる理由の違いでは分けない。
一覧ごとに、業務の操作で増減するかを確かめ、リソースと定義を分ける。
捨てると情報を失う値は可変属性か現在関係、正本から取り戻せる値は導出値として見分ける。
保持と消去は [preserve-facts-and-current-state](./preserve-facts-and-current-state.md) の「業務事実と現在情報を分けて保持する」に、今の状態の導き方は [derive-state-from-facts](./derive-state-from-facts.md) の「今の状態を事実の行から導く」に従う。
関係と制約への落とし方は、[persistence](../../concerns/persistence/README.md) が定める。

### 例
利用者の行に名前、状態、削除フラグ、一律の作成時刻と更新時刻を置くと、退会や停止という活動が残らず、名前を消すには同一性の行を書き換えることになる。

```text
user(id, displayName, status, deleted, createdAt, updatedAt)
```

登録は利用者のキーの行で表し、登録の時刻を残す契約がないので、登録の業務事実は置かない。
退会は利用者のキーの行を参照する一回限りの業務事実、停止は繰り返す期間の始まりの業務事実、解除はその終わりの業務事実として、それぞれ活動の時刻を一つだけ持つ。
表示名は消去の請求で消せる可変属性として、キーの行と別に置く。
停止中かは、停止と解除と退会から導く導出値であり、どこにも記録しない。
矢印は参照先を表す。

```text
user(id)
profile(userId -> user, displayName)
withdrawal(userId -> user, at)
suspension(id, userId -> user, reasonCode -> suspensionReason, at)
reinstatement(suspensionId -> suspension, at)
suspensionReason(code)
```
