## 文書の種別を分け、読み手を定める

### 要求
文書は、学習・手順・参照・説明の種別を分け、混ぜない。
読み手と、その読み手が作業中か学習中かを定めてから書く。
`docs/` は、継続する読み手のための文書を Git で追跡し、現在のコード、テスト、契約、設定を読者向けに投影する場所とする。
`docs/` に未実装の要件や入力契約を置く場合は、その根拠と決定状態を示し、現在の実装を説明する記述と区別する。
`work/` は、計画、調査、実験、下書きを置く一時的な作業場所とし、Git の追跡対象から除外する。
`work/` は checkout 内に置いてよく、repository 外に移すことを保存の条件にしない。
作業が終わったら、保守に必要な意味を [decision-records](./decision-records.md) の「設計判断の理由を決定の記録に残す」に従って移し、不要になった作業記録を取り除く。
他の project への公開や配布を選んだ library の README は英語で書き、日本語版を併置する。
この公開文書の条件は、同じシステム内で core や surface が library の public API を利用することだけでは適用しない。
英語の README を正本とし、日本語版は同じ変更で正本に合わせる控えとする。
他の project への公開や配布を選んだ library の CHANGELOG は、英語だけで書く。
AI が生成する運用文書も、学習・手順・参照・説明の種別に従い、読み手を定める。
文書には、想定する読み手がいなくなる条件を定め、その条件が成立した時点で取り除く。
読み手がいなくなった後も必要な情報は、[README](../README.md) の情報の正本が定める所在へ移す。
検証できない語の扱いは、[verification](../verification/README.md) に従う。

### 根拠
読み手のニーズは、学びたい・やり遂げたい・調べたい・理解したい、で質的に異なる。
作業中に参照する記述と、作業を離れて理解する記述を混ぜると、どちらも役に立たなくなる。
参照に説明を混ぜると、参照は脱線で曇り、説明も適所で展開できない。
読み手を定めずに書いた文書は、種別が滲み、誰の役にも立たない。
読み手は、参照先のリンクを必ず辿るとは限らない。
検証できない語は、読み手ごとに別の像を結び、要件が壊れている徴候である。
読み手のいない文書を残すと、誰も更新せず、現在の規範として読まれ、コードとの同期の負担だけが残る。
情報を残すことと、その情報を生んだ文書を残すことは別である。
`docs/` を現在の読者向けの投影にすれば、正本への入口と理解に必要な説明を保ちながら、当時の検討文を現行仕様として残さずに済む。
`work/` を一時的な作業場所にすれば、未確定の案や試行を、継続して保守する文書から分けられる。
必要な理由を作業記録だけに残すと、その記録を消せず、作業場所が実質的な永久保管庫になる。
読み手がいなくなった文書は、必要な情報を正本へ移せば、文書そのものを残す理由がなくなる。
他の project へ公開する library の読み手は日本語を読むとは限らず、英語で書けば最も広い読み手が読める。
日本語版の README は、日本語を第一言語とする読み手が英語版を訳さずに導入を判断できるようにする。
日本語版を正本に合わせる控えにすれば、二つの版の食い違いは正本を基準に直せる。
CHANGELOG は版ごとの差分を辿る参照であり、言語ごとに持つと、どちらの記述が版の差分の正本かが割れる。

### 完了条件
文書が、学習・手順・参照・説明のいずれかに分かれ、混ざっていない。
各文書が、想定する読み手と、作業中か学習中かと、その読み手がいなくなる条件を定めている。
参照の文書が、リンクを辿らなくてもその場で作業を完結できる形になっている。
読み手がいなくなる条件が成立した文書が、残っていない。
読み手がいなくなった後も必要な情報が、情報の正本が定める所在から辿れる。
`docs/` が Git で追跡され、現在の実装を説明する記述が対応する正本と一致している。
未実装の要件や入力契約の文書が、根拠と決定状態を持ち、現行実装の説明と区別されている。
`work/` が Git の追跡対象から除外され、作業終了後も必要な判断の意味が作業記録だけに残っていない。
他の project への公開や配布を選んだ library が、英語の README、日本語版の README、英語だけの CHANGELOG を持つ。
日本語版の README が、英語の README と同じ内容を述べている。

### 禁止事項
参照と説明、手順と学習を、一つの文書に混ぜること。
読み手を定めずに、文書を書くこと。
読み手がいなくなる条件が成立した文書を、残すこと。
読み手がいなくなった後も必要な情報を、その文書だけに置くこと。
未確定の作業記録を、現在の読者向けの文書として `docs/` に積み上げること。
`work/` を保守に必要な理由の唯一の保存場所にし、消せない作業記録として残すこと。
当時の文書を保存すること自体を目的に、必要な意味の正本への移動を避けること。
他の project への公開や配布を選んだ library の README を、日本語だけで書くこと。
他の project への公開や配布を選んだ library の CHANGELOG を、言語ごとに複数持つこと。
日本語版の README だけを変え、英語の README を変えないこと。

### 行動
書く文書が、学習・手順・参照・説明のどれかを決める。
想定する読み手と、その読み手が作業中か学習中かと、その読み手がいなくなる条件を定める。
参照の文書は、作業に要る情報をその場で完結させ、リンクは補助に留める。
条件が成立したら、後も必要な情報を情報の正本へ移し、文書を取り除く。
継続する読者向けの説明は `docs/` に置いて Git で追跡し、対応する正本と同じ変更で更新する。
未実装の要件や入力契約を文書に残すときは、何が現行の事実で、何が確認済みの意図か変更先かを区別する。
計画、調査、実験、下書きは `work/` に置き、Git の追跡対象から除外する。
作業記録を消す前に、必要な意味がコード、テスト、契約、commit、Why not と読者向けの文書から辿れることを確かめる。
他の project への公開や配布を選んだ library では、README を英語で書いて日本語版を併置し、CHANGELOG を英語で書く。
