## 文末の形を記述の種類で分ける

### 要求
日本語で書く commit の件名、実装コメント、ドキュメントコメントは、句点で閉じない記述として書く。
type のような接頭辞を持つ commit の件名では、接頭辞に続く部分を句点で閉じない記述とする。
句点で閉じない記述の単位は一行とし、ドキュメントコメントでは最初の一行と、各タグ、節、列挙の項目の各行をそれぞれ一つの記述とする。
句点で閉じない記述は体言止めか名詞終わりにし、動詞や形容詞の終止形と「です」「ます」で終えない。
句点で閉じない記述には、句点も読点も使わない。
句点で閉じない記述は一つの関心だけを述べ、「または」「および」「と」や中黒のような並列の接続で二つの関心を束ねない。
一つの関心を成す語を並べるときは、読点でなく中黒か「と」でつなぐ。
日本語で書く文書の段落と箇条書きは、句点で終わる完結した文で書く。
見出し、表のセル、link を並べる台帳や目次の項目は、文書の文の規律の対象にしない。
Markdown の段落と箇条書きでは、一つの文を一行に置き、句点ごとに改行する。
文書の文を、「…だけ」のように述語を欠いた断片で終えない。

### 根拠
句点で閉じない記述は、文でなく、履歴、一覧、補完の表示に並ぶラベルとして読まれる。
名詞で終えた記述は、時制も主語も意図の表明も持たないままラベルとして閉じ、並べても同じ形で読める。
動詞で終えた記述は文になり、文は句点を要するので、句点のない動詞終わりは途中で切れた文として読まれる。
「…する」「…した」の終わり方は、ラベルに要らない今後の意図か過去の報告を持ち込む。
一行の記述に読点や並列の接続が要るのは、二つの関心が入っている徴候である。
中黒は語を並べるだけで文を作らないので、ラベルの形を崩さない。
文書の文は逆に文として読まれるので、述語を欠いた断片は、省かれた述語を読み手に補わせる。
一つの文を一行に置けば、文の境界と行の境界が一致し、文ごとに読めて、差分も文ごとに比べられる。

### 完了条件
日本語で書く commit の件名、実装コメント、ドキュメントコメントの各記述が、体言止めか名詞終わりで終わっている。
句点で閉じない記述に、句点と読点がない。
句点で閉じない記述が、一つの関心だけを述べている。
日本語で書く文書の段落と箇条書きの各文が、句点で終わる完結した文である。
Markdown の段落と箇条書きの各行が、一つの文だけを持つ。

### 禁止事項
句点で閉じない記述を、「…する」「…した」「…を直す」「…にする」「…しない」のような動詞や形容詞の終わり方で書くこと。
句点で閉じない記述に、句点か読点を打つこと。
和文と英数字の境の空白を除き、句読点の代わりに空白や記号を挟んで、二つの内容を一つの記述へつなぐこと。
文書の文を、述語を欠いた断片で終えること。
Markdown の一行に、複数の文を並べること。

### 行動
句点で閉じない記述を書いたら末尾の語を確かめ、動詞や形容詞で終わるなら、その動作や状態を表す名詞で終える形へ書き換える。
読点か並列の接続が要るなら、一つの関心を名詞で終わる一つの記述に言い直せるかを確かめ、言い直せなければ記述を分ける。
commit を分けるかは、[commit-purpose](./commit-purpose.md) の「変更の目的を commit log に残す」に従って決める。
文書の段落と箇条書きは、各文が句点で終わり、句点ごとに改行されていることを確かめる。

### 例
動詞で終え、読点で一つの目的を二つに割った件名は、途中で切れた文として読まれる。

```text
feat: 注文を取り消せるようにし、在庫を戻す
```

一つの目的を、名詞で終わる一つの件名に言い直す。

```text
feat: 在庫を戻す注文の取消
```
