## 文書は最小で高シグナルにする

### 要求
文書は、最小で高シグナルなものにする。
この規律の対象は説明の文書であり、宣言のドキュメントコメントは [comment](../comment/declaration-contracts.md) の「ドキュメントコメントは宣言の契約を書く」が統べる。
各行に、その行を消したら読み手が誤るかを問い、誤らないなら消す。

### 根拠
量の多い文書は読まれず、無関係な記述が増えるほど、読み手は全体を無視するようになる。
削除して誤りが生じない行は、情報を足していない。
禁止だけを書くと、代わりに何をすべきかが分からず、読み手は迷う。
常時必要な情報と、必要なときだけの情報を分ければ、読み手は要る分だけ読める。
文書は、最初から完璧を目指すより、実際に起きた誤解から追記して育てる。

### 完了条件
各行が、削除すると読み手が誤る情報を持っている。
禁止に、代替の手段が併記されている。
常時必要な情報と、必要なときだけの情報が分かれている。

### 禁止事項
削除しても誤りが生じない行を、文書に残すこと。
代替を示さずに、禁止だけを書くこと。
無関係な記述を積み、読み手に全体を無視させること。

### 行動
各行に削除テストをかけ、残す価値のない行を消す。
禁止には、代わりに採るべき手段を併記する。
常時必要な情報と、参照時に読む情報を分ける。

### 例
削除しても誤りが生じない行と、代替のない禁止は、判断に必要な情報を持たない。

```md
- このプロジェクトはとても重要です。
- 変な HTTP クライアントを使わないこと。
```

削除テストに残る行だけにし、禁止には代替を併記する。

```md
- HTTP は `httpClient` を使う(`fetch` を直接呼ばない。再試行とトレースが入らないため)。
```
