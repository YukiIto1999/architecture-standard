## コードの内容を実装コメントで説明しない

### 要求
現在の処理、責務、順序は、[legibility](../legibility/README.md) に従い、フォルダ、ファイル、型、関数の構造と命名、コード本体で表す。
実装コメントを、コードの説明に使わない。

### 根拠
コードで読める内容をコメントにも書くと、同じ内容に二つの正本が生まれる。
コードだけを変更すればコメントは古くなり、コメントだけを変更すれば実装を表さなくなる。
説明を足さなければ読めないコードは、コメントが不足しているのでなく、配置、分割、命名、処理の流れのいずれかが不明瞭である。
コメントで不明瞭さを覆うと、コードは第一級の文書でなくなる。

### 完了条件
現在の処理、責務、順序が、実装コメントを読まずに、構造と命名、コード本体から読み取れる。
コードの内容を説明するだけの実装コメントが残っていない。

### 禁止事項
処理の目的、手順、分岐、結果を、コードの言い換えとして実装コメントへ書くこと。
不明瞭な配置、分割、命名、処理の流れを、実装コメントで補うこと。

### 行動
説明の実装コメントを見つけたら、まずコメントを外してコードを読む。
読めなければ、フォルダ、ファイル、型、関数の配置と分割、命名、コード本体の順に直す。
コードだけで読めるようになったら、説明の実装コメントを削除する。

### 例
コードの内容を説明するコメントは、処理の言い換えにすぎない。

```ts
// 注文を一件ずつ検証して、有効なら予約する
for (const order of orders) {
  if (isValid(order)) reserve(order);
}
```

説明を消し、検証済みの注文という意味をコードへ表す。

```ts
for (const order of validOrders(orders)) {
  reserve(order);
}
```
