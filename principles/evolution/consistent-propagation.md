## 影響範囲へ整合的に波及させる

### 要求
契約・命名・構造・規約・基盤の変更は、影響範囲の全体へ同じ方針で波及させ切る。
局所のシムや例外で、旧方式と新方式を恒久的に併存させない。

### 根拠
局所で例外を吸収すると、旧方式と新方式が併存し、標準が分裂する。
一つの概念的な変更が複数の箇所への散らばった修正を強いるなら、波及を完了させる合図である。
拡張と移行だけで収縮を省くと、二系統の恒久的な重複が残り、始める前より悪い状態になりうる。
新旧の共存は、取りうる状態を掛け算で増やし、問題が要求しない偶有的な複雑さを生む。
この複雑さは技術者が作ったものであり、波及を完了させれば技術者が消せる。
意味体系の異なる外部との境界では、翻訳を一箇所の隔離層に集約し、各所へ散らさない。
複数の利用者を持つ契約は、利用者が使う要素だけを読み未知を無視する寛容な読み手にし、契約全体への暗黙の結合を避ける。

### 完了条件
変更対象と同種の設定・規約・基盤コード・テスト・ドキュメントへ、同じ方針が適用されている。
同一の責務に対して、二つの異なる方式が併存していない。
拡張と移行のあと、収縮まで到達し、旧方式が消えている。
外部との翻訳が、一箇所の隔離層に集約されている。

### 禁止事項
単一ファイル内の局所修正・例外吸収・暫定シム・重複設定で済ませること。
拡張と移行だけで止め、旧方式を恒久的に残すこと。
外部の都合を翻訳する処理を、各所へ散らすこと。

### 行動
変更した設定・規約・基盤と同種の箇所を横断検索し、同じ方針で更新する。
新旧の分岐は、移行を完了して収縮させ、分岐を消す。
外部との翻訳は、継ぎ目に隔離層を一つ置いて集約する。

### 例
移行を完了させずに新旧の分岐を各所へ残すと、二つの方式を恒久的に保守することになる。

```ts
if (schema === "v1") { } else { }
```

変更をすべての消費者へ波及させ、収縮まで進めれば、旧方式と分岐は残らない。

```ts
process(order);
```
