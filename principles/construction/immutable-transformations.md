## 値を不変に扱い、変換の連なりで組む

### 要求
値は不変に扱い、状態の変化は新しい値の生成として表す。
処理は、合成できて置換できる変換の連なりとして構成する。

### 根拠
値は変わらず、変化とは別の値になることである。
場所の内容を上書きする様式は、記憶が限られた時代の前提に依る。
共有された可変の値を書き換えると、参照しているすべての箇所が知らぬ間に変わる。
破壊的な更新は、処理順序に依存する不具合と、意図しない共有状態の変更を生む。
変更を新しい値の生成として表すと、元の値はそのまま残り、過去の状態を保てる。
旧版から新版を作る操作は、構造の大半を共有する仕組みにすれば、丸ごと複製せずに済む。
読み取り専用で渡すデータに可変のコレクションを露出すると、外から書き換えられて不変性が崩れる。
処理を入力から出力を返す変換として書き、前段の出力を次段の入力へ連ねると、各段を独立に読め、差し替えられる。
変換の合成が安全なのは、各段が不変の値を入出力するからである。

### 完了条件
業務の意味を持つ値・境界を越える値・共有される値が、不変な構造で扱われている。
変更が、破壊的更新でなく、新しい値の生成として表されている。
公開するデータが、外から書き換えられない読み取り専用の形で渡されている。
各変換が、入力から出力を返し、共有の中間状態を書き換えない。

### 禁止事項
共有されたオブジェクトを、暗黙に破壊的更新すること。
読み取り専用で渡すデータに、可変のコレクションを露出すること。
中間状態を、複数の箇所から変更できる構造にすること。

### 行動
代入・破壊的メソッド・共有参照の書き換えの箇所を確認する。
破壊的更新が不要なら、新しい値を返す形へ置き換える。
処理を、入力から出力への変換に切り出し、連ねて組む。

### 例
共有配列を破壊的に更新すると、呼び出し側の `order` まで変わる。

```ts
function addLine(order: Order, line: OrderLine): void { order.lines.push(line); }
```

新しい値を返せば、元の `order` は変わらない。

```ts
function addLine(order: Order, line: OrderLine): Order {
  return { ...order, lines: [...order.lines, line] };
}
```
