## 値を不変に扱い、変換の連なりで組む

### 要求
値は不変に扱い、状態の変化は新しい値の生成として表す。
処理は、入力から出力を返す変換を、データ依存に沿って合成して構成する。
導出も遷移も、この変換として書く。
導出は正本から値を計算する変換であり、遷移は旧い状態と入力から新しい状態と結果を返す変換である。
どれを正本として保持するかは、変換の形でなく [preserve-facts-and-current-state](../data/preserve-facts-and-current-state.md) の「業務事実と現在情報を分けて保持する」が定める。
合成は直線の連なりに限らず、後段が入力に前提とする性質を前段の出力が保証する場合に限って成り立つ。
契約を変えない段の差し替えは、後段と呼び出し側が観測する出力・失敗・効果が変わらない場合に限って行う。
変換の連なりは入力と出力の対応を合成する構造であり、全段で同じ DTO を受け渡すことを意味しない。
各段は、その責務と得られる保証に合う型を使い、保証の差がなければ既存の型を再利用する。
合成を記述する箇所では同じ程度の抽象度の操作を使い、表現形式やアルゴリズムの詳細は、その決定を所有する処理へ閉じる。
抽象度の段差だけを理由にモジュールを分けず、境界は [split-by-change-reason](../separation/split-by-change-reason.md) の「変更理由で分ける」に従う。
各段に専用の class、framework、queue を機械的に設けず、関数の合成で表せる処理はその形に保つ。
前段の結果を必要としない独立した枝は、依存と副作用の順序を守ったうえで並行に実行できる。
変換のデータ依存と処理の寿命は別に扱い、並行の寿命の所有、取り消し、失敗、合流と資源解放は concerns の [concurrency](../../concerns/concurrency/structured-concurrency.md) の「構造化並行で寿命をスコープに束ねる」が定める。
並行度と流入の制御は concerns の [concurrency](../../concerns/concurrency/bounded-concurrency-backpressure.md) の「並行度を制限し、背圧を扱う」が定める。

### 根拠
値は変わらず、変化とは別の値になることである。
場所の内容を上書きする様式は、記憶が限られた時代の前提に依る。
共有された可変の値を書き換えると、参照しているすべての箇所が知らぬ間に変わる。
破壊的な更新は、処理順序に依存する不具合と、意図しない共有状態の変更を生む。
変更を新しい値の生成として表すと、元の値はそのまま残り、過去の状態を保てる。
旧版から新版を作る操作は、構造の大半を共有する仕組みにすれば、丸ごと複製せずに済む。
読み取り専用で渡すデータに可変のコレクションを露出すると、外から書き換えられて不変性が崩れる。
処理を入力から出力を返す変換として書き、前段の出力を次段の入力へ連ねると、各段を独立に読め、差し替えられる。
導出も遷移も入力から出力を返すので、同じ合成の形で書ける。
導出する値と遷移の結果がどの正本に対応するかは data の規律に従い、処理の合成から保存方式を決めない。
不変の値を入出力する各段は、共有の中間状態を介さないので、合成の依存が入力と出力の対応に現れる。
ただし合成が成り立つかは、不変であることでなく、前段の出力が保証する性質が後段の前提を満たすかで決まる。
型が合っても、後段の前提を満たさない出力を渡す合成や、契約を変えない差し替えで観測できる結果が変わる場合は、処理の意味を保たない。

### 完了条件
業務の意味を持つ値・境界を越える値・共有される値が、不変な構造で扱われている。
変更が、破壊的更新でなく、新しい値の生成として表されている。
公開するデータが、外から書き換えられない読み取り専用の形で渡されている。
導出と遷移を含む各変換が、入力から出力を返し、共有の中間状態を書き換えない。
連なる各段で、前段の出力が保証する性質が、後段の入力の前提を満たしている。
契約を変えずに段を差し替えたとき、後段と呼び出し側が観測する出力・失敗・効果が、契約が定める入力と出力の対応で照合され、型の一致だけで済まされていない。
変換ごとに入出力の責務と保証を説明でき、同型の DTO を全段へ通すことや各段専用の実行機構を前提にしていない。
合成を読む呼出側が、その抽象度の操作だけで目的を追え、個々の表現形式やアルゴリズムを組み立て直していない。
並行に実行する枝では、データ依存の有無とは別に、寿命の所有と合流を concurrency の規律へ割り当てている。

### 禁止事項
共有されたオブジェクトを、暗黙に破壊的更新すること。
読み取り専用で渡すデータに、可変のコレクションを露出すること。
中間状態を、複数の箇所から変更できる構造にすること。
変換の合成を理由に、依存のない処理まで一律に逐次実行したり、全段へ同じ未検証 DTO を流したりすること。
段を分けたことだけを理由に、class、framework、queue を追加すること。
前段の出力が後段の前提を満たすことを確かめず、型が合うことだけを理由に段を連ねること。
観測できる出力・失敗・効果が変わる処理へ、型が合うことだけを理由に段を差し替えること。

### 行動
代入・破壊的メソッド・共有参照の書き換えの箇所を確認する。
破壊的更新が不要なら、新しい値を返す形へ置き換える。
処理を、入力から出力への変換に切り出し、データ依存に沿って連ねて組む。
合成する操作の語彙を揃え、異なる抽象度の詳細が混ざる箇所は、その決定の所有者へ戻す。
連ねる段ごとに、入力に前提とする性質と出力が保証する性質を書き出し、前段の保証が後段の前提を満たす箇所だけをつなぐ。
契約を変えずに段を差し替えるときは、後段と呼び出し側が観測する出力・失敗・効果が同じかを確かめる。

### 例
共有配列を破壊的に更新すると、呼び出し側の `order` まで変わる。

```ts
function addLine(order: Order, line: OrderLine): void { order.lines.push(line); }
```

新しい値を返せば、元の `order` は変わらない。

```ts
function addLine(order: Order, line: OrderLine): Order {
  return { ...order, lines: [...order.lines, line] };
}
```
