## 集合処理を名前のある操作で表す

### 要求
集合の絞り込み・変換・集計・整列は、裸のループでなく、名前のある高水準の操作で表す。
業務的な意味を持つ集合は、操作を備えた一つの型に閉じ込める。

### 根拠
裸のループは、何をしているかを読み手が本体を追って復元しなければならない。
一つのループが絞り込みと集計のように複数のことを同時に行うと、意図が溶けて読めなくなる。
絞り込み・変換・集計を名前のある操作で書き、前段の結果を次段へ渡すと、何をするかが名前から読める。
本質的に順序を持たない規則を、変数への代入の積み重ねで書くと、記述の順序が正しさの条件に加わる。
条件を満たす候補を列挙して選ぶ宣言の形は、この順序への依存を消す。
集合を扱うロジックが各所に散ると、同じ集計が重複し、規則の変更が漏れる。
置き場と名前を持たない知識は、放置すると急速に重複していく。
集合とその操作を一つの型に閉じ込めると、集合に対する規則がそこに集まり、他の責務と混ざらない。

### 完了条件
集合の絞り込み・変換・集計・整列が、名前のある操作として表されている。
一つの操作が、一つのことだけを行っている。
業務的な意味を持つ集合が、操作を備えた一つの型に閉じ込められている。
集合に対する同じ判断が、各所に重複していない。

### 禁止事項
業務の意味を持つ集合処理を、裸のループとして各所に散らすこと。
一つのループに、複数の集合操作を混ぜること。
集合に対する規則を、集合の外の各所に書くこと。

### 行動
ループが何の集合操作かを確認し、絞り込み・変換・集計・整列の名前のある操作へ置き換える。
一つのループが複数のことをしていれば、操作ごとの段に分ける。
順序と無関係な規則が順序依存で書かれていれば、候補の列挙と選択の形へ直す。
業務的な意味を持つ集合は、操作を備えた型へ閉じ込める。

### 例
裸のループで絞り込みと集計を混ぜると、何を計算するかを本体から復元することになる。

```ts
let total = 0;
for (const line of order.lines) { if (line.taxable) total += line.amount; }
```

名前のある操作を連ねれば、意図を操作の名前と順序で表せる。

```ts
const total = order.lines.filter(line => line.taxable).reduce((subtotal, line) => subtotal + line.amount, 0);
```
