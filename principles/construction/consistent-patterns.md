## 同じ目的に同じパターンを使う

### 要求
同じ目的の処理には、同じ実装パターンを使う。
エラー処理・入出力変換・依存の渡し方・状態の更新・テストの構造を、一つの流儀に揃える。

### 根拠
流儀が分かれると、読み手は同種の処理のたびに別の解釈をやり直す。
パターンを統一すれば、一度学んだ構造を同種の処理へそのまま当てられる。
読み手には、コードを模倣して生成する主体も含まれる。
手本になるコードの品質が、そこから生成されるコードの品質を決める。
操作の結果が、名前や文脈から予測できると、読み手は驚かず誤読しない。
名前が示す動作と実装が食い違うと、読み手の予測を裏切り、驚きという代償を生む。
標準が定めていない書き方の一貫性は、スタイル規約よりプロジェクト、プロジェクトよりモジュールの局所で優先する。
似て非なるものを似せると、見かけの親しさが誤った予測を生むため、はっきり別物にする方がよい。

### 完了条件
同種の処理・エラー処理・入出力変換・依存の渡し方・状態更新・テストが、同じ構造で実装されている。
操作の結果が、名前と文脈から予測できる。
例外的な実装に、明確な理由がある。

### 禁止事項
同種の問題に、複数の流儀を併存させること。
名前が示す動作と、実装を食い違わせること。
個人の好みや局所の都合で、別のパターンを足すこと。
似て非なるものを、似せて紛らわしくすること。

### 行動
変更対象と同種の実装を検索し、既存の標準パターンを確認する。
差異があれば標準へ寄せ、標準自体を変える必要があれば、影響範囲の全体へ適用する。

### 例
同じ走査と変換を場所ごとに異なる流儀で書くと、同種の処理ごとに読み直す必要がある。

```ts
const ys = []; for (let i = 0; i < xs.length; i++) ys.push(f(xs[i]));
const zs = xs.reduce((a, x) => (a.push(g(x)), a), []);
```

同じ目的に `map` を選べば、局所の一貫性を保てる。

```ts
const ys = xs.map(f);
const zs = xs.map(g);
```
