## 正本を互換から独立させる

### 要求
契約の境界は、正本の構造を基準に定める。
併存する新旧の契約は、それぞれ独立した構造として扱い、移行と互換の処理を境界へ閉じ込める。

### 根拠
旧契約や互換対応の都合を正本へ持ち込むと、現在の業務概念が歪む。
同じ名前のフィールドでも、表す意味が違えば別の概念であり、別の型で表す。
申込時点の希望値と、現在運用されている値は、混ぜずに分ける。
互換のための表現を境界へ隔離すれば、正本は現在の概念だけを表せる。

### 完了条件
正本となる構造が、現在の業務概念を表している。
旧契約への対応が、境界に隔離されている。

### 禁止事項
正本のモデルへ、互換専用の項目・不要な任意化・旧名称・旧状態を混ぜること。
新旧の意味差を、同一のフィールドや同一の型へ押し込めること。

### 行動
契約項目ごとに、現在の正本概念か、互換のための表現かを確認する。
互換要素が正本に混ざっていれば、独立した構造として境界へ分ける。

### 例
互換専用の旧項目が正本に同居すると、現在の概念を読み取れない。

```ts
interface Order {
  total: Money;
  amount?: number;
  statusLegacy?: string;
}
```

正本は現在の概念だけにし、旧契約への写像は境界に置く。

```ts
interface Order { total: Money; status: OrderStatus }
```
