## 変更理由で分ける

### 要求
モジュールは、変更を要求するアクターと変更の理由が一致する単位で分ける。
処理の手順・技術層・framework・ファイル種別では分けない。

### 根拠
変更理由の異なる関心を同居させると、片方の修正がもう片方を壊し、確認すべき範囲が広がる。
変更を要求するアクターは、人間の利用者に限らず、他システムや、同じ利用者のライフサイクル上の異なる状態も含む。
アクターの区切りはコードからは決まらず、境界付けられたコンテキストとドメインの捉え方に従うモデリングの判断である。
だから分割の判定には、コードの照合だけでなく、要件の整理とモデリングが先に要る。
アクターの混在は、個々のコード片よりも、全体の設計と共通化の判断に現れる。
同時に変わる要素だけを同じ境界に置けば、修正の影響は境界の内に収まる。
分割の軸は、処理の段階ではなく、変わりそうな決定に置く。
変わりそうな決定を洗い出し、その一つひとつを別のモジュールに隠すと、決定の変更が一つのモジュールに封じ込まれる。
入力から出力への処理の流れでモジュールを割ると、データ形式や整列順の決定が複数のモジュールに漏れ、一つの変更が全体へ波及する。
同じ理由で変わる要素をまとめる凝集は、単一のタスクに全要素が貢献する形が最も強い。
同時刻に動くから、表面のカテゴリが同じだから、という理由でまとめた凝集は弱く、後で分け直しになる。
人は目に見える実体に思考を引かれ、実体の単位が正しい境界に見えてしまう。
実体をそのまま境界にすると、その実体に関わるあらゆる目的の属性と判断を吸収して肥大し、変更理由が混ざる。
特定のアクターを持たない汎用処理は、あらゆるアクターに開かれ、無限の責任を負う。
だから汎用の置き場は、最小に保つ。
重複の判定は、コードの見た目でなく、表している知識と意図で行う。
見た目が同じでも別の知識を表す一致は、偶然であって重複でない。

### 完了条件
各モジュールの変更理由と隠している決定が説明できる。
変更理由の異なる処理・型・設定・画面・永続化構造が、同一モジュールに混在していない。
一つの仕様変更で書き換わる範囲が、一つのモジュールに収まる。
新しいアクターの追加が、既存のアクターの実装に影響しない。
重複の判定が、コードの見た目でなく、表している知識と意図の一致で行われている。

### 禁止事項
処理の段階・技術層・framework・ファイル種別・目に見える実体だけを理由に、境界を決めること。
共通化を理由に、変更理由の異なる要素をまとめること。
別の知識を表す見た目の一致を、重複として共通化すること。
無関係な処理を、util や helper のような共通の置き場へ寄せ集めること。

### 行動
変更対象の利用者・変更契機・変更頻度・変更時に読む仕様を調べる。
変わりそうな決定として、データ形式・整列順・外部仕様・アルゴリズムを列挙し、各決定を一つのモジュールに隠す。
境界の候補が目に見える実体の単位なら、その実体に関わる目的を列挙し、目的ごとに分け直す。
同時に変わる要素だけを同じ境界に残し、別の理由で変わる要素を分ける。
変更に着手する前に、その変更がどのアクターのどのユースケースに属するかを答え、答えられなければモデリングへ戻る。
アクターが混在した実装を分けるときは、まず同一の実装を複製し、アクターごとに要件の違いを書き分けてから、残った偶然の一致を消す。
共通の置き場へ足す前に、対応するアクターかコンテキストへの配置や、既存の型への操作の追加で吸収できないかを先に検討する。
切り出した要素は、対応する概念の名前で検索して到達できる場所に置き、独立した再実装を防ぐ。
使われない項目が null で埋まるモデルを見つけたら、アクターの混在を疑って分け、不正な状態の排除は [modeling](../modeling/README.md) に従う。

### 例
入力、変換、整列、出力の手順で分けると、行の格納形式をすべてのモジュールが知り、形式の変更が三つのモジュールへ波及する。

```ts
class InputReader { constructor(private lines: Line[]) {} }
class Shifter { constructor(private lines: Line[]) {} }
class Sorter { constructor(private lines: Line[]) {} }
```

格納形式を `LineStore` に隠せば、三つのモジュールは形式を知らず、変更も `LineStore` に留まる。

```ts
interface LineStore { add(line: Line): void; get(i: number): Line }
class InputReader { constructor(private lines: LineStore) {} }
class Shifter { constructor(private lines: LineStore) {} }
class Sorter { constructor(private lines: LineStore) {} }
```
