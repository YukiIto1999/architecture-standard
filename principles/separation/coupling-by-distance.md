## 結合を距離に見合う強さにする

### 要求
結合はゼロにできないものとして扱い、その強さを要素間の距離に見合う形にする。
近い要素には強い結合を許し、遠い要素ほど弱い結合へ下げる。
距離は、同じ関数の中、同じ型やモジュールの中、別のモジュール、別のパッケージや別のシステムの4段で表す。
共有する知識の強さは、内部実装、業務要件そのもの、業務モデル、隠蔽した契約の4段で表す。内部実装が最も強く、隠蔽した契約が最も弱い。
境界を越える依存ごとに、知識の段と距離の段を記録する。記録の置き場は [documentation](../documentation/README.md) が定める決定の記録に従う。
結合と凝集の指標は、合否の閾値でなく、見直しを起動する条件として使う。閾値を置くときは、その project で観測した根拠と観測日と見直しの期限を併記する。

### 根拠
結合はシステムを束ねる糊であり、最小化ではなくバランスの対象である。
強い結合と遠い距離が重なると、一つの変更が遠くまで波及して全体が複雑になる。
弱い結合と近い距離が重なると、無関係なものが密集して局所が複雑になる。
指標の提唱者はいずれも、絶対の閾値を無条件に当てることを戒めている。静的に測れる結合は潜在的な費用にすぎず、実際に変更が起きなければ費用は現れない。
凝集の失敗は要素の中の費用を増やすだけだが、結合の失敗は要素をまたいで費用を広げるため、先に手を入れる価値が高い。
関連の強いものを近くへ置く要求は、変数からリポジトリまで、あらゆる規模で同じ一つの欲求である。
複数の階層を上下する長い参照の連なりは、距離に見合わない強い結合の兆候である。
長い参照の連なりの多くは、参照される構造自体が過剰な木である兆候であり、構造の見直しで消える。
結合の痛みは、共有する知識の強さと、要素間の距離に、対象の変わりやすさを重ねて決まり、三つのどれかを下げれば残りが高くても痛みは減る。
一方の変更で他方も直さねば正しさが保てない関係は、特定の値の意味への依存・引数の位置への依存・アルゴリズムの重複として現れる。
これらは、名前付きの定数・キーワード引数・一箇所への抽出によって、より弱い形へ下げられる。
ファイルやフォルダの名前と配置に振る舞いを結び付けると、参照を静的に追跡できない暗黙の結合が生まれる。
めったに変わらない要素なら、強い結合でも痛みは小さい。
複数の境界が一つの概念を共有する結合は、概念への属性の追加が受け手のすべてへ波及するため、距離や変わりやすさによらず弱いほどよい。

### 完了条件
遠い境界を越える結合が、隠蔽した契約の段に限られている。
近接する要素以外で、内部実装・グローバル状態・特定値の意味・引数位置への依存が残っていない。
何をするかを指示するフラグ引数で、呼び出し先の分岐を外から操作していない。
境界を越える依存に、知識の段と距離の段が記録されている。
結合と凝集の指標に置いた閾値が、観測した根拠と観測日と見直しの期限を伴っている。

### 禁止事項
別モジュールの内部状態や private へ直接到達すること。
複数のモジュールが、可変のグローバル状態を共有すること。
単一インスタンスや静的アクセサで包んだ可変状態を、共有されたグローバル状態の禁止の外と扱うこと。
合成データ構造を丸ごと渡し、受け手が一部しか使わないこと。
処理の切り替えフラグを渡し、呼び出し先の分岐を外から制御すること。
ファイルやフォルダの名前と配置に、プログラムの振る舞いを結び付けること。
結合と凝集の指標に、根拠と観測日と見直しの期限を伴わない一律の閾値を、合否条件として置くこと。

### 行動
境界を越える結合ごとに、共有している知識の段と距離の段と変わりやすさを記録する。
距離が遠いのに強い結合があれば、隠蔽した契約の段へ下げる。
意味を持つ裸の値は名前付きの定数や型へ、引数の位置依存は名前による対応づけへ、重複したアルゴリズムは一箇所へ移す。
境界をまたいで同じ概念を共有する箇所は、本当に同じ概念か、受け手に不要な属性まで渡していないかを確かめ、違うなら別の概念として名前ごと分ける。
結合の強さが読めないときは、意図的な破壊的変更で影響範囲を測り、計測の後に元へ戻す。

### 例
フラグで呼び出し先の分岐を操作すると、呼び出し先の内部が外に漏れる。

```ts
function save(order: Order, validate: boolean) { }
```

目的ごとに関数を分ければ、フラグによる結合がなくなる。

```ts
function save(order: Order) {}
function saveDraft(order: Order) {}
```

特定の値に意味を持たせると、その値の意味を各所が知り、変更時に一緒に書き換わる。

```ts
if (user.role === 2) { }
```

名前のある値へ下げれば、意味が型に現れ、変更は定義の一箇所に収まる。

```ts
if (user.role === Role.Admin) {}
```
