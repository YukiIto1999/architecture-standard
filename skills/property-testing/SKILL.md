# 契約を入力と操作列で検査する

性質の名前を列挙するのでなく、公開契約に違反する実装を検出できる入力、oracle、観測を組み立てる。
この Skill は生成する検査の実作業を所有し、機能実装全般の順序は所有しない。

## 根拠と実行の境界

1. 対象 project、公開入口、変更する保証、検査の作成か読取りか、実行を許可された範囲を固定する。
   architecture-standard の適用入口は `standard-apply` を使い、すでに固定した変更契約と選択済み process を引き継ぐ。
2. この `SKILL.md` の実体から二段上を標準 root とし、[tests の方法](../../structure/tests/methods.md) と [テストの信頼性を保つ](../../principles/verification/test-reliability.md) を読む。
   配置と実依存は [tests の構造](../../structure/tests/layout.md)、実行と再利用は [検証の順序](../../process/verification.md) を読む。
3. 対象の公開契約、入力 channel、producer と consumer、関連 test、依存の manifest と lockfile、検証 task を読む。
   採用済みの生成器と runner の版に対応する API を確認し、名前や option を記憶で書かない。
   新しい test framework を導入せず、対象言語の標準の実現と既存の test 配置へ落とす。
   既存の赤や利用者が報告した失敗を、確認のためだけに再実行しない。

## 保証と oracle を決める

検査する保証ごとに、次の対応を作る。

| 項目 | 記録する内容 |
|---|---|
| 契約 | 入力条件、結果、拒否、状態と効果の保証、その根拠 |
| 領域 | 入力 channel が運べる表現、契約が受ける値と拒否する値 |
| oracle | 独立した期待値、参照モデル、または契約から導いた観測関係 |
| 違反 | 小さい合理的な実装変更で破れる保証と consumer が見る失敗 |
| 観測 | 戻り値、公開状態、効果、拒否理由とその不変 |

往復、冪等性、比例関係、順序の不変、参照モデルとの一致は、契約がその条件を保証する場合にだけ使う。
性質の種類から強弱の序列を作らず、相互に独立した保証を省かない。
変換と逆変換が同じずれを持つ往復や、定数 0 でも通る比例関係を想定し、外部契約の値を判定する別の oracle が必要か確かめる。
実装の計算式、validation、schema をそのまま oracle に使って同じ誤りを写さない。
契約が未確定なら、実装の結果を正解に昇格させず、その決定だけを未確定として残す。

## channel から生成する

入口が byte 列、文字列、構造化された値のどれを受けるかを固定し、encoding、欠落、余分な項目、空値、長さ、数値の境界をその契約から選ぶ。
handler の引数型だけに領域を縮めず、入口で受ける表現と、parse 後の型の検査を分ける。
契約上の空値を含めることと、判定する入力が 0 件であることを混同しない。

有効値は、先に基になる値を生成し、その値から範囲、参照先、長さ、時刻などが従属する値を構築する。
filter や precondition を使う場合は、何を捨てるかと判定に到達する入力の数を観測できるようにする。
拒否する値は、有効値の constructor の外から別に作り、期待する拒否と、変更されない状態や効果を判定する。
境界の既知の例は固定入力として同じ保証へ加え、生成による検査を置き換えない。
生成数、棄却数、判定数、契約から分けた区分の通過数を runner の結果に残し、判定数 0 を成功にしない。

## 状態を持つ場合

状態を持たない対象なら、この段は行わない。
状態を持つ対象では、初期状態、独立したモデル、有効な操作、引数、状態更新、戻り値と公開観測を定める。
現在のモデルから有効な操作と従属する引数を生成し、無効な操作の拒否は別の検査にする。
各操作の直後に実体とモデルの必要な観測を比較し、最後だけの比較で前の違反を消さない。

enqueue の欠落を後続の clear が隠すような列を反例の候補とし、途中の戻り値や公開状態が判定されるか確かめる。
イベントの順序や重複に意味があるなら、その意味をモデルに残し、任意の並べ替えや再配送で同じになると仮定しない。
時刻や外部応答を制御するなら入力へ含め、制御した範囲と実際の資源の結合を検査する範囲を分ける。
process 内のモデルの成功を、datastore、terminal、別 process の保証へ広げない。

## 違反を検出する証拠を使う

守る保証を破る変更と、失敗するはずの観測を対応させる。
アサーションを強制的に赤へ変える確認は runner の経路の確認であり、製品の保証の違反を検出した証拠にはしない。
同じ対象、入力、保証、検証器に対する mutation の結果がすでにあるなら、その実際の差分と失敗した判定を読む。
証跡の条件が一致する間は、同じ手動変異や全量実行を重ねない。

追加の検出確認が必要で、実行を許可された場合だけ、許可範囲の小さい検証対象の差分を隔離した入力へ適用する。
基線の成功結果を再利用し、保証に対応する検査を実行して違反の観測を記録し、試した差分だけを取り除く。
利用者の変更を stash や reset で消さず、不確かな状態へ元の file 全体を上書きしない。
compile の失敗、runner の故障、判定へ到達しない timeout は、保証の違反の検出と分ける。
変更行の未検出 mutant 0 件と全量の生成 0 件の扱いは、tests の方法に従い、score の高さで代替しない。

## 縮小して分類する

失敗した値または操作列を、違反する観測が残る範囲で縮小する。
縮小後の値が領域を満たし、各操作の前提が依然として成り立つことを確認する。
縮小した値または列、seed と replay に必要な情報、生成器と検証器の版、失敗した観測を保存して再現する。
seed だけに頼らず、意味のある縮小入力も回帰へ加え、property の生成を残す。

| 分類 | 次の行動 |
|---|---|
| 製品の契約違反 | 反例を回帰へ固定し、許可された修正の工程へ渡す |
| 性質が契約と異なる | 契約から判定を修正し、製品を誤った性質へ合わせない |
| 生成器またはモデルの欠陥 | 領域、前提、oracle の誤りを直し、領域の縮小で隠さない |
| 未確定の仕様 | 判断を変える反例と不足する決定を返す |
| 実行環境の不成立 | runner、資源、版、実行条件の不足を示し、合格に数えない |

## 結果を返す

契約と性質、実際に判定した領域と件数、oracle、各操作の観測、縮小した反例と分類、使った mutation の証跡、実行した command と結果を返す。
未実行の検査と未確定の仕様は成功と分ける。
反例を見つけなかった実行は、その入力領域と観測の結果に限って報告し、全入力で正しいと主張しない。
隣接する実依存の検査と機能実装全般の red-green の工程を、この Skill の成功で代替しない。
