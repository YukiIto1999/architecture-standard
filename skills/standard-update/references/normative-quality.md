# 意味とモデルを裁定する

外部知見と現行標準の関係、本文の表現品質、採用するモデルを分けて判断する。
直接所有者の比較を起点にし、SKILL.md の影響表で全体への帰結を閉じてから裁定する。
この reference を標準本文の欠落を補う規範として使わない。

## 意味の関係

候補と既存本文について、次の比較を記録する。

| 比較軸 | 確認する差 |
|---|---|
| 主張の中心と判断軸 | 最重要の価値と、案の良否を決める基準 |
| 対象と範囲 | 問題とする対象、適用する境界、適用外 |
| 前提と例外 | 主張が成立する条件、例外の理由 |
| 因果関係 | 何が何を改善し、どの失敗を避けるか |
| 強制力と失敗 | 必須か推奨か、違反と失敗時処理 |
| 実装と検証 | 求める行動、下位実現、観測する合否 |

一致は各軸で判断上の差がなく、包含は既存文が候補の全結果をより広い範囲で保証する場合に使う。
部分包含は条件や結果の一部だけを満たす場合、異なる主軸は結論が同じでも価値や理由が異なる場合、補完は独立した必要な側面を加える場合に使う。
矛盾は同じ前提と範囲で両立しない判断を要求する場合、新規は該当モデルがない場合に使う。
関係が側面ごとに違うなら分解し、一つのラベルで差を消さない。
主軸の違いが具体的な境界や優先判断を変える例を作り、語の一致や論理的な包含だけで充足済みにしない。

## モデルの裁定

矛盾する双方について、成立条件と反例を示し、外部主張の誤り、現行標準の誤り、前提・範囲・抽象度の違い、所有や分解の誤りを比較する。
上位原則への整合を調べるが、上位原則自身が今回の反証で崩れる場合は再評価する。
既存規律を弱めること自体で不採用にせず、その変更が品質の保証を失うのか、過剰な拘束を除くのかを区別する。
影響表の各帰結を満たす最も整合的で説明力のあるモデルを選び、採否の根拠を残す。

裁定は、充足済みで無変更、意味を保った文章修正、意味拡張、新設、矛盾解消、不採用、根拠不足で見送りとして記録する。
再分解、所有者移動、構造変更は裁定を実現する方法であり、局所の文章修正より後回しにする段ではない。
文章修正は既存本文から導ける遵守結果を明確にする場合、意味拡張は新しい条件や遵守結果を導入する場合に使う。
主張を不採用にしても、その照合で現行側の表現や構造の欠陥が立証されたら、同じ因果関係の改善を行う。


## 別解釈で反証する

意図した読みを一文にし、同じ本文から成立する弱い読みと強い読みを具体例で作る。
別解釈では準拠するが意図した読みでは違反する対象を作れるなら、遵守判定は一意でない。
同じ箇所または直接参照先が別解釈を明示的に排除する場合だけ、その読みを反証済みとする。
裁定者が知っている含意、文法上両立する読み、周辺項目との都合のよい両立は排除根拠にしない。

「すべて」「重要な」「必要な場合」「適切な」「同じ」「一つ」のように対象集合または義務の強さを動かす語は、対象、前提、境界、適用外、判定条件を本文から一意に導けるか確かめる。
周辺の必須項目を一つでも不要に読める解釈を本文が排除できなければ、文章のリファクタリングを選ぶ。

## 同じ性質かを反例で分ける

重複を禁じる候補では、各判定について対象、入力境界、観測結果、失敗条件を一文にする。
最初に、各判定が割り当てられた要求と禁止事項を特定し、それらが要求する全適用対象・入力集合を比較領域にする。検証が自己申告する集合や、実装済みの case だけから比較領域を作らない。要求範囲を欠かさない非空の集合を標準本文から定められなければ、同じ性質とは判定しない。
二つの集合が一致しない、または一方が適用不能になる要素があるなら、二つの判定は比較不能であり、別の性質として両方を残す。両集合の交差部分だけを選んで共通集合と呼ばない。
同じ性質とみなせるのは、二つの判定が同じ規範命題へ割り当てられ、そこから導いた非空の適用集合の全要素で一方の合格が他方の合格を含意し、かつ逆方向も成り立つ一つの観測可能な述語として示せる場合だけである。一方の規範命題だけを満たさない対象または入力は、別の性質であることの反例になる。反例をまだ見つけていないことだけを、同じ性質の根拠にしない。
現行本文が重複禁止だけを要求し、適用集合の一致と合否述語の双方向の含意を判定条件として持たない場合、この条件の追加は片方を省ける範囲を変えるため、意味を保った文章修正ではなく意味拡張である。
「同じ性質」を「同じ要求」「同じ禁止事項」「同じ目的」へ置き換えるだけでは、比較不能な合否述語を省ける読みを排除できない。
同じ規範命題を実装する二つの検証機構の片方だけが、欠陥または更新漏れで誤判定することは、別の性質の証拠にしない。
対象、入力境界、観測結果、失敗条件の差は反例を作る候補であり、差が一つあるだけで別の性質と確定しない。正しく実現した両機構の一方だけが満たさない対象または入力を示して、規範命題の独立を確定する。
診断で使った候補軸を、そのまま「いずれかが異なれば常に別の性質」のような必要十分条件へ変えない。その形の変更案は意味を保った文章のリファクタリングではなく未証明の意味拡張として退け、反例で支えられる境界だけを書く。
重複判定の規範文を編集する場合、対象・入力境界・観測結果・失敗条件は共通集合と合否述語を定める材料として使う。変更案が「全軸が一致すれば同じ」「一軸でも異なれば別」、または「反例を発見できなければ同じ」と読める場合は破棄する。
編集前に、同じ表の行、分類名、item または label に属するが、片方にしか適用できない二つの検証を一組作る。さらに、同じ空集合または要求範囲の一部だけを両方が宣言する例を作る。変更案が、規範から導いた非空の全適用集合と双方向の含意を示さずこれらを「同じ」と判定するなら Edit しない。変更後の標準本文だけから、比較不能または一方だけが不合格となる場合は両方を残し、同じ規範命題から導いた非空の全適用集合で合否述語の同値を示せる場合だけ片方を省けると判定できることを読み直す。
同一とみなして片方を省く規律は、何が同じなら同じ単位か、少なくとも何が異なれば別の単位かを、標準本文の対象、入力境界、観測結果、失敗条件のいずれかで定めていなければならない。
分類名の列挙だけ、周辺の表からの推論、またはこの reference から持ち込んだ区別では、この条件を満たさない。

## 無変更ゲート

充足済みで無変更を選ぶ前に、次を記録する。

| 確認対象 | 記録する内容 |
|---|---|
| 候補と既存文 | 遵守判定を動かす語と要求する結果 |
| 判断単位 | 同じ節と直接参照先にある必須の判定 |
| 判定境界 | 対象、入力境界、観測結果、失敗条件 |
| 別解釈 | 準拠と違反が入れ替わる具体例 |
| 排除根拠 | 別解釈を否定する標準本文の箇所 |
| 検証 | 違反を検出する型、静的検査、実行テスト、計測または人手条件 |
| 表現の主軸 | 初見の読者が最重要の価値、判断軸、行動、違反をどう読むか |
| 全体への帰結 | 影響表の上位、同一概念、境界、下位実現、確認点、Skill の確認結果 |

語が一致すること、既存文が多くの項目を列挙すること、裁定者が意図を知っていることは無変更の根拠にしない。
別解釈を標準本文で排除できない、主軸が誤って伝わる、周辺の必須項目が不要になる、判定境界を本文から導けない、または違反の検出まで追跡できない場合は無変更を選ばない。
直接所有者が十分でも影響先の矛盾や責務混在が残るなら、その欠陥を解消するまで充足済みとしない。
未確認の影響先が裁定を変えうる場合は無変更の成功でなく、根拠不足として扱う。

## 改善方法の比較

語の置換で誤読を除ける案と、概念の再分解や所有者の再配置で判断を一貫させる案が実質的に異なるなら比較する。
既存の意図を保つ文章修正と、新しい対象、義務、違反、判定手段を導入する意味拡張を混同しない。
既存 file へ追記できることは、その所有者が適切である根拠にならない。
変更後は、候補から各変更への因果関係と、採用モデルから実装・検証への連鎖を確かめる。
