# 意味とモデルを裁定する

## 判断が分かれる例を作る

入力が変えようとする判断を一つ選び、状況と選択肢を固定する。
その場にいる開発者が、候補だけを読んだ場合と現行本文だけを読んだ場合に何を選ぶかを比べる。
同じ結論なら、対象、前提、競合する価値、失敗時の結果のいずれかを変え、同じ問いへの答えが分かれる境界を探す。
直接矛盾するなら、同じ前提で相容れない帰結を一つ示す。
別の意思決定を足して初めて生じる差は、それが元の判断の実装や検証を妨げる場合に限り、今回の影響範囲に入る。

一致は判断を分ける差がないこと、包含は一方の要求が他方の結果をその適用範囲全体で保証することを指す。
一部の条件だけを満たすなら部分包含、独立した必要条件なら補完、同じ前提で両立しない要求なら矛盾である。
既存に対象がなければ新規の候補とする。
ラベルを一つ選ぶことより、どの条件で結論が変わるかを示す。

意図した読みのほかに、同じ文から無理なく導ける、より弱い義務・強い義務を試す。
初見の読者が両者を区別できる根拠は、標準本文またはそこから辿れる正本の箇所で示す。
例の説明、この Skill、裁定者の予備知識で本文の欠落を埋めない。
判断に使う語が同義か不明なら、その同一視に依存しない修正と、事実の確認が必要な変更を分ける。

## モデルを選び、裁定する

比較で見つかった差を影響先まで辿った後で、現行と候補を同じ反例に当てる。
層の優先順位は適用時の規則であって、改訂時に上位原則を反証から守る規則ではない。
双方が別の前提で正しいなら、保証する性質、責務の所有者、適用期間など、違いを生む境界を切り分ける。
局所の但し書きと分解・再配置を比べ、利用側の実装と検証に一貫した答えを返せる方を選ぶ。

| 裁定 | 採否を支える証拠 |
|---|---|
| 充足済み | 判断軸・条件・違反が既存本文に表れ、合理的な別解釈を退ける箇所と、実装で違反を検出する手段がある。影響先に同じ原因の欠陥が残らず、今の所有者のままで判断できる。 |
| 表現の修正 | 既存の要求と遵守結果は維持できるが、要約・完了条件・例の読み方によって主軸が伝わらない。曖昧な箇所を直し、要求に照らして以前から導けた結果と一致させる。 |
| 意味の変更 | 現行では許される実装を禁じる、禁止を解く、対象や義務・判定手段を変える。どの例の合否が入れ替わるかを示し、所有・下位実現・確認点をその差に合わせる。 |
| 不採用 | 成立しない前提や失われる保証を具体例で示せる。提案を退けても、比較で判明した現行側の欠陥は別に裁定する。 |
| 未確定 | 採否を分ける事実、本文、影響先の確認が足りない。何が分かればどの判断が変わるかを示す。 |

一つの資料が複数の判断を含めば裁定を分ける。
構造変更は裁定を実現する手段であって目的ではない。
既存本文から導けなかった義務を導入するのに、文章を短くしたことを理由に表現の修正としない。
