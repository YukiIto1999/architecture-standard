# CLI の呼び出しを設計する

人が判断して操作する経路と、script が結果を受け取る経路を、同じ command の契約として成立させる。
この Skill は契約を組み立てる手順を所有し、標準の規範を別の正本として転写しない。

## 入口と根拠

1. 対象 project、依頼が設計だけか実装も含むか、変更する公開契約と変更しない範囲を固定する。
   architecture-standard を適用する対象の入口は `standard-apply` を使い、その変更契約と選択済み process を引き継ぐ。
   同じ作業ですでに読んだ本文と証拠は、現在も同じ内容なら読み直さない。
2. この `SKILL.md` の実体から二段上を標準 root とし、[console の構造](../../structure/surfaces/console/layout.md) を読む。
   設定を解決するなら [configuration](../../concerns/configuration/README.md) と、そこが正本とする源、型、起動時検証の本文を読む。
   対話入力と破壊操作は [experience](../../concerns/experience/README.md) の回復の本文へ進む。
   terminal を所有する場合だけ、console が指す資源と終了の正本を読む。
3. project の既存 command、help、利用例、task 定義、consumer script、設定、公開 operation、関連 test を読んで現在の契約を回収する。
   根拠のある既定動作と未確定の選択を分け、既存の公開契約を一般的な慣習だけで上書きしない。
   検証 command は project の task 定義から取り、設計だけの依頼で command の実行や実装を始めない。

## 操作から文法へ落とす

主要な利用者が何を入力し、何を見て、どの効果を期待するかを先に一つの呼び出しとして書く。
対話、選択して終了、一回の非対話処理、継続する terminal session のどれが必要かを決めてから、command tree と usage を組み立てる。
名前の候補だけから不要な subcommand や global option を作らない。

各 command について、次の情報を既存の仕様へまとめる。

| 項目 | 決める内容 |
|---|---|
| 目的と対応 | 利用者の目的、呼ぶ core operation、状態への効果 |
| 入力 | positional argument と option の型、必須性、未指定、既定動作、選択肢、入力元 |
| 入力元の競合 | argv、stdin、file の組み合わせと優先または拒否、stdin の消費者 |
| 出力 | 人向けと機械向けの形式、空結果、部分結果、順序と互換性 |
| 終了 | 成功、入力拒否、想定内失敗、欠陥、取り消し、部分成功の status と状態 |
| 発見 | 副作用のない help と version、usage、回復方法、必要なら completion の入口 |

入力の正本から検証済みの型への変換を辿り、command に業務判断や別の validation を作らない。
選べない入力元や未定義の競合は、根拠を得るまで仕様へ勝手な優先順を追加しない。

## 人と script の経路を分ける

stdout、stderr、終了 status、業務状態を別々の観測として定める。
機械向け形式の項目と型を決め、人向けの表や error 文言を script の解析対象にしない。
出力の redirect と入力の TTY は独立した条件として扱い、stdin を業務データと確認入力の両方へ割り当てない。

stdin、stdout、stderr が TTY か、非対話の指定があるかを条件表へ落とす。
条件ごとに、prompt の可否、装飾の描画先、入力不足の拒否、結果と診断の channel を記す。
機械向け形式を明示した経路では、TTY でも prompt や cursor 制御を結果へ混ぜない。
対話できない条件で不足を補えないなら、待機や既定の承認ではなく、効果の前の拒否へ落とす。

## 設定を解決する

command の入力、起動時設定、実行時の振る舞いを切り替える flag を分ける。
採用している設定の源と解決点を読み、競合する層を持つ場合は優先順、未指定、空値、明示的な false と 0、重複指定、不正値の結果を表にする。
供給源を増やす提案は標準の源の規律に照合し、環境変数や secret を引数へ追加する慣習で埋めない。
secret の値を help、利用例、結果、診断へ書かず、資格情報は認証の所有者が決める経路へ渡す。

## 効果を確かめる

破壊操作は、確認する対象、確定点、拒否したときに変わらない状態、非対話の明示的な承認を対応させる。
preview を持つなら、実行と同じ入力解決と計画を使うこと、書込みがないこと、preview 後の対象変更をどこで照合するかを定める。
再実行は、同じ要求の識別、二度目の結果、重複する効果、途中終了からの再開に分ける。
取り消しは確定前と確定後を分け、確定済みの効果を成功とも未実行とも偽らず、結果と終了 status へ写す。
並行処理の所有と cancellation の実現は標準の正本へ渡し、この Skill で別の停止規則を作らない。

## terminal を持つ場合

terminal の mode、screen buffer、cursor、入力を所有または変更しない場合は、この段は行わない。
選択して終了する単発操作でも、terminal の状態を取得する場合は同じ段で設計する。
terminal を持つ場合は、取得、初期化途中の失敗、処理中、最終終了、一時引き渡し、復帰を状態図にし、各状態の所有者と復元する mode を特定する。
既存 framework が入力と terminal の状態を所有するなら、その lifecycle 入口を使い、追加の stdin reader や signal handler を作らない。
editor や shell へ渡す直前に入力と描画を止めて所有を返し、復帰時に外部で変わるデータを再読込して全体を再描画する。

入力 loop、状態更新、描画、遅い I/O の結果を戻す event の経路を分ける。
I/O を待つ間も入力を受ける状態を設計し、無条件の再描画 loop を作らない。
cell 幅を使う配置と切詰めの実現を既存 ecosystem で確認し、日本語、結合文字、emoji、resize、狭すぎる状態の例を選ぶ。
固定の画面寸法や操作数を品質の代わりにせず、対象の表示と操作が成立する境界を定める。

## 呼び出しで閉じる

契約から必要な呼び出しを選び、argv、stdin、設定、TTY の条件、stdout、stderr、終了 status、前後の業務状態を期待結果に対応させる。
成功、入力拒否、空結果、出力途中の失敗、競合、非対話の破壊操作、再実行、確定前後の取り消しは、対象に存在する経路を漏らさず含める。
terminal の取得と復元、一時引き渡し、入力 loop の実結合は [tests の方法](../../structure/tests/methods.md) が定める PTY の検査へ割り当てる。
例の件数を固定せず、同じ失敗を複数の例で重ねる前に未観測の契約条件を探す。

実装を依頼された場合は、定めた契約の範囲だけを既存の parser と composition に反映し、consumer、help、利用例、test を一緒に更新する。
parser library の選定や切替は、別途依頼されたか実現不能の根拠がある場合にだけ扱う。
検証を許可された段階で project の入口を使い、同一の成功結果の再利用と実行範囲は [検証の順序](../../process/verification.md) に従う。

成果は、実装できる command の仕様、代表呼び出しと観測する結果、未確定の決定、実装した範囲、実測した検証と未実行の検査を分けて返す。
設計だけなら検証計画を渡し、設計した結果を動作確認済みとは報告しない。
